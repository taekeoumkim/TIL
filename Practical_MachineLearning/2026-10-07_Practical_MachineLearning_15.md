# 2026-10-07 데이터 문제 해결의 흐름

## 학습 목표

- 데이터 업무를 문제 정의부터 적용과 개선까지 이어지는 과정으로 이해한다.
- 질문과 데이터에 맞게 EDA, 프로덕트 분석, 통계, 머신러닝, 시계열 분석을 선택할 수 있다.
- Python, SQL, 통계와 모델링을 하나의 문제 해결 과정에서 연결할 수 있다.
- 관찰된 사실, 원인에 대한 가설, 모델의 예측을 구분할 수 있다.
- 결과를 의사결정과 실제 적용으로 연결하고 효과를 다시 검증할 수 있다.

---

## 1. 데이터 업무는 문제를 이해하는 것에서 시작한다

실제 업무에서는 사용할 모델보다 해결해야 하는 비즈니스 문제가 먼저 주어지는 경우가 많다.

온라인 교육 서비스에서 방문자 수는 크게 변하지 않았지만 결제 건수와 매출이 줄었다고 가정하자. 먼저 해야 할 일은 특정 모델을 학습하는 것이 아니라, 문제를 확인할 질문을 만드는 것이다.

- 언제부터 매출이 감소했는가?
- 어떤 강의와 사용자 집단에서 감소했는가?
- 결제까지 이어지는 사용자 행동이 달라졌는가?
- 실제 서비스 변화인가, 데이터 수집의 문제인가?

이 질문에 따라 필요한 데이터와 분석 방법이 달라진다. **분석 방법을 먼저 고르는 대신, 답해야 할 질문을 먼저 구체화해야 한다.**

---

## 2. 필요한 데이터를 확보하고 연결하기

필요한 정보는 여러 테이블에 나뉘어 있을 수 있다.

| 데이터 | 담고 있는 정보 | 확인할 질문 |
|---|---|---|
| users | 사용자 특성 | 어떤 사용자 집단에서 결제가 줄었는가? |
| courses | 강의 정보 | 어떤 강의의 매출이 감소했는가? |
| payments | 결제 시점과 금액 등 | 언제부터 매출이 감소했는가? |
| user_events | 서비스 행동 로그 | 어느 단계에서 사용자가 이탈하는가? |

데이터베이스와 ERD를 확인하여 테이블의 관계를 이해하고, SQL로 분석에 필요한 데이터를 구성한다.

결제 데이터와 행동 로그를 연결할 때는 사용자와 강의의 식별자, 이벤트 시점, 데이터의 집계 단위를 확인해야 한다. 중복 연결로 결제 금액이 여러 번 계산되지 않도록 주의한다.

SQL은 필요한 데이터를 확보하고 집계하는 도구이며, Python은 확보한 데이터를 가공하고 시각화하거나 모델링하는 도구로 연결된다.

---

## 3. 데이터 품질과 현재 상황부터 확인하기

분석 결과를 신뢰하려면 입력 데이터가 질문에 답할 수 있는 상태인지 확인해야 한다.

| 확인 항목 | 점검 내용 |
|---|---|
| 결측치 | 중요한 정보가 누락되었는가? |
| 중복 | 같은 사용자·결제·이벤트가 반복 기록되었는가? |
| 비정상 값 | 금액이나 날짜에 오류가 있는가? |
| 의미와 단위 | 컬럼과 집계 기준을 올바르게 이해했는가? |
| 수집 상태 | 분석 기간의 로그가 정상적으로 수집되었는가? |

그다음 EDA, 시각화와 기술통계로 현재 상황을 살펴본다.

방문자와 강의 조회 사용자는 유지되는데 결제 사용자만 줄었다면, 문제를 다음처럼 구체화할 수 있다.

> 유입 자체보다 강의 조회 이후 결제로 이어지는 과정에서 변화가 나타났을 가능성이 있다.

이는 원인을 확정한 결론이 아니라 다음 분석을 위한 단서이다. 결제 과정의 어디에서 변화가 생겼는지 추가로 확인해야 한다.

---

## 4. 같은 서비스에서도 질문에 따라 방법이 달라진다

| 질문 | 필요한 데이터 | 적절한 방법 |
|---|---|---|
| 어떤 변화가 발생했는가? | 기간별 매출과 사용자 지표 | EDA, 시각화, 기술통계 |
| 사용자가 어디에서 이탈하는가? | 순서와 시점이 있는 행동 로그 | Funnel, 프로덕트 분석 |
| 어느 사용자 집단에 문제가 집중되는가? | 기기·유입 경로·사용자 구분 | Segmentation |
| 관찰된 집단 차이를 얼마나 신뢰할 수 있는가? | 집단별 표본과 결과 | 통계 분석 |
| 어떤 사용자가 결제할 것인가? | 예측 시점의 사용자 정보와 결제 결과 | 분류 모델 |
| 다음 달 매출은 얼마인가? | 시간 순서가 있는 매출 | 시계열 분석 |

모든 문제에 모든 방법을 적용할 필요는 없다. 현재 질문에 필요한 방법을 선택하고, 결과를 바탕으로 다음 질문을 만든다.

---

## 5. Funnel과 Segmentation으로 문제 위치 찾기

사용자의 행동을 단계별로 나누는 Funnel 분석은 전환과 이탈이 발생하는 위치를 확인하는 데 유용하다.

다음은 온라인 교육 서비스의 예시이다.

| 단계 | 사용자 수 | 이전 단계 대비 전환율 |
|---|---:|---:|
| 서비스 방문 | 10,000명 | - |
| 강의 조회 | 7,000명 | 70.0% |
| 수강 신청 시작 | 3,500명 | 50.0% |
| 결제 완료 | 1,400명 | 40.0% |

전환율은 다음과 같이 계산한다.

$$
\text{단계 전환율}=\frac{\text{다음 단계에 도달한 사용자 수}}{\text{이전 단계의 사용자 수}}\times100
$$

이 예시에서는 신청 시작 이후 결제 완료까지의 전환율이 40%이다. 방문부터 결제까지의 전체 전환율은 14%로, 단계 전환율과 구분해야 한다.

Funnel을 계산할 때는 동일한 사용자 집합에서 단계 순서와 전환에 허용할 시간을 정의해야 한다. 단순히 각 이벤트의 전체 발생 건수를 나누면 사용자 전환율과 다른 값이 될 수 있다.

전체 결과를 확인한 뒤 기기, 유입 경로, 신규·기존 사용자 등으로 나누어 분석한다. 이를 통해 문제가 특정 집단에 집중되는지 확인할 수 있다.

---

## 6. 관찰된 차이와 원인을 구분하기

PC 결제 완료율이 48%, Mobile이 34%라면 두 집단의 관찰된 차이는 14%p이다. 그러나 이 차이만으로 모바일 환경이 매출 감소의 원인이라고 단정할 수 없다.

먼저 표본 수와 변동, 집단의 구성 차이를 확인하고 통계적 근거를 살펴본다. 통계적으로 유의한 차이가 있더라도 그것만으로 인과관계가 증명되지는 않는다.

| 구분 | 예시 |
|---|---|
| 관찰한 사실 | Mobile 사용자의 결제 완료율이 낮음 |
| 원인 가설 | 특정 모바일 결제 단계의 오류가 영향을 주었을 가능성 |
| 추가 확인 | 결제 오류 로그, 화면 동작, 사용자 문의 확인 |
| 효과 검증 | 개선안을 실험으로 평가 |

데이터에서 발견한 사실과 그 사실에 대한 설명을 분리해야 한다. 그래야 근거가 부족한 상태에서 잘못된 개선 방향을 선택하는 일을 줄일 수 있다.

---

## 7. 새로운 사용자의 행동을 예측한다면

사용자가 앞으로 결제할지 예측하는 질문은 이미 발생한 현상을 설명하는 질문과 다르다. 결제 여부를 0과 1로 정의하면 이진 분류 문제로 구성할 수 있다.

가장 먼저 **예측 시점과 결과를 관찰할 기간**을 정해야 한다. Feature에는 예측 시점까지 알 수 있는 정보만 포함한다.

예측 이후 발생한 행동이나 결제 완료 정보를 입력에 사용하면 데이터 누수가 생긴다. 실제 예측에서는 얻을 수 없는 정보로 높은 검증 점수를 기록할 수 있기 때문이다.

전체 사용자 10,000명 중 결제가 1,400명이라면 전부 미결제로 예측해도 Accuracy가 86%이다. 따라서 Accuracy만으로 유용한 모델이라고 판단하면 안 된다.

- Precision: 결제할 것으로 예측한 사용자 중 실제 결제한 비율
- Recall: 실제 결제한 사용자 중 모델이 찾아낸 비율
- F1-score: Precision과 Recall을 함께 고려하는 지표

모델 개선도 진단 결과에 맞게 선택한다.

| 진단 | 고려할 개선 방향 |
|---|---|
| Train만 좋고 검증 성능이 낮음 | 복잡도 제한, 규제, 누수 점검 |
| 클래스 불균형이 큼 | 평가 지표 재검토, 필요 시 가중치·Resampling 검토 |
| 분할에 따라 점수가 크게 변함 | CV와 데이터 구성 확인 |
| 설정이 적절하지 않음 | 하이퍼파라미터 탐색 |

더 복잡한 모델을 무조건 적용하기보다 무엇이 문제인지 확인한 뒤 개선하고 다시 검증한다.

---

## 8. 미래 매출을 예측한다면

다음 달 매출을 예측하는 문제는 개별 고객의 결제 여부를 예측하는 문제와 다르다.

시간 순서가 있는 과거 매출로 추세와 반복 패턴을 확인하고 시계열 분석을 적용할 수 있다. 과거 정보로 미래를 예측하는 상황에 맞게 검증해야 한다.

사용자 행동 분석, 분류와 시계열 분석은 같은 서비스에서 활용할 수 있지만 질문, 데이터 구성과 평가 방식이 다르다.

---

## 9. 결과와 모델의 판단을 해석하기

분석과 모델링의 결과는 다음 행동을 결정할 수 있는 문장으로 정리해야 한다.

모바일 결제율이 낮다면 어느 단계, 어느 사용자에게 차이가 생겼는지 설명하고 추가 확인이 필요한 사항을 구분한다.

머신러닝을 사용했다면 모델이 어떤 정보를 활용했는지도 확인한다.

| 관점 | 질문 | 방법 |
|---|---|---|
| Global | 전체 예측에서 어떤 Feature가 중요한가? | Feature Importance, SHAP Global |
| Local | 특정 사용자를 왜 이렇게 예측했는가? | SHAP Local |

SHAP은 모델 예측에 대한 기여를 설명한다. 특정 Feature의 기여도가 높다는 사실만으로 그 Feature가 실제 결과의 원인이라고 결론 내릴 수 없다.

모델 해석은 예측을 이해하고 활용 방향을 판단하는 근거이며, 실제 정책의 효과는 별도로 검증해야 한다.

---

## 10. 의사결정과 실제 적용으로 연결하기

추가 조사에서 모바일 결제 단계의 오류가 발견되었다면 해당 과정을 개선하고 효과를 검증할 수 있다.

A/B Test로 기존 화면과 개선 화면을 비교할 때는 목표 지표 하나뿐 아니라 다음 요소를 함께 확인한다.

- 결제 완료율이 개선되었는가?
- 통계적인 근거와 실제 효과의 크기는 어느 정도인가?
- 매출 등 비즈니스 측면에서 의미 있는 변화인가?
- 오류율이나 다른 중요한 지표가 악화되지 않았는가?

좋은 예측 모델도 활용 목적과 오류의 영향을 고려해야 한다. 결제 가능성에 따라 강의를 추천하는 경우에도, 예측 점수가 높은 것과 추천이 실제 결제를 늘리는 것은 별개의 검증 대상이다.

새 데이터에 모델을 적용하려면 학습 때와 동일한 전처리가 필요하다. 전처리와 모델을 Pipeline으로 연결하고 저장하면 일관된 처리 흐름을 재사용할 수 있다.

---

## 11. 적용 이후 다시 측정하고 개선하기

제품을 개선하거나 모델을 적용했다고 문제 해결이 끝나는 것은 아니다.

모바일 결제 화면을 바꾸었다면 실제 결제 완료율과 매출, 오류율이 어떻게 변했는지 확인한다. 모델을 적용했다면 새 데이터에서 예측 성능과 입력 분포가 유지되는지 확인한다.

서비스와 사용자 행동이 변하면 과거의 분석 결과나 모델 성능도 달라질 수 있다. 필요하면 원인을 다시 분석하고 개선안을 검증하여 재적용한다.

전체 흐름은 다음과 같이 연결된다.

1. 비즈니스 문제와 목표를 정의한다.
2. 질문에 필요한 데이터를 확보하고 품질을 확인한다.
3. 현재 상황을 분석하여 문제를 구체화한다.
4. 질문에 맞는 분석 또는 모델링 방법을 선택한다.
5. 결과의 신뢰성과 모델 성능을 검증한다.
6. 관찰된 사실과 해석을 구분하여 결과를 정리한다.
7. 의사결정을 내리고 제품이나 서비스에 적용한다.
8. 실제 효과를 다시 측정하고 새로운 문제를 개선한다.

---

## 12. 핵심 정리

- 데이터 업무는 문제 정의, 데이터 확보, 분석, 검증, 의사결정, 적용과 개선으로 이어진다.
- 분석 방법보다 해결할 질문을 먼저 정해야 한다.
- 데이터 품질이 좋지 않으면 분석 결과의 신뢰성도 낮아진다.
- Funnel과 Segmentation은 사용자 행동에서 문제 위치와 집단을 찾는 데 유용하다.
- 통계적 차이, 관찰된 관계와 인과관계는 구분해야 한다.
- 예측 모델은 예측 시점에 알 수 있는 정보만 Feature로 사용해야 한다.
- 모델의 개선 방법은 과적합, 불균형, 성능 변동 등 진단한 문제에 맞게 선택한다.
- Feature Importance와 SHAP은 모델의 판단을 설명하지만 인과관계를 증명하지 않는다.
- 분석과 예측의 결과는 실제 행동과 효과 검증으로 연결해야 한다.
- 적용 이후에도 데이터와 성능을 다시 확인하고 검증과 개선을 반복한다.

## 오늘의 한 문장

> 데이터 사이언스는 배운 방법을 모두 적용하는 일이 아니라, 해결할 질문에 맞는 데이터와 방법을 선택하고 결과를 의사결정과 검증 가능한 개선으로 연결하는 일이다.
