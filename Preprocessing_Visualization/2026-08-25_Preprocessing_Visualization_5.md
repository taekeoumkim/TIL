# \[2026-08-25\] EDA 기초 - 데이터를 이해하고 질문을 발전시키는 탐색적 데이터 분석

## 학습 목표

-   EDA(Exploratory Data Analysis, 탐색적 데이터 분석)의 정의와 필요성을
    설명할 수 있다.
-   본격적인 분석이나 모델링 전에 데이터의 특성과 문제점을 먼저 확인해야
    하는 이유를 이해한다.
-   EDA의 핵심 목적인 데이터 이해, 이상치·결측치 발견, 특성 선택의
    힌트를 이해한다.
-   EDA의 **질문 → 탐색 → 인사이트 → 새 질문** 과정을 단계별로 설명할 수
    있다.
-   `info()`, `describe()`, `groupby()`, `sort_values()` 등 지금까지
    배운 Pandas 기능을 EDA에 활용할 수 있다.

------------------------------------------------------------------------

# 1. EDA란?

EDA는 **Exploratory Data Analysis**, 즉 **탐색적 데이터 분석**을
의미한다.

데이터를 전달받았다고 해서 바로 매출을 계산하거나 머신러닝 모델을 만드는
것이 아니라, 먼저 데이터가 어떤 모습인지 이해하는 과정이 필요하다.

EDA는 본격적인 분석이나 모델링 전에 **데이터의 특성, 분포, 패턴을 통계와
시각화를 통해 파악하는 과정**이다.

쉽게 말하면 다음과 같다.

> **데이터를 본격적으로 분석하기 전에 데이터가 어떤 모습인지 살펴보고,
> 문제점과 특징을 발견하는 과정**

데이터 분석의 시작은 수치를 무작정 계산하는 것이 아니라 다음 두 가지를
먼저 생각하는 것이다.

``` text
데이터는 어떤 모습인가?
우리가 알고 싶은 것은 무엇인가?
```

------------------------------------------------------------------------

# 2. 데이터를 받자마자 분석하면 안 되는 이유

온라인 쇼핑몰 주문 데이터를 받았다고 가정한다.

다음과 같은 데이터가 있을 수 있다.

``` python
import pandas as pd

orders = pd.DataFrame({
    "customer": ["A", "B", "C", "D", "E"],
    "amount": [25000, 32000, 28000, None, 500000]
})

print(orders)
print()
print(orders.describe())
```

데이터를 살펴보면 다음과 같은 특징을 발견할 수 있다.

``` text
A → 25,000원
B → 32,000원
C → 28,000원
D → 결측값
E → 500,000원
```

여기서 바로 두 가지 질문이 생긴다.

``` text
1. D 고객의 주문 금액은 왜 비어 있을까?
2. 대부분 2~3만 원인데 50만 원 주문은 정상적인 값일까?
```

50만 원 주문은 실제 대량 주문일 수도 있고 잘못 입력된 값일 수도 있다.

즉, 데이터에 존재하는 값만 보고 바로 결론을 내리는 것이 아니라 **추가
확인이 필요한 데이터인지 판단하는 과정**이 필요하다.

이 과정이 EDA이다.

------------------------------------------------------------------------

# 3. EDA에서 발견할 수 있는 것

EDA를 통해 대표적으로 다음과 같은 것을 확인할 수 있다.

``` text
데이터의 전체 구조
데이터 타입
데이터의 분포
결측값
이상치
변수 간 관계
그룹별 차이
특이한 패턴
```

예를 들어 주문 금액 데이터에서

``` text
대부분 → 20,000 ~ 30,000원
특정 주문 → 500,000원
```

이라는 패턴을 발견했다면 500,000원이 **이상치인지 정상적인 대량 주문인지
추가로 확인**할 수 있다.

EDA는 단순히 오류를 찾는 과정만은 아니다.

데이터에 숨어 있는 특징과 패턴을 발견하여 **이후 분석 방향을 결정하는
과정**이기도 하다.

------------------------------------------------------------------------

# 4. EDA가 중요한 이유

EDA를 하지 않고 바로 머신러닝 모델에 데이터를 넣으면 여러 문제가 발생할
수 있다.

예를 들어 데이터에 다음과 같은 문제가 있다고 생각해보자.

``` text
결측값
이상치
잘못된 데이터 타입
잘못 입력된 값
특정 변수의 극단적인 분포
```

이런 문제를 확인하지 않고 모델링하면 문제가 그대로 모델에 반영되어
성능이 저하될 수 있다.

또한 EDA를 통해

``` text
어떤 feature가 중요할 가능성이 있는지
어떤 전처리가 필요한지
어떤 데이터 품질 문제가 있는지
```

를 미리 파악할 수 있다.

따라서 EDA는 시간을 낭비하는 단계가 아니라 **잘못된 방향으로 분석하는
시간 낭비를 줄이는 과정**이라고 이해할 수 있다.

------------------------------------------------------------------------

# 5. EDA의 3가지 핵심 목적

학습자료에서는 EDA를 수행하는 핵심 목적을 세 가지로 정리했다.

  목적                    설명
  ----------------------- -----------------------------------------
  모델링 전 데이터 이해   데이터의 구조, 분포, 변수 간 관계 파악
  이상치·결측치 발견      데이터 품질 문제를 조기에 발견하고 대응
  특성 선택 힌트          분석이나 모델에 중요한 변수를 파악

------------------------------------------------------------------------

## 5-1. 모델링 전 데이터 이해

모델을 만들기 전에 데이터가 어떤 구조인지 알아야 한다.

예를 들어 다음을 확인할 수 있다.

``` text
몇 개의 행과 컬럼이 있는가?
어떤 변수들이 있는가?
각 컬럼의 데이터 타입은 무엇인가?
값들은 어떤 범위에 분포하는가?
변수 간에는 어떤 관계가 있는가?
```

데이터를 충분히 이해해야 이후 분석 방향을 올바르게 설정할 수 있다.

------------------------------------------------------------------------

## 5-2. 이상치와 결측치 발견

EDA를 통해 데이터 품질 문제를 조기에 발견할 수 있다.

예:

``` text
주문 금액이 비어 있음 → 결측값
대부분 3만 원인데 500만 원 주문 → 이상치 가능성
숫자여야 하는 컬럼이 문자열 → 데이터 타입 문제
```

이런 문제를 발견한 뒤 실제 오류인지 정상적인 데이터인지 판단하고 필요한
전처리를 수행해야 한다.

------------------------------------------------------------------------

## 5-3. 특성 선택의 힌트

머신러닝 모델에서는 어떤 변수를 사용하는지가 중요하다.

EDA를 통해 특정 변수가 예측하려는 대상과 관련이 있을 가능성을 발견할 수
있다.

예를 들어 고객 이탈 여부와 서비스 이용 횟수 사이에 차이가 있다면
`usage_count`가 고객 이탈과 관련된 중요한 feature일 가능성을 생각해볼 수
있다.

------------------------------------------------------------------------

# 6. 고객 이탈 모델을 만들기 전 EDA

구독 서비스에서 고객이 다음 달에 서비스를 해지할지 예측하는 모델을
만든다고 가정한다.

바로 모델을 만드는 대신 **이탈 고객과 유지 고객 사이에 어떤 차이가
있는지** 먼저 확인한다.

``` python
import pandas as pd

customers = pd.DataFrame({
    "customer": ["A", "B", "C", "D", "E", "F"],
    "usage_count": [3, 4, 2, 18, 15, 20],
    "churn": ["이탈", "이탈", "이탈", "유지", "유지", "유지"]
})

print(
    customers
    .groupby("churn")["usage_count"]
    .mean()
)
```

결과:

``` text
churn
유지    17.666667
이탈     3.000000
```

EDA 결과를 보면

``` text
이탈 고객 평균 이용 횟수 → 3회
유지 고객 평균 이용 횟수 → 약 17.7회
```

라는 차이가 나타난다.

------------------------------------------------------------------------

# 7. EDA에서 발견한 패턴을 바로 결론으로 생각하면 안 된다

위 결과만 보면 다음과 같이 생각할 수 있다.

``` text
이용 횟수가 적은 고객은 이탈한다.
```

하지만 EDA 결과만으로 이런 인과적인 결론을 내리면 안 된다.

현재 확인할 수 있는 것은

> **서비스 이용 횟수가 고객 이탈과 관련이 있을 가능성이 있다.**

정도이다.

즉, EDA에서 발견한 패턴은 **최종 결론이라기보다 이후 분석에서 확인해야
할 힌트**라고 생각해야 한다.

이러한 패턴은 이후

``` text
추가 분석
feature 선택
모델링
가설 설정
```

등의 방향을 정하는 데 사용할 수 있다.

------------------------------------------------------------------------

# 8. EDA의 핵심 프로세스

EDA는 데이터를 한 번 확인하고 끝나는 과정이 아니다.

학습자료에서는 EDA를 다음 네 단계의 반복 과정으로 설명한다.

``` text
1. 질문 (Question)
        ↓
2. 탐색 (Exploration)
        ↓
3. 인사이트 (Insight)
        ↓
4. 새 질문 (New Question)
        ↓
다시 질문으로 돌아가 반복
```

즉,

> **질문 → 탐색 → 인사이트 → 새 질문**

이라는 순환 구조이다.

------------------------------------------------------------------------

# 9. 1단계: 질문(Question)

EDA는 **질문에서 시작**한다.

먼저 분석하고자 하는 질문을 정의한다.

좋은 질문은 구체적이고 데이터를 통해 답할 수 있어야 한다.

예:

``` text
월별 매출은 어떻게 변하고 있는가?
어떤 상품의 매출이 가장 높은가?
어떤 고객군의 이탈률이 높은가?
회원 등급별 평균 구매금액은 어떻게 다른가?
```

반대로 다음처럼 너무 추상적인 질문은 분석하기 어렵다.

``` text
매출을 분석해보자.
고객을 알아보자.
```

따라서 EDA를 시작할 때는 **무엇을 알고 싶은지 구체적인 질문으로 만드는
것**이 중요하다.

------------------------------------------------------------------------

# 10. 2단계: 탐색(Exploration)

질문을 정의했다면 데이터에서 답을 찾기 위해 탐색한다.

탐색 단계에서는 통계와 시각화 등을 사용할 수 있다.

학습자료에서 언급된 대표적인 도구는 다음과 같다.

``` python
hist()
boxplot()
scatter plot
groupby()
```

또한 지금까지 배운 Pandas 기능도 EDA에서 활용할 수 있다.

``` python
df.info()
df.describe()
df.groupby(...)
df.sort_values(...)
```

즉, 이전에 배운 Pandas 문법은 단순히 문법 자체가 목적이 아니라 **EDA
과정에서 질문에 답하기 위한 도구**로 사용할 수 있다.

------------------------------------------------------------------------

# 11. 3단계: 인사이트(Insight)

탐색 결과에서 의미 있는

``` text
패턴
이상치
관계
차이
```

를 발견하고 해석하는 단계이다.

예를 들어:

``` text
20대 여성 고객의 구매 전환율이 다른 고객군보다 높다.
```

처럼 구체적으로 발견한 내용을 인사이트라고 할 수 있다.

중요한 점은 단순히 숫자를 출력하는 것과 인사이트는 다르다는 것이다.

``` text
단순 결과
→ 노트북 매출: 8,500,000원

인사이트
→ 노트북이 다른 상품보다 가장 높은 매출을 기록하고 있다.
```

그리고 이 인사이트를 통해 **왜 이런 결과가 발생했는지 새로운 질문**을
만들 수 있다.

------------------------------------------------------------------------

# 12. 4단계: 새 질문(New Question)

인사이트를 발견했다고 EDA가 끝나는 것은 아니다.

발견한 내용에서 새로운 질문을 만든다.

예를 들어

``` text
인사이트
→ 노트북의 매출이 가장 높다.
```

라는 결과를 얻었다면 다음 질문으로 이어질 수 있다.

``` text
왜 노트북 매출이 높은가?
노트북이 많이 팔렸기 때문인가?
상품 가격이 높기 때문인가?
특정 기간에 판매가 집중되었는가?
```

새로운 질문이 만들어지면 다시 데이터를 탐색한다.

따라서 EDA는 다음 과정이 반복된다.

``` text
질문
 ↓
탐색
 ↓
인사이트
 ↓
새 질문
 ↓
탐색
 ↓
새 인사이트
 ↓
...
```

------------------------------------------------------------------------

# 13. 쇼핑몰 매출 예제로 이해하는 EDA

쇼핑몰 데이터에서 다음 질문으로 EDA를 시작했다고 가정한다.

> **어떤 상품의 매출이 가장 높은가?**

상품별 매출 데이터가 다음과 같다.

``` python
import pandas as pd

sales = pd.DataFrame({
    "product": ["노트북", "마우스", "키보드", "모니터"],
    "sales": [8500000, 1200000, 1800000, 5200000]
})

print(
    sales.sort_values(
        "sales",
        ascending=False
    )
)
```

결과:

``` text
product    sales
노트북     8500000
모니터     5200000
키보드     1800000
마우스     1200000
```

이를 EDA의 4단계로 연결하면 다음과 같다.

### 1. 질문

``` text
어떤 상품의 매출이 가장 높은가?
```

### 2. 탐색

상품별 매출을 확인하고 높은 순서대로 정렬한다.

``` python
sales.sort_values(
    "sales",
    ascending=False
)
```

### 3. 인사이트

``` text
노트북의 매출이 850만 원으로 가장 높다.
```

하지만 여기에서 분석을 끝내지 않는다.

### 4. 새 질문

``` text
왜 노트북 매출이 높은가?
```

그리고 다음 질문으로 발전시킬 수 있다.

``` text
노트북이 많이 팔렸기 때문인가?
노트북의 단가가 높기 때문인가?
특정 기간에 판매가 집중되었는가?
```

이처럼 EDA에서는 **하나의 발견이 다음 탐색의 출발점**이 된다.

------------------------------------------------------------------------

# 14. EDA는 선형 과정이 아니라 순환 과정

EDA를 다음처럼 생각하면 안 된다.

``` text
질문 → 탐색 → 결과 → 끝
```

실제 EDA는 다음과 같다.

``` text
       ┌───────────────┐
       ↓               │
    질문               │
       ↓               │
    탐색               │
       ↓               │
   인사이트             │
       ↓               │
   새 질문 ─────────────┘
```

즉, **질문과 탐색을 반복하면서 데이터를 점점 더 깊게 이해하는
과정**이다.

이 점이 오늘 학습한 EDA에서 가장 중요한 개념 중 하나였다.

------------------------------------------------------------------------

# 15. EDA는 언제 끝날까?

EDA에는 명확한 종료 기준이 없다.

분석 목적에 맞는 충분한 인사이트를 얻었다고 판단되면 마무리할 수 있다.

실무에서는 다음 질문을 기준으로 생각할 수 있다.

> **이 데이터로 다음 단계인 모델링이나 보고서 작성을 진행할 수 있을 만큼
> 충분히 이해했는가?**

만약 시간이 제한되어 있다면 모든 질문을 끝까지 분석하기보다는 핵심
질문에 집중하고 나머지는 이후 분석할 내용으로 남겨둘 수 있다.

즉, EDA는 무조건 오래 하는 것이 목적이 아니라 **분석 목적에 필요한
수준까지 데이터를 이해하는 것**이 중요하다.

------------------------------------------------------------------------

# 16. EDA에서 info() 활용하기

본격적인 분석 전에 데이터의 전체 구조를 확인할 수 있다.

``` python
import pandas as pd

df = pd.read_csv(
    "ecommerce_sales_analytics_5000.csv"
)

df.info()
```

`info()`를 통해 다음을 확인할 수 있다.

``` text
전체 행 수
전체 컬럼 수
각 컬럼의 이름
각 컬럼의 데이터 타입
각 컬럼의 non-null 개수
결측값 존재 가능성
```

EDA를 시작할 때 데이터의 기본 구조를 빠르게 파악하는 데 유용하다.

------------------------------------------------------------------------

# 17. EDA에서 describe() 활용하기

수치형 컬럼의 기본 통계량을 한 번에 확인하려면 `describe()`를 사용할 수
있다.

``` python
df.describe()
```

대표적으로 다음 값을 확인할 수 있다.

  값        의미
  --------- -------------
  `count`   데이터 개수
  `mean`    평균
  `std`     표준편차
  `min`     최솟값
  `25%`     1사분위수
  `50%`     중앙값
  `75%`     3사분위수
  `max`     최댓값

예를 들어

``` text
평균에 비해 max가 지나치게 크다.
```

면 이상치가 존재할 가능성을 생각해볼 수 있다.

다만 값이 크다는 이유만으로 바로 이상치라고 결정하는 것이 아니라 **실제
의미를 추가로 확인해야 한다.**

------------------------------------------------------------------------

# 18. EDA에서 groupby() 활용하기

그룹별 차이를 확인할 때 `groupby()`를 활용할 수 있다.

고객 이탈 여부에 따른 평균 이용 횟수:

``` python
customers.groupby(
    "churn"
)["usage_count"].mean()
```

상품 카테고리별 주문 건수처럼 범주별 데이터 특성을 확인할 때도 활용할 수
있다.

예를 들어:

``` python
df.groupby(
    "product_category"
)["order_id"].count()
```

이처럼 이전에 배운 `groupby()`는 EDA에서 **그룹별 패턴과 차이를 발견하는
도구**가 된다.

------------------------------------------------------------------------

# 19. EDA에서 sort_values() 활용하기

값의 크기를 비교하고 상위 또는 하위 데이터를 찾을 때 `sort_values()`를
사용할 수 있다.

``` python
sales.sort_values(
    "sales",
    ascending=False
)
```

이를 이용하면 다음과 같은 질문에 답할 수 있다.

``` text
어떤 상품의 매출이 가장 높은가?
어떤 주문의 배송 기간이 가장 긴가?
어떤 고객의 구매금액이 가장 큰가?
```

즉, 이전 강의에서 배운 정렬도 EDA의 탐색 단계에서 활용할 수 있다.

# 20. 지금까지 배운 Pandas와 EDA의 연결

지금까지 배운 Pandas 기능을 EDA 관점에서 다시 보면 각각의 역할을
이해하기 쉽다.

  Pandas 기능       EDA에서의 활용
  ----------------- ---------------------------------------
  `head()`          데이터의 앞부분 확인
  `info()`          데이터 구조, 타입, 결측 여부 확인
  `describe()`      수치형 변수의 분포와 요약 통계 확인
  `groupby()`       그룹별 차이와 패턴 탐색
  `agg()`           여러 그룹별 통계 지표 확인
  `sort_values()`   상위·하위 값 확인
  `sort_index()`    index 기준으로 결과 정리
  `merge()`         서로 다른 데이터를 결합하여 추가 탐색

결국 Pandas의 여러 메서드는 따로 존재하는 기능이 아니라 **데이터에 대한
질문에 답하기 위한 도구**라고 볼 수 있다.

# 21. EDA를 할 때 생각해야 할 질문

새로운 데이터를 받으면 바로 코드를 작성하기보다 다음과 같은 질문을 먼저
생각해볼 수 있다.

``` text
데이터는 몇 행, 몇 열인가?
어떤 컬럼들이 존재하는가?
각 컬럼의 데이터 타입은 무엇인가?
결측값은 존재하는가?
값의 범위는 어느 정도인가?

발견한 패턴은 무엇을 의미하는가?
```

# 22. 오늘의 핵심 코드

``` python
import pandas as pd

# 데이터 불러오기
df = pd.read_csv(
    "ecommerce_sales_analytics_5000.csv"
)

# 1. 데이터 구조 확인
df.info()

# 2. 수치형 컬럼의 요약 통계
df.describe()

# 3. 그룹별 비교
result = (
    df.groupby("product_category")["order_id"]
      .count()
)

# 4. 값 기준 정렬
result = df.sort_values(
    "sales",
    ascending=False
)

# 고객 이탈 여부별 평균 이용 횟수
result = (
    customers.groupby("churn")["usage_count"]
             .mean()
)
```

# 23. 오늘 배운 내용 정리

## EDA란?

EDA는 본격적인 분석이나 모델링 전에 **데이터의 특성, 분포, 패턴,
문제점을 탐색하는 과정**이다.

``` text
EDA
= Exploratory Data Analysis
= 탐색적 데이터 분석
```

------------------------------------------------------------------------

## EDA를 해야 하는 이유

EDA를 통해 다음을 확인할 수 있다.

``` text
1. 모델링 전 데이터 이해
2. 이상치·결측치 발견
3. 중요한 feature에 대한 힌트 발견
```

EDA를 하지 않고 바로 분석이나 모델링을 진행하면 데이터의 문제를 놓치거나
잘못된 방향으로 분석할 가능성이 있다.

------------------------------------------------------------------------

## EDA의 4단계

``` text
질문 (Question)
      ↓
탐색 (Exploration)
      ↓
인사이트 (Insight)
      ↓
새 질문 (New Question)
      ↓
다시 반복
```

EDA는 한 번 데이터를 확인하고 끝나는 작업이 아니라 **질문과 탐색을
반복하면서 데이터를 이해하는 순환 과정**이다.

------------------------------------------------------------------------

## EDA에서 사용할 수 있는 Pandas 기능

``` python
info()
describe()
groupby()
sort_values()
```

이전 강의에서 배운 Pandas 기능들을 EDA의 탐색 도구로 활용할 수 있다.

------------------------------------------------------------------------

# 24. 오늘의 핵심 한 줄

> **EDA는 데이터를 바로 분석하는 것이 아니라, 질문을 가지고 데이터를
> 탐색하고 인사이트를 발견한 뒤 다시 새로운 질문으로 발전시키면서
> 데이터를 이해하는 과정이다.**

# 25. 느낀 점

오늘은 지금까지 배웠던 Pandas 문법들이 실제 데이터 분석 과정에서 어떻게
연결되는지 이해할 수 있었다.

이전까지는 `info()`, `describe()`, `groupby()`, `sort_values()` 같은
기능을 각각 하나의 Pandas 문법으로 생각했는데, EDA를 배우면서 이
기능들이 결국 **데이터에 대한 질문에 답하기 위한 탐색 도구**라는 것을
알게 되었다.

특히 데이터를 받자마자 바로 원하는 값을 계산하거나 머신러닝 모델을
만드는 것이 아니라 먼저 데이터의 구조, 결측값, 이상치, 분포 등을
확인해야 한다는 점이 중요했다. 데이터 자체에 문제가 있다면 이후 분석
결과나 모델 성능에도 영향을 줄 수 있기 때문이다.

또 하나 중요하게 느낀 점은 EDA에서 발견한 패턴을 바로 결론으로 생각하면
안 된다는 것이다. 예를 들어 이탈 고객의 평균 이용 횟수가 유지 고객보다
낮다고 해서 바로 "이용 횟수가 낮으면 고객이 이탈한다"고 결론 내리는 것이
아니라, **두 변수 사이에 관련이 있을 가능성이 있으므로 추가로 확인할
필요가 있다**고 생각해야 한다.

가장 기억에 남는 부분은 EDA의 과정이었다.

``` text
질문 → 탐색 → 인사이트 → 새 질문
```

처음에는 EDA가 데이터의 결측값이나 통계량을 한 번 확인하는 과정이라고
생각했지만, 실제로는 하나의 결과를 발견하면 "왜 이런 결과가
나왔을까?"라는 새로운 질문을 만들고 다시 데이터를 탐색하는 반복적인
과정이라는 것을 알게 되었다.

앞으로 새로운 데이터를 받으면 바로 코드를 작성하기보다 먼저 다음과 같이
생각해보려고 한다.

> **무엇을 알고 싶은가?\
> 어떤 데이터를 확인해야 답할 수 있는가?\
> 탐색 결과에서 어떤 특징을 발견했는가?\
> 그 특징에서 어떤 새로운 질문을 만들 수 있는가?**

이 과정을 반복하면서 데이터를 충분히 이해한 뒤 분석이나 모델링으로
넘어가는 습관을 만들어야겠다.
