## 오늘의 학습 주제

API와 웹 크롤링으로 수집한 데이터를 분석에 사용하기 전에 구조와 품질을 확인하는 방법을 배웠다. DataFrame의 행·컬럼·자료형을 살펴보고, 중복·결측·수집 실패를 구분하여 탐색한 뒤 분석 목적별 활용 가능성을 판단하는 과정이다.

```text
원시 CSV 불러오기 → 구조와 수집 건수 확인
→ 결측·빈 문자열·중복 후보 탐색 → 수집 기록 확인
→ 분석 목적별 활용 가능 건수 파악 → 정제 기준 결정
```

이번 학습의 범위는 **품질 문제의 탐색과 판단**이다. 중복 제거, 결측 처리, 최종 정제 파일 생성은 다음 단계에서 다룬다.

## 1. 수집 데이터의 구조와 수집 결과 확인

파일이 만들어졌다고 해서 데이터가 예상한 형태로 저장되었다는 보장은 없다. 필요한 컬럼이 빠졌거나, 인덱스가 불필요한 컬럼으로 저장되었거나, 일부 페이지의 데이터만 포함되어 있을 수 있다.

이번 데이터셋은 명언 하나를 한 행으로 저장하고 다음 네 개의 컬럼을 사용한다.

| 컬럼 | 의미 |
| --- | --- |
| `text` | 명언 본문 |
| `author` | 작성자 이름 |
| `tags` | 관련 태그 문자열 |
| `source_url` | 데이터 수집 출처 |

### 기본 구조 확인 도구

| 기능 | 확인할 내용 |
| --- | --- |
| `df.shape` | 행과 열의 개수 |
| `len(df)` | 전체 행 수 |
| `df.columns.tolist()` | 컬럼명과 순서 |
| `df.dtypes` | 컬럼별 자료형 |
| `df.info()` | 자료형과 비결측 개수 등 기본 정보 |
| `df.head(3)` | 처음 세 행의 실제 값 |
| `value_counts(dropna=False)` | 결측을 포함한 값별 건수 |

예를 들어 `(100, 4)`는 100행, 4열이라는 뜻이다. 다만 컬럼이 네 개여도 `text`가 빠지고 `Unnamed: 0`이 들어 있다면 올바른 구조가 아니다. 컬럼 수뿐 아니라 이름도 비교해야 한다.

```python
expected_columns = ["text", "author", "tags", "source_url"]

missing_columns = [
    col for col in expected_columns if col not in df.columns
]
extra_columns = [
    col for col in df.columns if col not in expected_columns
]

print("누락된 컬럼:", missing_columns)
print("추가된 컬럼:", extra_columns)
```

위 비교는 컬럼의 존재 여부를 확인한다. 컬럼 순서까지 검증하려면 `df.columns.tolist() == expected_columns`처럼 별도로 비교할 수 있다.

문자열 컬럼의 자료형은 Pandas 버전과 읽기 설정 등에 따라 `object`나 문자열 자료형으로 나타날 수 있다. 자료형 표시만 보지 말고 본문에 명언이, 작성자에 이름이, 출처에 URL이 들어 있는지 실제 값도 확인한다. `head()`는 일부 행만 보여 주므로 전체 품질을 보장하지 않는다.

### 수집 건수가 예상과 다를 때

| 발견한 문제 | 우선 확인할 사항 |
| --- | --- |
| CSV 파일 없음 | 파일 경로와 수집 코드 실행 여부 |
| 행 수가 0 | 추출 결과와 저장 과정 |
| 필수 컬럼 누락 | 필드 추출과 DataFrame 생성 과정 |
| `Unnamed: 0` 존재 | `to_csv(index=False)` 설정 여부 |
| 예상보다 적은 행 수 | 페이지별 요청·추출 결과와 종료 조건 |
| 예상과 다른 자료형 | 원본 값과 CSV 읽기·저장 과정 |

예상 건수는 사이트의 데이터 변경 가능성을 고려해야 한다. 행 수가 맞아도 중복과 누락이 동시에 발생할 수 있으므로 건수만으로 전체 수집 성공을 확정하지 않는다.

## 2. 중복·결측·수집 실패 구분

### 중복 후보는 기준을 정해 탐색하기

중복은 동일 페이지의 반복 수집, 여러 페이지의 동일 데이터, API와 HTML 결과의 결합 등으로 발생할 수 있다. 같은 명언이 반복되면 단어 빈도가 실제보다 높게 집계될 수 있다.

이번에는 **본문과 작성자가 모두 동일한 행**을 중복 후보로 판단한다. 출처가 달라도 같은 명언일 수 있으므로 `source_url`은 비교 기준에서 제외한다.

```python
df.duplicated(subset=["text", "author"])
df.duplicated(subset=["text", "author"], keep=False)
```

| 설정 | 표시되는 행 |
| --- | --- |
| 기본값 `keep="first"` | 같은 값 중 첫 번째를 제외한 반복 행 |
| `keep=False` | 중복 그룹에 포함된 모든 행 |

동일한 명언이 두 행에 있다면 `keep=False`로 계산한 중복 후보 행 수는 2다. 첫 행을 남기는 정책이라면 제거 대상은 1행이므로, **중복 그룹의 전체 행 수와 삭제할 행 수는 다르다.**

중복 후보라고 즉시 삭제하지 않는다. 분석 단위와 출처, 반복 수집 여부를 확인한 뒤 처리 기준을 정한다.

### 결측값과 빈 문자열은 다르다

`isna()`는 `None`, `NaN`, `pd.NA` 같은 결측값을 확인한다. 하지만 빈 문자열과 공백 문자열도 텍스트 분석에서는 내용이 없는 값이므로 함께 탐색해야 한다.

| 값 | 확인할 점 |
| --- | --- |
| `None`, `NaN`, `pd.NA` | 결측값으로 탐색 |
| `""` | 문자열이지만 내용 없음 |
| `"   "` | 공백 제거 후 빈 문자열인지 확인 |

`read_csv()`는 기본적으로 빈 필드나 일부 문자열을 결측값으로 해석할 수 있다. 학습자료에서는 `keep_default_na=False`로 기본 자동 해석을 끄고, 확인용 복사본에서 공백과 빈 문자열을 직접 처리한다.

이 설정을 사용하면 `"NULL"`, `"NaN"` 같은 문자열도 그대로 남을 수 있다. 실제로 결측을 뜻하는지는 데이터의 의미와 별도 규칙으로 판단해야 한다.

### 수집 실패는 CSV만으로 확인하기 어렵다

저장된 행이 정상이어도 수집하지 못한 페이지가 있을 수 있다. 이를 확인하려면 다음 기록이 필요하다.

- 페이지별 요청 성공 여부와 HTTP 상태 코드 또는 오류 내용
- 페이지별 추출 건수와 실패한 URL
- API의 `has_next=False` 또는 HTML의 Next 링크 종료 조건 도달 여부

`source_url`별 건수는 저장된 데이터의 분포를 보여 준다. 요청하지 못한 페이지나 실패한 요청은 행 자체가 없을 수 있으므로, 출처별 집계와 수집 기록을 함께 살펴야 한다.

## 3. 분석 목적에 따른 품질 판단

데이터 품질은 분석 목적에 필요한 조건을 얼마나 충족하는지에 따라 판단한다.

| 개념 | 의미 |
| --- | --- |
| 완전성(Completeness) | 필요한 값과 데이터가 충분히 확보되었는가? |
| 고유성(Uniqueness) | 동일한 데이터가 불필요하게 반복되지 않는가? |
| 유효성(Validity) | 요구하는 형식과 조건에 맞는가? |
| 활용 가능성(Data Usability) | 실제 분석 목적에 사용할 수 있는가? |

### 분석마다 필수 값이 다르다

| 분석 목적 | 필요한 값 | 누락 시 판단 |
| --- | --- | --- |
| 단어 빈도 분석 | `text` | 본문이 없으면 활용하기 어려움 |
| 작성자별 명언 분석 | `text`, `author` | 작성자가 없으면 비교에 제한 |
| 태그별 명언 분석 | `text`, `tags` | 태그가 없으면 분류에 제한 |
| 출처 추적 | `source_url` | 수집 기록 확인 필요 |

작성자가 없어도 본문이 있으면 기본 텍스트 분석에 사용할 수 있다. 태그가 없어도 마찬가지다. 따라서 모든 컬럼의 값이 채워진 행만 남기는 기준을 일괄 적용하기보다 분석 목적별로 판단해야 한다.

데이터셋의 스키마로 요구하는 컬럼과, 특정 분석에서 값이 반드시 있어야 하는 필드는 구분한다. 컬럼이 존재해도 값은 비어 있을 수 있다.

### 전체 수집 건수와 활용 가능 건수 구분

예를 들어 100행 중 본문이 있는 행이 95개, 본문과 작성자가 있는 행이 90개, 본문과 태그가 있는 행이 85개라면 분석별 대상 건수는 달라진다. 이 숫자는 설명을 위한 가상 예시다.

```text
텍스트 분석 후보 = 본문이 있는 행
작성자별 분석 후보 = 본문과 작성자가 모두 있는 행
태그별 분석 후보 = 본문과 태그가 모두 있는 행
```

이는 필수 값의 존재 여부만 확인한 결과다. 중복 처리, 내용의 적절성, 수집 완전성 검증까지 마친 최종 분석 건수는 아니다.

## 4. 구조·품질·활용 가능 건수를 함께 확인하는 코드

다음은 학습자료의 탐색 과정을 하나로 정리한 예시다. 앞서 수집한 `quotes_raw.csv`와 Pandas가 필요하다. 원본 파일을 덮어쓰거나 정제 파일을 생성하지 않는다.

```python
from pathlib import Path
import pandas as pd

# 1. 파일과 기본 구조 확인
file_path = Path("quotes_raw.csv")
if not file_path.exists():
    raise FileNotFoundError("quotes_raw.csv 파일이 없습니다.")

df = pd.read_csv(
    file_path, encoding="utf-8-sig", keep_default_na=False
)
columns = ["text", "author", "tags", "source_url"]

print("Shape:", df.shape)
print("컬럼:", df.columns.tolist())
print("자료형:\n", df.dtypes)
df.info()
print(df.head(3))

missing = [col for col in columns if col not in df.columns]
extra = [col for col in df.columns if col not in columns]
print("추가된 컬럼:", extra)
if missing:
    raise ValueError(f"누락된 컬럼: {missing}")

# 2. 원본을 유지하고 확인용 복사본에서 값 정리
check_df = df.copy()
for col in columns:
    values = check_df[col].astype("string").str.strip()
    check_df[col] = values.mask(values.eq(""), pd.NA)

print("\n결측·빈 문자열 건수:")
print(check_df[columns].isna().sum())

# 3. 본문과 작성자가 있는 행의 중복 후보 탐색
has_text = check_df["text"].notna()
has_author = check_df["author"].notna()
has_tags = check_df["tags"].notna()
has_source = check_df["source_url"].notna()

duplicate_mask = (
    has_text
    & has_author
    & check_df.duplicated(
        subset=["text", "author"], keep=False
    )
)
print("\n중복 후보 행 수:", duplicate_mask.sum())
print(check_df.loc[duplicate_mask, ["text", "author"]].head(10))

# 4. 출처별 분포 확인
print("\n출처별 건수:")
print(check_df["source_url"].value_counts(dropna=False))
print("출처 누락 건수:", (~has_source).sum())

# 5. 필수 값 존재 여부에 따른 분석 후보 건수
counts = {
    "텍스트 분석": int(has_text.sum()),
    "작성자별 분석": int((has_text & has_author).sum()),
    "태그별 분석": int((has_text & has_tags).sum()),
}

print("\n전체 수집 건수:", len(df))
for purpose, count in counts.items():
    if len(df) > 0:
        print(f"{purpose}: {count}개 ({count / len(df):.1%})")
    else:
        print(f"{purpose}: 0개 (비율 계산 불가)")

print("원본 데이터와 CSV 파일은 변경하지 않았습니다.")
```

### 코드에서 기억할 점

- 필수 컬럼을 먼저 확인하여 이후 탐색이 가능한지 판단한다.
- `.astype("string").str.strip()`으로 확인용 값을 만들고 빈 문자열을 `pd.NA`로 표시한다.
- 확인용 복사본에서만 값을 정리하므로 원본 `df`와 CSV는 유지된다.
- 본문과 작성자가 모두 존재하는 행만 중복 후보 비교 대상으로 삼는다.
- `keep=False`의 합계는 중복 그룹에 포함된 전체 행 수다.
- 전체 행 수가 0이면 활용 가능 비율을 계산하지 않아 0으로 나누는 상황을 피한다.

이 코드는 문자열의 존재와 정확히 일치하는 중복 후보를 탐색한다. 실제 값이 의미상 올바른지, URL이 유효한지, 전체 페이지를 수집했는지까지 자동으로 검증하지는 않는다. 예시 코드를 실제 CSV에 실행한 결과는 이 문서에 포함하지 않았다.

## 5. 탐색 결과를 정제 기준으로 연결하기

| 발견한 문제 | 다음 단계에서 검토할 내용 |
| --- | --- |
| 본문 누락 | 원본과 추출 과정을 확인한 뒤 재수집 또는 제외 |
| 작성자 누락 | 작성자별 분석 필요성에 따라 유지 여부 판단 |
| 태그 누락 | 기본 텍스트 분석에 유지할 수 있는지 판단 |
| 중복 후보 | 분석 단위와 중복 기준을 확인한 뒤 제거 여부 결정 |
| 출처 누락 | 수집 기록에서 복구 가능한지 확인 |
| 페이지 수집 실패 | 실패한 요청과 종료 조건을 확인하고 재수집 검토 |

문제의 유형과 건수를 확인하는 것은 탐색이고, 데이터를 삭제하거나 수정하는 것은 정제다. 먼저 원인을 파악하고 분석 목적에 맞는 처리 기준을 결정해야 한다.

## 오늘 배운 점

- 컬럼 수가 맞아도 필요한 이름이 빠질 수 있으므로 구조를 구체적으로 비교해야 한다.
- `isna()`뿐 아니라 빈 문자열과 공백 문자열도 확인해야 텍스트의 실제 누락을 파악할 수 있다.
- 중복 여부는 비교할 컬럼과 분석 단위를 먼저 정해야 하며, 후보 행 수를 삭제 건수로 해석하면 안 된다.
- 저장된 CSV가 정상이어도 수집하지 못한 데이터가 있을 수 있어 페이지별 기록이 중요하다.
- 분석 목적마다 필요한 값이 다르므로 전체 수집 건수와 목적별 활용 가능 건수를 나누어 살펴야 한다.
- 품질 문제를 발견한 뒤에는 원인과 분석 영향을 확인하고 정제 방법을 결정해야 한다.

> 오늘의 핵심: 데이터가 저장되었는지를 넘어, 예상한 구조인지와 분석에 필요한 값이 있는지, 수집 범위가 완전한지를 나누어 확인하는 방법을 배웠다.
