## 1. A/B 테스트란?

A/B 테스트는 사용자를 두 집단으로 나누어 서로 다른 조건을 제공한 뒤, 두 집단의 성과 지표를 비교하는 통제 실험이다.

예를 들어 회원가입 버튼의 문구를 변경한 뒤 가입률이 증가했더라도, 그 변화만으로 새 문구의 효과라고 단정할 수는 없다. 주말 방문자 증가나 광고 캠페인처럼 결과에 영향을 미친 다른 요인이 있을 수 있기 때문이다.

A/B 테스트에서는 동일한 기간에 다음 두 조건을 운영한다.

| 구분 | 적용 조건 | 역할 |
|---|---|---|
| A 그룹 | 기존 회원가입 버튼 | 대조군(Control) |
| B 그룹 | 문구를 변경한 버튼 | 실험군(Treatment) |

두 그룹 사이에서 버튼 문구만 다르게 유지하면, 관찰된 가입률 차이를 문구 변경의 효과로 해석할 근거가 생긴다.

### 핵심 목적

A/B 테스트의 목적은 단순히 두 집단의 수치를 비교하는 것이 아니라, 특정 변화가 결과에 미친 **인과효과**를 측정하는 데 있다.

## 2. 랜덤화가 필요한 이유

랜덤화(Randomization)는 사용자를 대조군과 실험군에 무작위로 배정하는 과정이다. 이는 A/B 테스트에서 인과관계를 추론할 수 있게 하는 핵심 원리다.

사용자가 직접 그룹을 선택하거나 운영자가 특정 고객만 실험군에 배정하면 연령, 성별, 기기, 방문 목적, 구매 성향 등의 특성이 한쪽에 치우칠 수 있다. 이 경우 결과의 차이가 실험 처치 때문인지 집단의 원래 특성 때문인지 구분하기 어렵다.

무작위 배정을 사용하면 표본 규모가 충분할 때 관찰된 특성뿐 아니라 관찰하기 어려운 특성도 두 집단에 대체로 고르게 분포한다. 따라서 두 그룹의 가장 중요한 차이를 실험 처치로 제한할 수 있다.

### 랜덤 배정 예시

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(42)

n = 20
users = pd.DataFrame({
    "user_id": np.arange(1, n + 1)
})

users["group"] = rng.choice(["A", "B"], size=n)

print(users)
```

난수 시드를 고정하면 동일한 배정 결과를 재현할 수 있다. 실제 서비스에서는 사용자 ID 등을 기준으로 한 일관된 배정 방식을 사용하여 같은 사용자가 실험 기간 동안 동일한 그룹에 머물도록 해야 한다.

## 3. 실험 단위 정의

실험 단위는 무작위 배정을 적용하는 최소 단위다.

| 실험 단위 | 설명 | 고려할 점 |
|---|---|---|
| 사용자(User) | 사용자별로 A 또는 B를 배정 | 온라인 실험에서 가장 일반적이며 경험을 일관되게 유지할 수 있음 |
| 세션(Session) | 접속 세션마다 그룹을 배정 | 같은 사용자가 세션별로 다른 조건을 경험할 수 있음 |
| 페이지뷰(Page view) | 페이지를 열 때마다 조건을 배정 | 조건 혼합과 사용자 경험의 불일치 가능성이 큼 |
| 기기(Device) | 기기별로 그룹을 배정 | 한 사용자가 여러 기기를 사용하면 서로 다른 조건에 노출될 수 있음 |

추천 시스템을 페이지뷰 단위로 배정하면 한 사용자가 오전에는 A 추천을, 오후에는 B 추천을 볼 수 있다. 이처럼 동일한 사용자가 여러 조건에 노출되면 실험군 간 오염이 발생하고 결과를 명확하게 해석하기 어렵다.

따라서 실험 단위는 서비스의 사용 방식과 실험 목적을 고려해 정해야 하며, 일반적인 온라인 서비스에서는 사용자 단위 배정이 적합한 경우가 많다.

## 4. 실험 지표 설계

실험 결과를 올바르게 판단하려면 분석 전에 측정할 지표를 명확히 정의해야 한다.

### 4.1 핵심 지표(Primary Metric)

실험의 성공 여부를 판단하는 가장 중요한 지표다. 실험 가설과 직접 연결되어야 한다.

- 예: 동영상 추천 실험의 영상 시청 완료율
- 예: 검색 결과 개선 실험의 상품 클릭률(CTR)

### 4.2 보조 지표(Secondary Metric)

핵심 지표만으로 설명하기 어려운 사용자 행동을 추가로 파악하기 위한 지표다.

- 예: 추천 영역 클릭률
- 예: 평균 시청 시간

### 4.3 가드레일 지표(Guardrail Metric)

핵심 지표가 개선되는 동안 서비스의 다른 중요한 측면이 악화되지 않았는지 확인하는 안전장치다.

- 예: 앱 이탈률
- 예: 오류율
- 예: 고객 불만 또는 취소율

추천 클릭률이 상승했더라도 실제 영상 시청으로 이어지지 않을 수 있다. 시청 완료율이 상승한 대신 앱 이탈률이 크게 높아질 수도 있다. 따라서 핵심 지표뿐 아니라 보조 지표와 가드레일 지표를 함께 확인해야 한다.

## 5. A/B 테스트의 전체 프로세스

### 5.1 가설 수립

먼저 어떤 변경이 어떤 사용자 행동을 개선할 것인지 명확하게 정의한다.

> 상품 평점을 더 눈에 띄게 표시하면 사용자가 상품을 선택하기 쉬워져 상품 클릭률이 증가할 것이다.

좋은 가설은 다음 내용을 포함한다.

- 변경할 요소
- 기대하는 사용자 행동의 변화
- 효과를 측정할 지표

### 5.2 실험 설계

가설을 검증하기 위한 조건을 사전에 결정한다.

- 대조군: 기존 검색 결과 화면
- 실험군: 상품 평점을 확대해 표시한 화면
- 실험 단위: 사용자
- 핵심 지표: 상품 클릭률
- 표본 크기: 검출하려는 효과를 고려하여 결정
- 실험 기간: 요일 효과와 사용자 행동 주기를 고려하여 사전에 확정

### 5.3 실험 실행

사용자를 무작위로 배정하고, 실험 기간 동안 동일한 사용자가 같은 조건을 경험하도록 한다. 실험 중에는 두 그룹의 표본 수와 데이터 수집 상태도 점검해야 한다.

예를 들어 사용자 1,000명을 배정한 결과가 A 그룹 491명, B 그룹 509명이라면 완전히 같은 인원은 아니지만 무작위 배정에서 발생할 수 있는 차이다.

### 5.4 결과 분석

각 그룹의 지표를 계산하고 차이의 크기와 통계적 불확실성을 함께 평가한다.

| 그룹 | 상품 클릭률 |
|---|---:|
| A 그룹 | 12.0% |
| B 그룹 | 13.4% |

두 그룹의 클릭률 차이는 `13.4% - 12.0% = 1.4%p`이다. 그러나 1.4%포인트의 차이가 관찰되었다는 사실만으로 실험군이 더 좋다고 결론 내릴 수는 없다. 표본의 우연한 변동으로도 이러한 차이가 나타날 수 있기 때문이다.

따라서 다음 사항을 함께 확인해야 한다.

- 표본 크기가 충분한가?
- 차이가 통계적으로 유의한가?
- 효과의 크기가 서비스 관점에서도 의미가 있는가?
- 가드레일 지표가 악화되지 않았는가?

분석 결과는 단순한 승패 판정이 아니라 기능 적용, 추가 실험, 실험 중단 등의 의사결정으로 연결되어야 한다.

## 6. 실험 전에 결정해야 하는 이유

가설, 핵심 지표, 표본 크기, 실험 기간은 결과를 확인하기 전에 정해야 한다.

### 지표의 사후 선택

결과를 본 뒤 유리하게 나온 지표만 선택하면 우연한 차이를 실제 효과로 잘못 판단할 가능성이 커진다. 핵심 지표를 미리 지정하면 이러한 선택 편향을 줄일 수 있다.

### 조기 종료와 반복 확인

실험 도중 결과를 반복해서 확인하다가 유의해 보이는 순간 실험을 종료하면 거짓 양성의 가능성이 증가한다. 이를 흔히 피킹(Peeking) 문제라고 한다.

이를 예방하려면 다음 원칙을 지켜야 한다.

- 필요한 표본 크기를 사전에 산정한다.
- 실험 기간과 종료 조건을 미리 정한다.
- 특별한 운영상 문제가 없다면 계획한 시점까지 실험을 유지한다.
- 결과 분석 방법도 실험 전에 정의한다.

## 7. 간섭 효과와 실험군 오염

A/B 테스트는 일반적으로 한 사용자가 받은 처치가 다른 사용자의 결과에 영향을 주지 않는다고 가정한다. 그러나 사용자 간 상호작용이 있는 서비스에서는 이 가정이 깨질 수 있다.

예를 들어 B 그룹에만 친구 초대 할인 기능을 제공했다고 하자. B 그룹 사용자가 A 그룹의 친구를 초대하면 A 그룹 사용자도 할인 혜택을 받고 주문할 수 있다. 실험군의 처치가 대조군에 영향을 준 것이다.

```python
base_rate = 0.20
true_effect = 0.05
spillover = 0.02

control_rate = base_rate + spillover
treatment_rate = base_rate + true_effect
observed_effect = treatment_rate - control_rate

print(observed_effect)  # 0.03
```

실제 처치 효과가 5%포인트여도 대조군에 2%포인트의 파급 효과가 발생하면 관찰되는 차이는 3%포인트로 축소된다. 이를 간섭 효과 또는 스필오버(Spillover)라고 한다.

### 대응 방법: 군집 단위 랜덤화

사용자들이 서로 영향을 주는 구조라면 개별 사용자가 아닌 군집 단위로 배정하는 방법을 고려할 수 있다.

- 친구 관계로 연결된 사용자 그룹
- 같은 회사나 학교에 속한 사용자
- 같은 지역 또는 매장을 이용하는 사용자

서로 영향을 주는 대상을 같은 실험 조건에 배정하면 대조군과 실험군 사이의 처치 확산을 줄일 수 있다. 다만 군집 단위 실험은 독립적인 관측 단위가 줄어들 수 있으므로 표본 크기와 분석 방법을 별도로 고려해야 한다.

## 8. 실험 설계 시 흔한 오류

| 오류 | 문제점 | 대응 방법 |
|---|---|---|
| 무작위 배정 없이 그룹 구성 | 집단 특성의 차이가 결과에 섞임 | 충분한 표본을 무작위로 배정 |
| 동일 사용자가 A와 B를 모두 경험 | 실험군 간 오염과 일관성 저하 | 사용자 단위의 고정 배정 적용 |
| 결과를 본 뒤 핵심 지표 선택 | 우연히 유리한 결과를 채택할 가능성 증가 | 가설과 핵심 지표를 사전에 정의 |
| 유의해 보이는 순간 조기 종료 | 거짓 양성 가능성 증가 | 표본 크기와 종료 조건을 사전 확정 |
| 핵심 지표만 확인 | 부작용과 장기적 손실을 놓칠 수 있음 | 보조·가드레일 지표를 함께 분석 |
| 사용자 간 간섭 무시 | 처치가 대조군에 확산되어 효과가 왜곡됨 | 간섭 구조를 파악하고 군집 랜덤화 검토 |

- [ ] 대조군과 실험군의 차이가 한 가지로 제한되어 있는가?
- [ ] 서비스 특성에 맞는 실험 단위를 선택했는가?
- [ ] 사용자를 무작위로 배정하는가?
- [ ] 동일 사용자의 그룹이 실험 기간 동안 유지되는가?
- [ ] 핵심·보조·가드레일 지표를 사전에 정의했는가?
- [ ] 필요한 표본 크기와 실험 기간을 미리 정했는가?
- [ ] 중간 결과를 보고 임의로 실험을 종료하지 않는가?
- [ ] 사용자 간 간섭이나 처치 확산 가능성을 점검했는가?
- [ ] 통계적 유의성과 실질적 중요성을 함께 평가하는가?

## 핵심 용어 정리

| 용어 | 의미 |
|---|---|
| 대조군(Control) | 기존 조건을 경험하는 비교 기준 집단 |
| 실험군(Treatment) | 새 기능이나 변경된 조건을 경험하는 집단 |
| 랜덤화(Randomization) | 실험 대상을 무작위로 그룹에 배정하는 과정 |
| 실험 단위 | 무작위 배정이 이루어지는 최소 단위 |
| 핵심 지표 | 실험의 성공 여부를 판단하는 주된 지표 |
| 가드레일 지표 | 핵심 지표 개선에 따른 부작용을 감시하는 지표 |
| 피킹(Peeking) | 실험 중 결과를 반복 확인하고 유리한 시점에 종료하는 행위 |
| 스필오버(Spillover) | 한 집단의 처치가 다른 집단의 결과에 영향을 미치는 현상 |
| 군집 랜덤화 | 서로 영향을 주는 대상을 묶어 군집 단위로 배정하는 방식 |

## 오늘의 정리

1. A/B 테스트는 두 집단의 수치를 단순 비교하는 방법이 아니라 변경 사항의 인과효과를 측정하는 통제 실험이다.
2. 랜덤화는 사용자 특성을 두 그룹에 고르게 분산하여 집단 간 차이를 실험 처치 중심으로 해석하게 해 준다.
3. 실험 단위는 조건 혼합과 사용자 경험의 일관성을 고려해 정해야 하며, 온라인 서비스에서는 사용자 단위 배정이 자주 사용된다.
4. 핵심 지표만 개선되었다고 성공으로 판단해서는 안 되며 보조 지표와 가드레일 지표를 함께 확인해야 한다.
5. 가설, 지표, 표본 크기, 실험 기간, 종료 조건을 사전에 정해야 선택 편향과 조기 종료 문제를 줄일 수 있다.
6. 사용자 간 상호작용으로 실험군의 처치가 대조군에 퍼질 수 있으므로 필요하면 군집 단위 랜덤화를 고려해야 한다.

> **한 문장 요약:** 신뢰할 수 있는 A/B 테스트는 명확한 가설을 세우고 사용자를 무작위로 일관되게 배정한 뒤, 사전에 정한 지표와 종료 기준으로 효과와 부작용을 함께 평가하는 실험이다.
