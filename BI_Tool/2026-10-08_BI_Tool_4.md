# 2026-10-08 Tableau 데이터 결합: 조인·유니온·블렌딩·관계

## 1. 데이터 구조에 따라 결합 방법이 달라진다

분석에 필요한 정보는 여러 테이블과 파일에 나뉘어 있을 수 있다. 온라인 쇼핑몰에서는 주문, 고객, 반품, 월별 파일과 광고 데이터를 함께 사용할 수 있다.

| 분석에 필요한 작업 | 결합 방식 |
|---|---|
| 주문에 고객 지역과 등급 추가 | Join |
| 동일한 구조의 월별 주문 파일 통합 | Union |
| 주문·고객·반품의 구조를 유지하며 함께 분석 | Relationship |
| 독립된 매출·광고 데이터 원본을 하나의 뷰에서 사용 | Blending |

방법을 선택하기 전에 각 데이터의 구조, 공통 필드, 한 행의 의미를 확인해야 한다. 결합이 가능하다는 것과 분석 결과가 올바르다는 것은 별개이다.

---

## 2. Join: 공통 Key로 행을 연결하기

**Join(조인)**은 연결 조건이 맞는 행을 찾아 여러 테이블의 정보를 결합한다. 주문과 고객을 고객ID로 연결하면 주문 정보 옆에 고객 지역이나 등급을 추가할 수 있다.

**Join Key**는 어떤 행끼리 연결할지 결정하는 필드이다.

| 주문ID | 고객ID | 매출 |
|---|---|---:|
| O001 | C001 | 120,000 |
| O002 | C002 | 80,000 |
| O003 | C001 | 150,000 |

고객 테이블에서 C001의 지역이 Seoul, C002의 지역이 Busan이라면 결합 결과에 해당 지역을 붙일 수 있다. 이때 C001의 고객 정보는 두 주문에 반복된다.

Join은 주로 정보를 가로로 확장하지만, Key의 중복과 결합 유형에 따라 행 수도 달라진다.

---

## 3. Join 유형과 유지할 행

| 유형 | 결과에 남기는 데이터 |
|---|---|
| Inner Join | 양쪽에서 조건이 일치하는 행 |
| Left Join | 왼쪽의 모든 행과 연결되는 오른쪽 정보 |
| Right Join | 오른쪽의 모든 행과 연결되는 왼쪽 정보 |
| Full Outer Join | 양쪽의 모든 행과 연결 가능한 정보 |

일치하지 않는 쪽의 필드는 외부 조인 결과에서 Null로 나타날 수 있다.

주문을 모두 유지하면서 고객 정보를 추가하려면 주문을 왼쪽에 둔 Left Join을 고려할 수 있다. Inner Join을 사용하면 고객 정보가 없는 주문이 제외되어 총매출이 줄어들 수 있다.

Left Join이 왼쪽의 행을 유지한다는 것은 결과 행 수가 항상 같다는 뜻이 아니다. 오른쪽에서 같은 Key가 여러 번 매칭되면 왼쪽 행도 여러 번 나타난다.

---

## 4. Granularity와 중복 집계 위험

**Granularity(세부 수준)**는 데이터 한 행이 무엇을 나타내는지 의미한다.

| 테이블 | 한 행의 단위 예시 |
|---|---|
| 고객 | 고객 1명 |
| 주문 | 주문 1건 |
| 주문 상세 | 주문에 포함된 상품 항목 1개 |

주문 1건의 매출이 100,000원이고 상세 항목이 3개라면, 주문과 상세를 Join한 결과에서 주문 매출이 세 행에 반복될 수 있다. 이를 그대로 합하면 300,000원으로 과대 집계된다.

일대다·다대다 결합에서는 다음을 확인해야 한다.

- Key가 각 테이블에서 유일한가?
- 하나의 Key에 몇 개의 행이 연결되는가?
- 결합 후 행 수와 고유 주문 수가 어떻게 달라졌는가?
- 매출과 같은 Measure가 반복되었는가?

Join의 핵심은 컬럼 추가가 아니라 **분석 단위가 의도대로 유지되는지 확인하는 것**이다.

---

## 5. Union: 같은 구조의 데이터를 아래로 쌓기

**Union(유니온)**은 동일하거나 호환되는 컬럼 구조의 데이터를 세로로 이어 붙여 행을 추가하는 방법이다.

1월과 2월 주문 파일이 주문ID, 고객ID, 매출이라는 같은 구조라면 하나의 주문 데이터로 통합할 수 있다.

| 구분 | Join | Union |
|---|---|---|
| 결합 기준 | 공통 Key와 연결 조건 | 호환되는 컬럼 구조 |
| 방향 | 가로 | 세로 |
| 주요 변화 | 관련 정보 추가 | 관측치 추가 |
| 예시 | 주문과 고객 | 월별 주문 파일 |

Union 전에는 컬럼 이름, 자료형, 단위가 일치하는지 확인한다. 같은 매출 컬럼이라도 파일마다 금액 단위가 다르면 그대로 합쳐서는 안 된다.

파일 간 기간이 겹치면 같은 주문이 중복으로 들어올 수 있다. Tableau의 Union이 중복 관측치를 자동으로 제거한다고 생각하면 안 된다.

### Wildcard Union

일정한 이름 규칙을 가진 여러 파일이나 테이블은 Wildcard Union으로 한 번에 연결할 수 있다. 포함할 이름 패턴을 잘못 지정하면 불필요한 파일이 함께 들어갈 수 있으므로 대상 범위를 확인한다.

---

## 6. Relationship: 테이블을 논리적으로 연결하기

**Relationship(관계)**은 테이블을 하나로 미리 병합하지 않고 공통 필드로 연결 관계를 정의하는 방식이다.

예를 들어 주문과 고객은 고객ID, 주문과 반품은 주문ID로 연결할 수 있다. 각 테이블은 논리 테이블로 유지되고, Tableau는 뷰에서 사용한 필드에 따라 필요한 쿼리를 구성한다.

| 계층 | 역할 |
|---|---|
| Logical Layer | 논리 테이블 사이의 Relationship 구성 |
| Physical Layer | 논리 테이블 내부의 Join과 Union 구성 |

각 테이블의 원래 세부 수준을 가능한 한 유지하며 분석할 수 있도록 지원하는 것이 Relationship의 중요한 특징이다.

다만 관계를 사용한다고 잘못된 Key나 데이터 중복이 자동으로 해결되는 것은 아니다. 연결 기준과 집계 결과를 확인해야 한다.

---

## 7. Relationship과 Join 비교

| 관점 | Relationship | Join |
|---|---|---|
| 구성 위치 | Logical Layer | Physical Layer |
| 결합 방식 | 테이블 간 연결 관계 정의 | 행 수준의 병합 구조 정의 |
| 세부 수준 | 논리 테이블의 단위를 유지하며 분석 지원 | 결합된 행 구조에 따라 집계 |
| Join 유형 | 하나의 유형을 미리 고정하지 않음 | Inner, Left 등 명시 |
| 적합한 상황 | 여러 테이블의 구조를 유지하며 분석 | 행 수준의 명시적 결합이 필요 |

여러 테이블의 구조와 세부 수준을 유지하고 싶다면 Relationship을 먼저 고려할 수 있다. 특정 조인 유형이나 하나의 결합된 행 구조가 필요하면 Join을 선택한다.

관계 설정에서도 연결 필드의 자료형이 맞는지 확인한다. Cardinality는 일대일·일대다·다대다 등의 대응 관계이며, Referential Integrity는 연결 값의 참조 무결성과 관련된다.

이 정보가 확실하지 않다면 임의로 지정하지 않고 기본 설정을 활용한다. 잘못된 가정은 결과에 영향을 줄 수 있다.

---

## 8. Blending: 서로 다른 데이터 원본의 결과 연결

**Blending(블렌딩)**은 독립된 Tableau 데이터 원본을 유지하면서 하나의 뷰에서 결과를 함께 사용하는 방식이다.

매출은 데이터베이스에 있고 광고비는 Excel에 있다고 가정하자. 두 데이터를 각각 별도의 Tableau 데이터 원본으로 구성한 상태에서 날짜별 매출과 광고비를 비교할 때 Blending을 활용할 수 있다.

| 개념 | 의미 |
|---|---|
| Primary Data Source | 뷰의 기준이 되는 주 데이터 원본 |
| Secondary Data Source | 연결해서 사용하는 보조 데이터 원본 |
| Linking Field | 두 원본을 연결하는 공통 필드 |

뷰에서 먼저 사용한 원본이 일반적으로 주 원본이 된다. 보조 원본의 값은 Linking Field에 맞는 수준으로 집계되어 주 원본의 결과와 결합된다.

따라서 Blending은 원본 행들을 하나의 테이블로 합치는 Join과 다르다. 날짜별 광고비를 여러 주문에 붙여 중복 합산하는 상황과도 구분해야 한다.

---

## 9. Relationship과 Blending의 차이

| 관점 | Relationship | Blending |
|---|---|---|
| 연결 대상 | 하나의 Tableau 데이터 원본 안의 논리 테이블 | 서로 다른 Tableau 데이터 원본 |
| 연결 기준 | 관계 필드 | Linking Field |
| 데이터 활용 | 필요한 테이블로 쿼리 구성 | 원본별 결과를 뷰에서 결합 |
| 활용 목적 | 여러 테이블의 구조와 단위를 유지하며 분석 | 독립된 원본을 한 시각화에서 사용 |

둘 다 하나의 테이블로 미리 병합하지 않는다는 점은 비슷하지만, 연결 대상과 동작 수준이 다르다.

파일과 데이터베이스라는 저장 위치만으로 Blending을 선택하는 것은 아니다. **별도의 Tableau 데이터 원본으로 유지하면서 함께 분석할 것인지**가 중요한 판단 기준이다.

## 10. 결합 방법 선택과 결과 검증

| 필요한 작업 | 우선 고려할 방법 |
|---|---|
| 같은 구조의 데이터를 더 쌓기 | Union |
| Key로 행 수준의 정보를 명시적으로 연결 | Join |
| 테이블별 구조를 유지하며 하나의 데이터 원본에서 분석 | Relationship |
| 독립된 데이터 원본의 결과를 뷰에서 연결 | Blending |

결합 후에는 연결이 성공했는지뿐 아니라 숫자가 올바른지 검증한다.

1. 각 데이터의 행 단위를 확인한다.
2. Key의 자료형, 유일성과 누락을 확인한다.
3. 유지할 행과 분석 목적에 맞는 방식을 선택한다.
4. 결합 전후 행 수와 고유 식별자 수를 비교한다.
5. 주요 Measure의 합계와 반복 여부를 확인한다.
6. 날짜의 집계 수준과 원본별 기간을 맞춘다.

서로 다른 단위의 데이터를 연결할수록 검증이 중요하다.

## 11. 복잡한 데이터 준비와 Tableau Prep

결합 전에 데이터 정제와 구조 변경이 필요한 경우가 있다. 파일마다 컬럼 이름이나 자료형이 다르거나 여러 단계의 정리가 필요하면 분석용 데이터를 준비하는 과정부터 구성해야 한다.

Tableau Prep Builder는 이러한 데이터 준비 작업을 위한 도구로 활용할 수 있다. 시각화를 구성하기 전에 입력 데이터의 형태와 의미를 맞추는 것이 목적이다.

준비 단계와 분석 단계는 연결된다. 정제와 결합이 올바르지 않으면 차트를 잘 만들어도 잘못된 숫자를 전달할 수 있다.

## 12. 핵심 정리

- Join은 공통 Key로 관련 행의 정보를 연결한다.
- 조인 유형에 따라 유지되는 행이 달라진다.
- Key의 중복으로 행과 Measure가 반복될 수 있으므로 세부 수준을 확인한다.
- Union은 호환되는 구조의 데이터를 세로로 이어 붙인다.
- Relationship은 논리 테이블을 유지하며 연결 관계를 정의한다.
- Logical Layer에서는 관계를, Physical Layer에서는 Join과 Union을 구성한다.
- Blending은 독립된 Tableau 데이터 원본의 결과를 뷰에서 연결한다.
- Relationship과 Blending은 연결 대상과 데이터 활용 방식이 다르다.
- 방법 선택은 데이터 구조, 행 단위와 분석 목적을 기준으로 한다.
- 결합 전후의 행 수, 누락, 중복과 집계값을 검증해야 한다.

## 오늘의 한 문장

> 데이터 결합은 테이블을 붙이는 작업을 넘어, 각 데이터의 단위와 연결 기준을 이해하고 집계 결과가 분석 목적에 맞게 유지되는지 확인하는 과정이다.
