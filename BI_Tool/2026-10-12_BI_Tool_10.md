# 2026-10-12 Tableau 대시보드 액션으로 인터랙션 구현

## 1. 사용자 선택에 반응하는 대시보드

**Dashboard Action**은 사용자가 차트의 마크를 선택하거나 마우스를 올리는 행동에 따라 다른 요소가 반응하도록 만드는 기능이다.

지역별 매출 차트에서 부산 막대를 선택하면 다른 차트가 부산의 카테고리별 매출과 월별 추세를 보여주도록 구성할 수 있다. 사용자는 여러 필터를 따로 조작하지 않고 관심 항목을 직접 탐색한다.

같은 선택이라도 목적에 따라 필요한 반응은 다르다. 선택한 데이터만 남기거나, 전체 속에서 강조하거나, 상세 화면으로 이동할 수 있다.

---

## 2. Action의 기본 구조

| 요소 | 확인할 질문 | 예시 |
|---|---|---|
| Source | 어디에서 행동하는가? | 지역별 매출 워크시트 |
| Run Action On | 어떤 행동으로 실행하는가? | 부산 마크 선택 |
| Target | 무엇이 반응하는가? | 카테고리별 매출 워크시트 |
| 변경 내용 | 어떤 결과를 만들 것인가? | 부산 데이터만 표시 |

Action 종류에 따라 대상은 워크시트뿐 아니라 파라미터나 외부 URL이 될 수 있다.

설계할 때는 출발 차트와 대상 차트를 연결하는 것에 더해, 어떤 필드의 값을 전달할지도 확인한다. 지역을 선택했는데 상품ID 등의 다른 필드로 연결되면 원하는 결과가 나오지 않을 수 있다.

---

## 3. 실행 조건: Hover, Select, Menu

| 조건 | 동작 | 활용 목적 |
|---|---|---|
| Hover | 마크 위에 마우스를 올리면 실행 | 항목을 빠르게 훑어보기 |
| Select | 마크를 선택하면 실행 | 관심 항목을 유지하며 상세 분석 |
| Menu | 메뉴에서 Action을 선택하면 실행 | 외부 페이지 열기 등 명시적인 동작 |

Hover는 빠르지만 마우스 이동만으로 결과가 바뀔 수 있다. 자세히 살펴볼 상태를 유지해야 한다면 Select가 적합할 수 있다.

외부 페이지를 열거나 화면을 이동하는 기능은 사용자가 예상하고 실행할 수 있어야 한다. 실행 조건은 지원되는 Action의 설정과 사용 목적에 맞게 선택한다.

---

## 4. Filter Action: 선택한 데이터에 집중

Filter Action은 선택한 항목의 값을 조건으로 전달하여 대상 뷰의 데이터를 제한한다.

부산을 선택하면 상품별 매출 차트와 월별 추세에서 부산 데이터만 표시하도록 만들 수 있다.

| 항목 | 설정 예시 |
|---|---|
| Source | 지역별 매출 |
| 실행 | Select |
| Target | 상품별 매출, 월별 추세 |
| 연결 기준 | 지역 |
| 결과 | 선택 지역의 상세 데이터 표시 |

전체 데이터와 비교해야 하는 차트까지 필터링하면 비교 기준이 사라질 수 있다. 집중 분석할 대상과 전체 기준을 유지할 대상을 구분해야 한다.

---

## 5. Highlight Action: 전체를 유지하며 강조

Highlight Action은 데이터를 제외하는 대신 관련 항목을 강조한다. 선택하지 않은 항목도 남아 있으므로 전체 속에서 관심 항목의 위치를 비교할 수 있다.

| 관점 | Filter Action | Highlight Action |
|---|---|---|
| 목적 | 선택한 데이터에 집중 | 전체 속에서 선택 항목 강조 |
| 선택하지 않은 데이터 | 대상 뷰에서 제외 | 유지하되 상대적으로 약하게 표현 |
| 예시 | 부산 상품 매출만 표시 | 전국 추세에서 부산 강조 |

상세 분석에는 Filter, 전체 비교에는 Highlight를 고려한다. 같은 선택이 여러 차트에 서로 다른 반응을 줄 수도 있지만 사용자가 그 차이를 이해할 수 있어야 한다.

---

## 6. URL Action: 외부 정보 연결

URL Action은 선택한 항목과 관련된 외부 웹페이지를 여는 기능이다.

상품별 매출 차트에서 상품을 선택하면 상품 관리 페이지나 재고 현황 페이지를 확인하도록 구성할 수 있다. 상품ID 등을 URL에 전달하면 항목별 상세 페이지로 연결할 수 있다.

외부 페이지의 용도와 연결되는 항목이 명확해야 한다. 내부 차트를 탐색하려는 선택이 예상치 못한 외부 페이지 열기로 이어지지 않도록 실행 조건을 설계한다.

---

## 7. Parameter Action: 선택값을 계산 기준으로 전달

Parameter Action은 마크에서 선택한 값을 파라미터에 전달한다.

부산을 선택하여 [비교 기준 지역]의 값을 부산으로 바꾸고, 연결된 계산식에서 다른 지역과 비교하도록 구성할 수 있다.

1. 사용자가 지역 마크를 선택한다.
2. 해당 지역값이 파라미터에 전달된다.
3. 계산식이 변경된 값을 사용한다.
4. 비교 결과가 뷰에 반영된다.

Parameter Action 자체는 직접 데이터를 필터링하는 기능이 아니다. 실제 변화를 만들려면 파라미터를 참조하는 계산식이나 필터가 필요하다.

전달할 필드와 파라미터의 자료형, 여러 마크를 선택했을 때의 값 처리도 확인한다.

---

## 8. Navigation: 화면 이동과 조건 전달 구분

Go to Sheet 등의 이동 Action은 다른 워크시트, 대시보드 또는 스토리로 탐색을 이어가게 한다. 별도의 이동 버튼은 Navigation 객체로 제공할 수 있다.

그러나 **화면을 이동하는 것과 선택한 데이터만 표시하는 것은 서로 다른 동작**이다.

부산을 선택한 뒤 부산 상세 대시보드를 보고 싶다면 두 요구가 모두 충족되어야 한다.

| 요구 | 활용 기능 |
|---|---|
| 상세 화면으로 이동 | Navigation / Go to Sheet |
| 부산 데이터만 표시 | 선택값을 전달하는 Filter Action 등 |

화면만 이동하면 상세 화면에 전체 데이터가 표시될 수 있다. 제목과 데이터 범위가 선택한 항목과 일치하는지 확인해야 한다.

---

## 9. 선택 해제 후 동작도 설계하기

Filter Action에서는 선택 해제 후 동작을 정할 수 있다.

| 설정 | 결과 |
|---|---|
| Show All Values | 대상 차트에 전체 데이터 표시 |
| Exclude All Values | 대상 차트에 데이터를 표시하지 않음 |
| Leave the Filter | 마지막 필터 상태 유지 |

전체 현황에서 자유롭게 탐색하는 대시보드는 선택 해제 시 전체로 돌아가는 것이 자연스러울 수 있다. 반면 항목을 선택해야만 상세 정보를 보여주는 화면은 빈 상태를 활용할 수 있다.

상태를 유지한다면 사용자가 현재 어떤 조건을 보고 있는지 알아야 한다. 선택 표시가 사라졌는데 데이터가 계속 제한되면 전체 데이터로 오해할 수 있다.

---

## 10. Hierarchy와 Drill-down

**Drill-down**은 요약된 정보에서 더 세부적인 수준으로 내려가며 탐색하는 방식이다. **Hierarchy**는 Dimension을 상위·하위 수준으로 구성한 구조이다.

상품 분석에서는 카테고리, 하위 카테고리, 상품을 계층으로 구성할 수 있다.

| 방식 | Hierarchy | Action 기반 Drill-down |
|---|---|---|
| 탐색 구조 | 같은 차트에서 상세 수준 확장 | 다른 차트나 화면 연결 |
| 화면 구성 | 기존 차트 중심 | 요약과 상세 화면을 다르게 구성 |
| 활용 | 카테고리에서 상품까지 단계적으로 보기 | 지역 요약에서 여러 상세 지표 확인 |

Hierarchy의 Expand / Collapse로 세부 수준을 펼치거나 접을 수 있다. 계층을 펼친다고 선택한 카테고리만 자동으로 남는 것은 아니다. 특정 카테고리에 집중하려면 별도의 필터가 필요할 수 있다.

Drill-down은 분석 방식이고, Hierarchy와 Action은 이를 구현하는 방법이다.

---

## 11. 사용자 탐색 흐름에 맞게 조합하기

클릭 가능한 기능이 많다고 좋은 대시보드는 아니다. 한 번의 선택으로 필터링, 강조, 이동과 기준 변경이 동시에 발생하면 결과의 원인을 이해하기 어려울 수 있다.

먼저 사용자가 따라갈 질문을 정한다.

1. 전체에서 어느 지역의 성과가 눈에 띄는가?
2. 그 지역은 어떤 상품에서 매출이 발생하는가?
3. 해당 상품의 이익과 추세는 어떠한가?
4. 추가 업무 정보가 필요한가?

각 질문에 필요한 반응만 연결한다. 현재 선택 지역, 분석 범위와 상세 수준을 표시하고, 상위 화면으로 돌아가는 방법도 제공한다.

## 12. 인터랙션 결과 검증

| 확인 항목 | 점검 내용 |
|---|---|
| 실행 조건 | 선택·호버·메뉴가 의도한 동작인가? |
| 전달 값 | 선택한 지역이나 상품이 정확히 전달되는가? |
| 대상 범위 | 필요한 차트만 바뀌는가? |
| 비교 기준 | 전체와 비교할 차트가 유지되는가? |
| 선택 해제 | 전체 복귀·빈 상태·유지 설정이 맞는가? |
| 화면 이동 | 선택한 조건도 함께 반영되는가? |
| 탐색 복귀 | 상위 화면으로 돌아올 수 있는가? |

Action을 각각 테스트한 뒤 함께 사용할 때도 점검한다. 차트가 반응하는지만 보는 것이 아니라 사용자의 분석 질문에 맞는 결과가 나타나는지 확인해야 한다.

---

## 13. 핵심 정리

- Dashboard Action은 사용자 행동을 다른 요소의 반응에 연결한다.
- Source, 실행 조건, Target과 전달할 값을 정의한다.
- Filter는 데이터 범위를 제한하고 Highlight는 전체를 유지하며 강조한다.
- URL은 외부 정보, Parameter는 계산 기준값, Navigation은 화면 이동에 활용한다.
- Parameter Action은 파라미터에 값을 전달하며 별도의 계산 연결이 필요하다.
- 화면 이동과 선택값의 데이터 필터링은 구분하여 구성한다.
- 선택 해제와 현재 탐색 상태도 인터랙션의 일부이다.
- Hierarchy는 같은 차트의 수준을 펼치고, Action은 다른 차트나 화면을 연결한다.
- 기능의 수보다 사용자의 질문과 탐색 흐름에 맞는 반응이 중요하다.
