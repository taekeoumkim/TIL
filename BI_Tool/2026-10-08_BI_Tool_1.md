# 2026-10-08 데이터 시각화 개론과 BI 도구

## 1. 데이터 시각화는 왜 필요할까?

**데이터 시각화(Data Visualization)**는 숫자와 텍스트로 된 데이터를 막대, 선, 점과 같은 시각적 형태로 표현하여 이해를 돕는 방법이다.

표에서 숫자를 하나씩 읽는 대신 길이, 위치, 색을 비교하면 패턴과 차이를 빠르게 파악할 수 있다. 월별 매출의 증감이나 카테고리별 판매량의 차이는 적절한 차트로 표현할 때 전체 흐름이 잘 드러난다.

데이터 분석의 결과는 의사결정자가 이해하고 다음 행동을 판단할 수 있도록 전달해야 한다. 시각화는 분석 결과를 이러한 판단의 근거로 연결하는 수단이다.

차트가 항상 표보다 좋은 것은 아니다. 목적에 따라 선택해야 한다.

| 표현 방식 | 적합한 목적 |
|---|---|
| 표 | 정확한 값 확인, 세부 항목 조회 |
| 차트 | 패턴, 차이, 추세, 관계 파악 |

필요하면 핵심 경향은 차트로 보여주고 정확한 값은 레이블이나 표로 함께 제공할 수 있다.

---

## 2. 탐색적 시각화와 설명적 시각화

시각화의 목적은 크게 두 가지로 구분할 수 있다.

| 구분 | 탐색적 시각화 | 설명적 시각화 |
|---|---|---|
| 영어 | Exploratory | Explanatory |
| 목적 | 데이터를 살펴보고 패턴과 이상치 발견 | 발견한 결과와 메시지를 전달 |
| 사용 시점 | 분석 과정 | 보고와 의사결정 과정 |
| 중심 질문 | 어떤 일이 발생하고 있는가? | 무엇을 이해하고 판단해야 하는가? |

탐색 단계에서는 여러 차트를 만들어 관점을 바꾸며 살펴볼 수 있다. 설명 단계에서는 전달할 핵심을 정하고 불필요한 정보를 줄여야 한다.

분석 과정에서 만든 차트를 그대로 보고에 사용하기보다, 청중과 전달 목적에 맞게 다시 구성하는 것이 중요하다.

---

## 3. 다섯 가지 분석 목적과 차트 유형

차트는 보기 좋은 형태를 먼저 고르는 것이 아니라, 데이터로 답하려는 질문에 맞게 선택한다.

| 분석 목적 | 핵심 질문 | 대표 차트 |
|---|---|---|
| 비교(Comparison) | 어떤 항목이 더 크거나 작은가? | 막대 차트 |
| 구성(Composition) | 전체에서 각 부분이 차지하는 비중은? | 파이 차트, 누적 막대, 트리맵 |
| 분포(Distribution) | 값이 어떻게 퍼져 있는가? | 히스토그램, 박스플롯 |
| 관계(Relationship) | 두 변수는 어떤 관련이 있는가? | 산점도, 버블 차트 |
| 추세(Trend) | 시간에 따라 어떻게 변하는가? | 라인 차트, 영역 차트 |

하나의 차트가 여러 목적을 표현할 수도 있다. 예를 들어 누적 막대는 전체 크기와 내부 구성을 함께 보여준다. 다만 무엇을 가장 명확하게 전달해야 하는지 먼저 정해야 한다.

---

## 4. 목적별 차트의 특징

### 비교: 막대 길이로 크기 판단하기

막대 차트는 항목별 수치를 같은 기준선에서 비교할 때 유용하다. 카테고리 간 크기 차이와 순위를 빠르게 확인할 수 있다.

항목 이름이 길면 가로 막대를 사용하고, 순위가 중요하면 값에 따라 정렬하는 방식이 이해를 돕는다. 막대 길이가 수치를 나타내므로 기준선을 잘못 설정하면 차이가 과장될 수 있다.

### 구성: 전체와 부분의 비율 표현하기

파이 차트는 하나의 전체를 구성하는 비중을 표현한다. 항목이 많거나 비율이 비슷하면 각도와 면적의 차이를 비교하기 어려워질 수 있다.

여러 집단의 구성비를 비교할 때는 100% 누적 막대를 고려할 수 있다. 절대 크기까지 중요하면 일반 누적 막대와 구분해야 한다.

구성비를 해석할 때는 무엇을 전체로 삼았는지 분모를 명확하게 표시한다.

### 분포: 평균만으로 보이지 않는 구조 확인하기

히스토그램은 값을 구간으로 나누어 빈도를 표시한다. 어디에 값이 집중되는지, 치우침이나 여러 봉우리가 있는지 확인할 수 있다. 구간 설정에 따라 보이는 형태가 달라질 수 있다.

박스플롯은 중앙값과 사분위 범위 등을 요약하여 여러 집단의 분포를 비교하는 데 유용하다. 평균이 같더라도 퍼짐의 정도는 다를 수 있다.

### 관계: 점의 패턴으로 변수 간 관련 확인하기

산점도는 두 수치형 변수의 값을 가로축과 세로축 위치로 표시한다. 함께 증가하거나 감소하는 패턴, 비선형 관계, 이상치를 살펴볼 수 있다.

버블 차트는 점의 크기로 추가적인 수치 정보를 표현할 수 있다. 다만 크기까지 해석해야 하므로 복잡성이 높아질 수 있다.

산점도에서 관계가 보여도 한 변수가 다른 변수의 원인이라고 바로 결론 내릴 수는 없다.

### 추세: 시간 순서의 변화 표현하기

라인 차트는 시간 순서에 따라 값을 연결하여 변화와 흐름을 보여준다. 증가·감소, 반복 패턴과 변화 시점을 확인하는 데 적합하다.

영역 차트는 선 아래 면적을 채워 크기와 변화의 흐름을 강조할 수 있다. 여러 영역이 겹치면 읽기 어려울 수 있으므로 전달 목적을 고려한다.

## 5. 차트 선택 프레임워크

### 1단계: 비즈니스 질문을 한 문장으로 정한다

어떤 데이터를 갖고 있는지뿐 아니라 무엇을 알고 싶은지 명확하게 작성한다.

예를 들어 “고객 데이터를 시각화한다”보다 “신규 고객과 기존 고객의 주문 금액 분포가 어떻게 다른가?”가 구체적이다.

### 2단계: 분석 목적을 분류한다

질문이 비교·구성·분포·관계·추세 중 어떤 목적에 해당하는지 판단한다. 위 질문은 주문 금액이 어떻게 퍼져 있는지 집단별로 확인하므로 분포 목적이다.

### 3단계: 차트와 선택 근거를 정한다

여러 집단의 중앙값과 퍼짐을 비교하기 위해 박스플롯을 선택할 수 있다. 분포의 세부적인 형태가 중요하다면 다른 분포 차트도 함께 고려한다.

핵심은 **왜 이 차트가 질문에 답하기 적합한지 설명할 수 있는가**이다.

차트 후보가 여러 개라면 청중이 가장 빠르고 정확하게 이해할 수 있는 것을 선택한다. 차트 선택에는 데이터의 항목 수, 비교 대상, 전달할 메시지도 영향을 준다.

## 6. 좋은 시각화의 기준은 명확함이다

장식이 많다고 정보 전달력이 높아지는 것은 아니다. 불필요한 요소를 덜어내고 핵심 데이터에 시선이 모이도록 설계해야 한다.

| 원칙 | 적용 방법 |
|---|---|
| 불필요한 요소 제거 | 3D 효과, 짙은 배경, 과도한 격자선 줄이기 |
| 핵심 데이터 강조 | 중요한 항목만 진한 색으로 표시 |
| 명확한 레이블 | 범례를 반복 확인하지 않도록 필요한 값에 직접 표시 |
| 색의 일관성 | 같은 의미에 같은 색을 사용 |
| 읽기 쉬운 맥락 | 제목, 기간, 단위와 비교 기준을 명확히 표시 |

정보 전달에 기여하지 않는 장식을 **차트 정크(Chart Junk)**라고 한다. 불필요한 요소는 데이터와 메시지를 가릴 수 있다.

모든 항목을 서로 다른 진한 색으로 표현하면 핵심이 드러나기 어렵다. 중요한 하나를 강조하고 나머지는 중립적인 색으로 표현하는 방식이 효과적일 수 있다.

## 7. 데이터로 이야기를 전달하기

설명적 시각화는 차트 자체보다 전달할 메시지가 중심이다. 청중이 확인해야 할 결과와 그 의미가 자연스럽게 이어져야 한다.

- 어떤 질문을 다루는가?
- 데이터에서 어떤 결과를 확인했는가?
- 중요한 항목은 무엇인가?
- 그 결과가 어떤 판단에 도움이 되는가?

단순히 “월별 매출”이라는 제목을 쓰는 것보다, 근거가 충분하다면 변화의 핵심을 드러내는 제목을 사용할 수 있다. 다만 데이터가 뒷받침하지 않는 원인이나 결론을 제목으로 단정해서는 안 된다.

색과 굵기, 레이블은 메시지를 돕는 수단이다. 무엇을 강조할지 먼저 정한 뒤 표현을 선택해야 한다.

## 8. BI 도구의 역할

**BI(Business Intelligence) 도구**는 여러 데이터에 연결하여 분석하고, 시각화와 대시보드를 만들어 공유하는 소프트웨어이다.

드래그 앤 드롭과 같은 인터페이스로 시각적 탐색을 반복하고, 조직이 공통된 지표를 확인하는 데 활용할 수 있다.

| 기능 | 활용 목적 |
|---|---|
| 데이터 연결 | 여러 곳에 있는 데이터를 분석에 활용 |
| 시각적 탐색 | 항목과 조건을 바꾸며 패턴 확인 |
| 대시보드 구성 | 중요한 지표와 차트를 한 화면에 정리 |
| 공유 | 분석 결과를 다른 사람의 판단에 연결 |

BI 도구가 데이터 정의와 해석까지 자동으로 대신하는 것은 아니다. 지표의 의미, 집계 기준, 차트 선택과 결과 해석은 사용자가 이해해야 한다.

## 9. Tableau와 Power BI의 특징

두 도구는 모두 데이터 분석과 시각화, 공유에 활용할 수 있지만 학습과 활용에서 중점을 두는 부분이 다르다.

| 관점 | Tableau | Power BI |
|---|---|---|
| 주요 특징 | 시각적 탐색과 표현의 자유도 | Excel, Azure 등 Microsoft 생태계와의 연결 |
| 학습할 요소 | 드래그 앤 드롭 기반 탐색과 시각화 구성 | 시각화 구성과 DAX 등 수식 언어 |
| 활용 맥락 | 시각적 분석과 대시보드 표현을 중시하는 작업 | Microsoft 도구와 연결된 분석 환경 |
| 공유 방식 예시 | Tableau Public, Tableau Cloud 등 | Power BI Service 등 |

이 비교는 도구의 특징을 이해하기 위한 것이며 사용 조직을 배타적으로 나누는 기준은 아니다. 어떤 도구를 사용하든 질문을 정의하고 적절한 시각화로 전달하는 능력이 필요하다.

BI 역량을 정리할 때는 도구를 사용할 수 있다는 사실에 더해, 어떤 질문에 답했고 어떤 지표와 차트를 선택했는지 설명할 수 있어야 한다.

## 10. 핵심 정리

- 데이터 시각화는 숫자를 시각적 형태로 바꾸어 빠른 이해를 돕는다.
- 표는 정확한 값 확인에, 차트는 패턴과 비교에 유용하다.
- 탐색적 시각화는 발견을, 설명적 시각화는 전달을 목적으로 한다.
- 차트는 비교·구성·분포·관계·추세라는 분석 목적에 맞게 선택한다.
- 질문을 정의하고 목적을 분류한 뒤 차트와 선택 근거를 정한다.
- 차트 후보가 여러 개라면 청중이 이해하기 쉬운 표현을 선택한다.
- 좋은 시각화는 장식보다 명확한 메시지와 정확한 표현을 우선한다.
- 불필요한 요소를 줄이고 핵심 데이터에 색과 레이블을 집중한다.
- BI 도구는 데이터 연결, 분석, 대시보드와 공유를 지원한다.
- Tableau와 Power BI의 특징을 이해하되, 도구 활용을 질문과 의사결정에 연결해야 한다.

## 오늘의 한 문장

> 좋은 데이터 시각화는 보기 좋은 차트를 만드는 것이 아니라, 비즈니스 질문에 맞는 표현으로 데이터를 이해시키고 다음 판단을 돕는 것이다.
