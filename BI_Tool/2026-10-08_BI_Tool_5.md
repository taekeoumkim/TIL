# 2026-10-08 Tableau 계산된 필드 기초: 논리·집계 함수

## 1. 계산된 필드로 새로운 지표 만들기

**Calculated Field(계산된 필드)**는 기존 필드와 함수를 이용하여 분석에 필요한 값을 정의하는 사용자 지정 필드이다.

매출과 비용은 있지만 이익 필드가 없다면 다음처럼 계산할 수 있다.

```text
[매출] - [비용]
```

Tableau 계산식에서는 대괄호로 필드를 참조한다. 만든 필드는 다른 필드처럼 차트, 필터와 색상 등에 활용할 수 있다. 원본 파일이나 데이터베이스에 새 컬럼을 직접 추가하는 작업과는 다르다.

| 필요한 지표 | 계산 예시 |
|---|---|
| 이익 | [매출] - [비용] |
| 할인 후 금액 | [매출] * (1 - [할인율]) |
| 주문당 수량 | SUM([수량]) / COUNTD([주문ID]) |
| 전체 전환율 | SUM([구매수]) / SUM([방문수]) |

계산식을 작성하기 전에 **지표의 의미, 단위와 계산 수준**을 정해야 한다. 할인율이 0.1인지 10인지와 같은 저장 방식도 확인한다.

## 2. IF와 ELSEIF: 조건에 따른 분기

IF는 조건을 확인하여 해당 결과를 반환한다. 여러 조건이 필요하면 ELSEIF를 사용한다.

```text
IF [매출] >= 1000000 THEN '우수'
ELSEIF [매출] >= 500000 THEN '보통'
ELSE '관리필요'
END
```

조건은 위에서부터 확인한다. 먼저 만족하는 조건의 결과를 반환하므로 큰 금액 조건부터 작성했다. 50만 원 조건을 먼저 쓰면 100만 원 이상도 그 조건에 포함될 수 있다.

| 매출 범위 | 반환값 |
|---|---|
| 100만 원 이상 | 우수 |
| 50만 원 이상, 100만 원 미만 | 보통 |
| 50만 원 미만 | 관리필요 |

위 계산은 행 수준의 매출을 기준으로 한다. 한 고객이 여러 주문을 가진 데이터에서 고객별 전체 구매 금액으로 등급을 정하려면, 먼저 고객 단위의 집계가 필요하다. 행별 분류와 고객별 분류를 혼동하면 안 된다.

## 3. CASE와 IIF

### CASE: 특정 값과의 일치 여부로 분류

하나의 표현식 결과를 여러 값과 비교할 때 CASE를 사용할 수 있다.

```text
CASE [등급]
WHEN 'A' THEN '핵심고객'
WHEN 'B' THEN '일반고객'
ELSE '기타고객'
END
```

기존 코드값을 새로운 이름으로 바꾸는 경우에 적합하다. 매출이 일정 금액 이상인지와 같은 범위 조건은 IF로 표현하는 것이 자연스럽다.

### IIF: 하나의 조건을 간단하게 표현

```text
IIF([매출] >= 1000000, '우수', '일반')
```

조건이 참이면 첫 번째 결과를, 거짓이면 두 번째 결과를 반환한다. 조건에 Null이 포함될 수 있다면 결과 처리도 별도로 고려해야 한다.

| 함수 | 적합한 상황 |
|---|---|
| IF / ELSEIF | 범위 조건 또는 여러 조건의 순차적인 분기 |
| CASE | 하나의 값과 여러 후보의 일치 비교 |
| IIF | 간단한 참·거짓 분기 |

## 4. 집계 함수: 여러 행을 하나의 값으로 요약

| 함수 | 역할 | 활용 예시 |
|---|---|---|
| SUM | 합계 | 총매출 |
| AVG | 평균 | 행별 매출의 평균 |
| MIN | 최솟값 | 가장 작은 매출 |
| MAX | 최댓값 | 가장 큰 매출 |
| COUNT | Null이 아닌 값의 개수 | 값이 기록된 주문ID 수 |
| COUNTD | Null을 제외한 고유값 개수 | 고유 주문 수, 고유 고객 수 |

COUNT와 COUNTD는 서로 다르다. 주문ID가 여러 행에 반복되면 COUNT는 반복된 값도 세고, COUNTD는 고유한 주문ID를 센다.

집계가 수행되는 범위는 뷰의 Dimension과 적용된 필터 등에 따라 달라진다. region으로 나누었다면 지역별로, 날짜로 나누었다면 해당 날짜 수준별로 계산된다.

AVG([매출])도 한 행이 주문인지 상품 항목인지에 따라 의미가 달라진다. 평균을 계산하기 전에 행의 단위를 확인해야 한다.

## 5. 전체 전환율과 행별 비율은 다르다

| 날짜 | 방문수 | 구매수 | 행별 전환율 |
|---|---:|---:|---:|
| 10/01 | 100 | 10 | 10% |
| 10/02 | 200 | 30 | 15% |
| 10/03 | 300 | 60 | 20% |

행별 전환율은 다음 계산이다.

```text
[구매수] / [방문수]
```

전체 전환율은 전체 구매수와 전체 방문수를 각각 합한 뒤 나눈다.

```text
SUM([구매수]) / SUM([방문수])
```

$$
\text{전체 전환율}=\frac{10+30+60}{100+200+300}
=\frac{100}{600}\approx16.67\%
$$

행별 전환율의 단순 평균은 15%로 서로 다르다. 단순 평균은 각 날짜를 같은 비중으로 보지만, 전체 비율은 방문수가 많은 날짜의 영향을 더 크게 반영한다.

**전체 비율을 구할 때는 지표 정의에 맞게 분자와 분모를 집계해야 한다.** 방문과 구매의 기간, 대상과 단위도 일치해야 한다.

## 6. 객단가와 주문당 수량

객단가를 주문 1건당 평균 매출로 정의한다면 다음 계산을 사용한다.

```text
SUM([매출]) / COUNTD([주문ID])
```

주문당 수량은 다음과 같다.

```text
SUM([수량]) / COUNTD([주문ID])
```

한 주문이 여러 행에 나뉘어 있어도 고유 주문 수를 분모로 사용할 수 있다. 다만 분자의 매출과 수량이 행별로 더해도 되는 값인지 확인해야 한다.

주문 총매출이 상세 항목마다 반복되어 있다면 SUM([매출])은 과대 집계될 수 있다. COUNTD를 쓴다고 분자의 중복까지 해결되는 것은 아니다.

---

## 7. 집계와 비집계 값을 섞지 않기

다음 계산은 수준이 맞지 않는다.

```text
SUM([매출]) - [비용]
```

매출은 여러 행을 집계한 값이고 비용은 행 수준 값이다. 기본 계산에서는 이처럼 집계와 비집계 필드를 그대로 섞으면 오류가 발생할 수 있다.

현재 뷰의 총매출과 총비용을 비교하려면 둘 다 집계한다.

```text
SUM([매출]) - SUM([비용])
```

각 행의 이익을 계산하려면 둘 다 행 수준으로 사용한다.

```text
[매출] - [비용]
```

문법 오류를 없애기 위해 임의로 집계 함수를 붙이는 것이 아니라, **행별 값인지 그룹별 지표인지 먼저 결정**해야 한다.

분모가 0인 경우의 처리도 지표 정의에 포함한다. 예를 들어 방문수가 0이면 전환율을 계산하지 않도록 작성할 수 있다.

```text
IF SUM([방문수]) > 0 THEN
    SUM([구매수]) / SUM([방문수])
ELSE
    NULL
END
```

## 8. 문자열 함수로 필요한 정보 추출하기

| 함수 | 역할 |
|---|---|
| LEFT | 왼쪽에서 지정한 길이만큼 추출 |
| RIGHT | 오른쪽에서 지정한 길이만큼 추출 |
| MID | 지정한 위치부터 일부 추출 |
| CONTAINS | 특정 문자열 포함 여부 확인 |
| SPLIT | 구분자로 나눈 부분 추출 |

상품코드의 앞 세 글자가 카테고리를 나타낸다면 다음처럼 추출할 수 있다.

```text
LEFT([상품코드], 3)
```

하이픈으로 구분된 코드의 첫 부분을 추출하는 예시는 다음과 같다.

```text
SPLIT([상품코드], '-', 1)
```

문자열 가공은 실제 코드 구조에 맞아야 한다. 길이나 구분자 규칙이 일정한지, Null이나 예외 값이 있는지 확인한다.

## 9. 날짜 함수와 기간 지표

날짜 함수는 날짜의 일부를 추출하거나 두 날짜의 차이를 구하는 데 활용한다. 가입일부터 첫 구매일까지의 소요 기간은 날짜 차이로 정의할 수 있다.

```text
DATEDIFF('day', [가입일], [첫구매일])
```

날짜 순서가 반대이면 음수가 나올 수 있고, 아직 구매하지 않은 고객은 첫구매일이 없을 수 있다. 이런 값의 의미를 구분해야 한다.

DATEDIFF의 날짜 단위와 날짜 경계 계산은 단순한 시간 길이와 다를 수 있으므로, 필요한 지표가 달력상 날짜 차이인지 정확한 경과 시간인지 먼저 정의한다.

## 10. Parameter로 계산 기준 바꾸기

**Parameter(파라미터)**는 사용자가 변경할 수 있는 하나의 입력값이다. 계산식에 연결하면 기준값을 바꿀 수 있다.

숫자형 파라미터 [목표매출]을 만들고 다음처럼 활용할 수 있다.

```text
IF SUM([매출]) >= [목표매출] THEN '달성'
ELSE '미달성'
END
```

뷰의 지역이나 기간별 매출 집계 결과를 목표값과 비교한다. 사용자가 목표값을 바꾸면 계산 결과도 달라진다.

| 구분 | Parameter | Filter |
|---|---|---|
| 기본 역할 | 계산 등에 사용할 입력값 제공 | 분석할 데이터를 조건에 따라 제한 |
| 직접적인 동작 | 값 자체를 변경 | 포함할 데이터 범위 변경 |
| 예시 | 목표매출 기준 변경 | 특정 지역만 표시 |

파라미터를 만든 것만으로 데이터가 제거되지는 않는다. 파라미터를 참조하는 계산식을 필터에 적용하면 간접적으로 표시 범위를 바꿀 수 있다.

---

## 11. 계산된 필드 작성 흐름

1. 분석 질문을 정한다.
2. 지표의 의미와 단위를 정의한다.
3. 필요한 원본 필드와 행의 단위를 확인한다.
4. 행 수준인지 집계 수준인지 결정한다.
5. 조건과 계산에 적합한 함수를 선택한다.
6. Null, 0인 분모와 중복의 처리를 확인한다.
7. 계산 결과를 표본 데이터로 점검한다.
8. 뷰와 필터가 바뀌었을 때도 의도한 지표인지 확인한다.

계산식이 실행된다는 것만으로 올바른 지표가 된 것은 아니다. 계산 결과가 질문의 정의와 일치해야 한다.

---

## 12. 핵심 정리

- 계산된 필드는 기존 데이터로 새로운 값을 정의하며 원본에 직접 컬럼을 추가하는 것과 다르다.
- IF는 조건과 범위 분기, CASE는 값의 일치 비교, IIF는 간단한 참·거짓 분기에 적합하다.
- SUM, AVG, MIN, MAX, COUNT, COUNTD는 여러 행을 요약한다.
- COUNT는 값의 개수, COUNTD는 고유값의 개수를 계산한다.
- 전체 전환율은 전체 구매수와 방문수의 비율이며 행별 비율의 단순 평균과 다를 수 있다.
- 객단가와 같은 지표는 분자와 분모의 단위, 중복 여부를 함께 확인한다.
- 집계와 비집계 값을 사용하려면 계산 수준을 맞춰야 한다.
- 문자열·날짜 함수는 필요한 정보를 가공하고 기간 지표를 만드는 데 활용한다.
- 파라미터는 계산의 입력값을 제공하고 필터는 데이터 범위를 제한한다.
