# 2026-10-12 Tableau 필터의 종류와 차이

## 1. 같은 조건도 적용 순서에 따라 결과가 달라진다

Tableau의 필터는 데이터를 제한하는 기능이지만, 언제 적용되는지에 따라 계산 결과도 바꾼다.

전체 매출 상위 5개 카테고리를 선정한 뒤 서울 매출을 표시하는 것과, 서울 데이터에서 상위 5개를 다시 선정하는 것은 다르다.

| 분석 질문 | 필요한 처리 |
|---|---|
| 전국 Top 5의 서울 매출은? | 전체 기준으로 Top 5 선정 후 서울 결과 확인 |
| 서울 안에서 매출 Top 5는? | 서울 데이터로 먼저 제한한 뒤 Top 5 계산 |

서울에서 잘 팔리는 카테고리가 전국 Top 5에 없다면 첫 번째 방식에서는 누락될 수 있다. 표시된 항목이 5개보다 적어질 수도 있다.

이 차이를 이해하려면 **Order of Operations(실행 순서)**를 확인해야 한다.

---

## 2. 필터 종류별 역할

| 종류 | 역할 | 예시 |
|---|---|---|
| Extract Filter | 추출에 포함할 데이터 범위 제한 | 최근 3년만 추출 |
| Data Source Filter | 원본 수준에서 사용할 데이터 범위 제한 | 특정 국가 데이터만 사용 |
| Context Filter | 후속 계산과 필터의 기준 범위를 먼저 설정 | 서울 안의 Top 5 |
| Dimension Filter | 차원 값으로 데이터 제한 | 지역과 카테고리 선택 |
| Measure Filter | 집계된 측정값에 조건 적용 | 총매출 100만 원 이상 |
| Table Calculation Filter | 테이블 계산 후 표시 결과 제한 | 계산된 순위가 5 이하인 항목 표시 |

필터는 같은 선택 화면을 제공하더라도 적용 대상과 단계가 다를 수 있다.

Measure Filter에서 SUM([매출])에 조건을 적용하는 것은 원본 행별 매출에 조건을 적용하는 것과 다르다. 현재 뷰의 집계 단위를 함께 확인해야 한다.

---

## 3. 주요 실행 순서

주요 기능을 중심으로 단순화한 순서는 다음과 같다.

1. Extract Filter
2. Data Source Filter
3. Context Filter
4. FIXED LOD
5. Top N 및 일반 Dimension Filter 단계
6. INCLUDE / EXCLUDE LOD
7. Measure Filter
8. Table Calculation
9. Table Calculation Filter

전체 실행 순서에는 다른 기능도 포함된다. 여기서는 필터와 LOD, 테이블 계산의 관계를 이해하는 데 초점을 둔다.

핵심은 **앞 단계에서 남긴 데이터가 뒤 단계 계산의 대상이 될 수 있다는 것**이다. 일반 Dimension Filter를 놓은 순서만으로 Top N보다 먼저 처리되리라고 기대하면 안 된다.

---

## 4. 일반 Dimension Filter와 Quick Filter

Dimension Filter는 지역, 카테고리, 고객 유형 등의 값으로 분석할 데이터를 제한한다.

사용자가 화면에서 직접 지역을 선택하도록 필터 컨트롤을 표시할 수 있다. 이 인터페이스를 흔히 **Quick Filter**라고 부른다.

| 구분 | 의미 |
|---|---|
| Dimension Filter | 차원 값으로 데이터를 제한하는 필터 |
| Quick Filter | 사용자가 필터 값을 변경하는 화면 컨트롤 |

Quick Filter는 별도의 실행 단계가 아니다. 컨트롤의 이름이나 모양만으로 처리 순서가 정해지지 않으며, 실제 필터의 종류와 설정을 확인해야 한다.

---

## 5. Context Filter로 기준 범위 먼저 정하기

Context Filter는 일반 Dimension Filter보다 먼저 데이터 범위를 제한한다.

서울의 매출 상위 5개를 구하려면 지역 필터를 **Add to Context(컨텍스트에 추가)**로 설정할 수 있다.

1. 서울 데이터로 범위를 제한한다.
2. 제한된 데이터에서 카테고리별 매출을 집계한다.
3. 해당 범위의 Top 5를 선정한다.
4. 결과를 표시한다.

| 관점 | 일반 지역 필터 | 지역 Context Filter |
|---|---|---|
| 기본 역할 | 지역 조건으로 데이터 제한 | 후속 계산의 지역 범위 먼저 설정 |
| Top N 결과 | 전체 기준 Top N 중 선택 지역의 값이 표시될 수 있음 | 선택 지역 안에서 Top N 계산 가능 |
| FIXED와의 관계 | FIXED 이후 적용 | FIXED 이전 적용 |

컨텍스트로 바꾸는 것은 단순히 필터를 강조하는 것이 아니라 계산에 사용할 범위를 바꾸는 선택이다.

---

## 6. FIXED LOD와 필터

다음 식은 고객별 최초 구매일을 계산한다.

```text
{ FIXED [고객ID] : MIN([주문일]) }
```

일반 연도 필터로 2026년만 표시해도 최초 구매일이 2025년으로 남을 수 있다. FIXED 계산이 일반 Dimension Filter보다 먼저 수행되기 때문이다.

반면 연도 필터를 Context Filter로 바꾸면 2026년 데이터 안에서 최초 구매일이 계산된다.

| 목적 | 고려할 설정 |
|---|---|
| 2026년에 주문한 고객의 전체 기간 최초 구매일 확인 | 일반 연도 필터와 FIXED |
| 2026년 안에서 최초 구매일 확인 | 연도 Context Filter와 FIXED |

FIXED가 모든 필터를 무시하는 것은 아니다. 추출 필터, 원본 필터와 컨텍스트 필터처럼 먼저 적용되는 조건은 계산 범위를 바꿀 수 있다.

---

## 7. 테이블 계산 필터의 특징

테이블 계산 필터는 계산이 수행된 뒤 표시 결과를 제한한다.

일반 Dimension Filter로 항목을 제거하면 그 뒤의 테이블 계산 대상이 달라질 수 있다. 반면 테이블 계산 필터는 이미 계산된 값의 표시를 제한하므로 계산에 사용한 항목들이 그대로 남아 있을 수 있다.

예를 들어 구성비에서 “전체”를 유지한 채 일부 항목만 보여주려는 경우와, 선택한 항목들 안에서 구성비를 다시 구하려는 경우는 다른 질문이다.

계산 결과를 숨기는 것과 계산 전에 데이터를 제외하는 것을 구분해야 한다.

---

## 8. Context Filter를 항상 사용할 필요는 없다

단순히 서울 매출만 표시한다면 일반 Dimension Filter로 충분할 수 있다. 특정 범위 안에서 Top N을 다시 계산하거나 FIXED의 대상을 제한해야 할 때 Context Filter를 고려한다.

Context Filter가 항상 속도를 높이는 것은 아니다. 범위를 구성하는 추가 작업과 변경 빈도, 원본과 환경에 따라 비용이 달라질 수 있다.

| 목적 | 우선 고려할 방식 |
|---|---|
| 특정 지역·카테고리 선택 | 일반 Dimension Filter |
| 특정 지역 안의 Top N | 지역 Context Filter + Top N |
| 특정 기간 안의 FIXED 계산 | 기간 Context Filter |
| 집계된 매출에 조건 적용 | Measure Filter |
| 계산된 결과의 표시 제한 | Table Calculation Filter |

기능부터 선택하기보다 어떤 범위를 기준으로 계산해야 하는지 정의한다.

---

## 9. 여러 워크시트에 필터 적용하기

대시보드에서 지역을 바꾸었는데 일부 차트만 바뀐다면 필터의 적용 범위가 제한되어 있을 수 있다.

**Apply to Worksheets**로 필터를 적용할 워크시트를 지정한다.

| 적용 방식 | 활용 목적 |
|---|---|
| 현재 워크시트 | 해당 차트만 개별 분석 |
| 선택한 워크시트 | 관련 지표에만 같은 조건 적용 |
| 같은 데이터 원본의 모든 워크시트 | 공통 원본 기반 차트에 적용 |
| 관련 데이터 원본의 워크시트 | 설정된 필드 관계를 이용해 원본 간 적용 |

매출과 이익을 같은 지역 기준으로 비교하려면 두 워크시트에 같은 지역 조건을 적용해야 한다. 서로 다른 원본에는 필드 관계와 데이터 구조가 맞는지도 확인한다.

필터를 공유하는 것과 각 워크시트의 계산 설정이 같은 것은 별개이다. Top N과 FIXED가 있다면 해당 시트의 컨텍스트 설정과 계산 범위도 검증한다.

---

## 10. 모든 차트에 같은 필터를 적용해야 할까?

같은 필터를 적용할 차트는 분석 목적에 따라 정한다.

서울의 성과를 비교하는 매출·이익 차트는 함께 바뀌는 것이 자연스럽다. 그러나 전국과의 비교를 위한 기준 차트는 전국 범위를 유지해야 할 수 있다.

변하지 않는 차트가 의도된 것이라면 제목이나 설명으로 그 범위를 명확히 표시한다. 선택 지역과 전체 기준의 값이 섞여 보이면 사용자가 같은 조건으로 해석할 수 있기 때문이다.

확인할 질문은 다음과 같다.

- 어떤 차트가 같은 조건으로 비교되어야 하는가?
- 어떤 차트는 전체 기준을 유지해야 하는가?
- 계산의 분모와 Top N 선정 범위가 바뀌어야 하는가?
- 필터의 적용 대상과 표시된 제목이 일치하는가?

---

## 11. 결과 검증 흐름

1. 사용자가 원하는 질문과 계산 범위를 정한다.
2. 원본·추출 수준에서 이미 제한된 데이터가 있는지 확인한다.
3. 일반 필터와 컨텍스트 중 필요한 방식을 선택한다.
4. Top N, LOD와 테이블 계산의 실행 순서를 확인한다.
5. 적용할 워크시트를 지정한다.
6. 조건을 바꿔 항목 수, 집계값과 순위가 예상대로 변하는지 확인한다.
7. 각 차트의 분석 범위를 제목과 설명에 반영한다.

예상과 다른 결과는 수식뿐 아니라 실행 순서나 적용 범위에서 발생할 수 있다.

---

## 12. 핵심 정리

- 필터는 종류별로 역할과 실행 단계가 다르다.
- 일반 Dimension Filter만으로 특정 지역 안의 Top N 계산 순서가 보장되지 않는다.
- Context Filter는 후속 계산의 기준 범위를 먼저 제한한다.
- FIXED는 컨텍스트 이후, 일반 Dimension Filter 이전에 계산된다.
- INCLUDE와 EXCLUDE는 일반 Dimension Filter 이후에 계산된다.
- Quick Filter는 컨트롤이며 독립적인 실행 단계가 아니다.
- 테이블 계산 필터는 계산 이후 표시 결과를 제한한다.
- Context Filter가 항상 성능을 높이는 것은 아니다.
- Apply to Worksheets로 공통 필터의 적용 범위를 정한다.
- 분석 목적에 따라 전체 기준을 유지할 차트와 함께 바꿀 차트를 구분한다.

---

## 오늘의 한 문장

> Tableau 필터는 보여줄 데이터를 고르는 기능이면서 계산의 범위를 정하는 기능이므로, 조건과 함께 실행 순서와 워크시트 적용 범위를 확인해야 한다.
