# 2026-10-08 Tableau LOD 표현식으로 집계 수준 제어하기

## 1. 집계 수준이 달라지면 결과도 달라진다

**Level of Detail(LOD)**은 어떤 Dimension을 기준으로 데이터를 나누어 계산하는지를 뜻한다.

같은 주문 데이터에서 SUM([매출])을 사용하더라도 지역을 배치하면 지역별 매출, 고객ID를 배치하면 고객별 매출이 된다.

| 지역 | 고객ID | 주문ID | 매출 |
|---|---|---|---:|
| Seoul | C001 | O001 | 100,000 |
| Seoul | C001 | O002 | 150,000 |
| Seoul | C002 | O003 | 80,000 |
| Busan | C003 | O004 | 120,000 |

이 데이터의 한 행은 주문 한 건이다. 지역 수준으로 집계하면 Seoul은 330,000원, Busan은 120,000원이다.

계산식을 이해할 때는 함수뿐 아니라 **어떤 단위로 계산하는지**를 함께 확인해야 한다.

---

## 2. Row Level과 View Level

| 구분 | 기준 | 예시 |
|---|---|---|
| Row Level | 원본 데이터의 각 행 | [매출] - [비용] |
| View Level | 현재 뷰의 Dimension | 지역별 SUM([매출]) |
| LOD 표현식 | 별도로 지정하거나 뷰에서 조절한 Dimension | 고객별 총매출 계산 |

Row Level은 행마다 계산한다. View Level은 뷰에서 데이터를 나누는 기준에 따라 집계한다.

화면에는 지역별 결과를 표시하면서 계산에는 고객 단위가 필요할 수 있다. 이처럼 **화면에서 보고 싶은 수준과 계산에 필요한 수준이 다를 때** LOD 표현식을 활용한다.

---

## 3. 고객당 평균 매출과 주문당 평균 매출

앞의 Seoul 데이터에서 C001의 총매출은 250,000원, C002는 80,000원이다.

고객 한 명당 평균 매출은 다음과 같다.

$$
\frac{250,000+80,000}{2}=165,000
$$

반면 원본의 주문별 매출을 평균하면 다음과 같다.

$$
\frac{100,000+150,000+80,000}{3}=110,000
$$

두 계산은 서로 다른 질문에 답한다. AVG([매출])만 사용하면 고객별 총매출의 평균이 아니라 원본 행에 대한 평균을 구하게 된다.

고객별로 먼저 합산한 뒤 평균을 구하려면 중간 계산 수준을 지정해야 한다. 이 사례처럼 단순한 고객당 매출은 SUM([매출]) / COUNTD([고객ID])로도 계산할 수 있지만, LOD는 중간 집계가 필요한 더 다양한 계산에 활용할 수 있다.

---

## 4. LOD 기본 구조

```text
{ LOD유형 [Dimension] : 집계식 }
```

중괄호 안에서 집계 수준과 계산을 정의한다. 대표적인 유형은 FIXED, INCLUDE, EXCLUDE이다.

| 유형 | 계산 기준 | 목적 |
|---|---|---|
| FIXED | 지정한 Dimension | 뷰의 Dimension과 별도로 기준 지정 |
| INCLUDE | 현재 뷰 + 지정한 Dimension | 더 세부적으로 먼저 계산 |
| EXCLUDE | 현재 뷰 - 지정한 Dimension | 일부 기준을 빼고 더 큰 수준으로 계산 |

유형을 고르기 전에 현재 뷰의 수준과 실제 필요한 계산 수준을 비교해야 한다.

---

## 5. FIXED: 지정한 수준으로 계산하기

고객별 총매출을 뷰의 구성과 별도로 계산하는 식이다.

```text
{ FIXED [고객ID] : SUM([매출]) }
```

고객 C001은 두 주문을 합쳐 250,000원으로 계산된다. 뷰에 지역이나 카테고리를 추가해도 식 자체의 계산 기준은 고객ID이다.

고객별 최초 구매일도 지정할 수 있다.

```text
{ FIXED [고객ID] : MIN([주문일]) }
```

각 고객의 주문 중 가장 이른 날짜를 찾는다. 단, 계산 대상 데이터에 포함된 주문 중 최초 날짜이며 이후 설명할 필터 실행 순서의 영향을 받는다.

FIXED는 **뷰의 Dimension과 독립적**이라는 뜻이지 모든 필터의 영향을 무시한다는 뜻은 아니다.

---

## 6. INCLUDE: 뷰보다 세부적으로 계산하기

지역만 표시한 뷰에서 고객별 총매출을 먼저 계산하려면 고객ID를 추가한다.

```text
{ INCLUDE [고객ID] : SUM([매출]) }
```

계산은 지역과 고객 수준에서 수행되고, 그 결과를 지역 수준으로 다시 집계할 수 있다.

고객별 합계를 평균으로 표시하면 고객당 평균 매출을 얻는다.

```text
AVG({ INCLUDE [고객ID] : SUM([매출]) })
```

앞의 예시에서 Seoul은 고객별 합계 250,000원과 80,000원의 평균인 165,000원이다.

| 단계 | 수준 |
|---|---|
| 화면 | 지역 |
| INCLUDE 내부 계산 | 지역 + 고객ID |
| 결과 표시 | 고객별 합계를 지역별 평균으로 재집계 |

INCLUDE는 현재 뷰에 상대적으로 작동한다. 뷰에 카테고리까지 추가하면 내부 계산은 지역·카테고리·고객 수준이 될 수 있다. 따라서 뷰를 바꿀 때 지표 의미도 확인해야 한다.

---

## 7. EXCLUDE: 뷰의 일부 Dimension 제외하기

지역과 카테고리를 함께 표시한 뷰에서 지역을 제외한 카테고리별 매출을 계산할 수 있다.

```text
{ EXCLUDE [지역] : SUM([매출]) }
```

현재 뷰는 지역 + 카테고리지만, 이 계산에서는 카테고리 기준으로 매출을 집계한다.

이를 이용하면 각 지역·카테고리의 값과 더 큰 기준의 카테고리 매출을 함께 비교할 수 있다.

EXCLUDE는 항상 데이터 전체의 총합을 계산하는 것이 아니다. 지정한 Dimension만 제외하고, 나머지 뷰 기준과 적용되는 필터는 영향을 준다.

---

## 8. LOD 결과를 표시할 때의 주의점

LOD 계산 수준과 표시 수준이 다르면 같은 값이 여러 마크에 반복되어 보일 수 있다. 특히 고객별 FIXED 값을 주문 수준에서 표시하면 한 고객의 총매출이 여러 주문에 대응할 수 있다.

이를 원본의 각 행마다 독립적인 금액인 것처럼 더하면 의도와 다른 결과가 나올 수 있다. 고객별 값을 평균낼 때도 고객이 아니라 주문에 비례한 가중치가 생기지 않는지 확인해야 한다.

확인할 질문은 다음과 같다.

- LOD가 어떤 단위로 계산되었는가?
- 결과를 현재 뷰에서 어떻게 재집계하는가?
- 같은 값이 여러 행이나 마크에 반복되는가?
- 평균의 대상이 고객인지 주문인지 명확한가?

계산식이 맞더라도 최종 집계 방식까지 지표 정의와 일치해야 한다.

---

## 9. 필터와 LOD의 실행 순서

Tableau는 필터와 계산을 정해진 순서로 처리한다. LOD를 이해하기 위한 주요 순서는 다음과 같다. 이는 전체 실행 순서를 단순화한 것이다.

1. Context Filter
2. FIXED LOD
3. 일반 Dimension Filter
4. INCLUDE / EXCLUDE LOD
5. Measure Filter

| LOD | 일반 Dimension Filter와의 관계 |
|---|---|
| FIXED | 필터보다 먼저 계산 |
| INCLUDE | 필터 적용 후 계산 |
| EXCLUDE | 필터 적용 후 계산 |

같은 필터를 적용해도 유형에 따라 계산 대상이 달라질 수 있다. 예상과 다른 결과가 나오면 집계 수준과 함께 실행 순서를 확인해야 한다.

---

## 10. FIXED와 연도 필터 예시

고객 C001의 주문일이 다음과 같다고 하자.

| 주문일 |
|---|
| 2025-10-10 |
| 2026-02-15 |
| 2026-05-20 |

최초 구매일은 다음 식으로 구한다.

```text
{ FIXED [고객ID] : MIN([주문일]) }
```

2026년만 표시하는 일반 Dimension Filter를 적용해도 최초 구매일이 2025-10-10으로 남을 수 있다. FIXED가 먼저 계산되고 연도 필터가 나중에 적용되기 때문이다.

이는 계산 오류가 아니라 실행 순서에 따른 결과이다.

| 질문 | 필요한 기준 |
|---|---|
| 2026년 주문 고객의 전체 데이터 기준 최초 구매일은? | 일반 연도 필터를 적용하되 FIXED 기준 유지 |
| 2026년 안에서 각 고객의 첫 구매일은? | 연도 필터를 FIXED 이전에 적용 |

두 질문은 서로 다른 지표이다.

---

## 11. Context Filter로 FIXED 계산 대상 제한하기

2026년 데이터 안에서 최초 구매일을 계산하려면 연도 필터가 FIXED보다 먼저 적용되어야 한다. 연도 필터를 Context Filter로 설정하면 이러한 순서로 처리된다.

1. 2026년 데이터를 먼저 남긴다.
2. 남은 데이터에서 고객별 MIN([주문일])을 계산한다.
3. 뷰에 결과를 표시한다.

앞의 C001은 2026-02-15가 계산된다.

Context Filter로 바꾸는 것은 단순한 오류 수정이 아니라 **계산에 포함할 데이터 범위를 바꾸는 선택**이다. 분석 목적에 맞게 사용해야 한다.

데이터 원본 필터나 추출 필터처럼 FIXED 이전 단계에서 데이터를 제한하는 조건도 있을 수 있으므로, “FIXED는 언제나 전체 원본을 본다”라고 해석해서는 안 된다.

---

## 12. LOD 선택과 검증 흐름

1. 원본 데이터 한 행의 단위를 확인한다.
2. 현재 뷰의 Dimension을 정리한다.
3. 계산에 필요한 Dimension과 지표를 정의한다.
4. FIXED, INCLUDE, EXCLUDE를 선택한다.
5. 최종 표시에서 사용할 재집계 방식을 확인한다.
6. 필터의 종류와 실행 순서를 확인한다.
7. 소수의 고객이나 주문으로 직접 계산한 값과 비교한다.
8. 뷰와 필터를 바꾸었을 때도 의도한 결과인지 확인한다.

LOD 문법을 외우는 것보다 계산 단위와 대상 데이터를 설명할 수 있는 것이 중요하다.

---

## 13. 핵심 정리

- 기본 집계는 현재 뷰의 Dimension에 따라 달라진다.
- Row Level과 View Level을 구분해야 한다.
- LOD는 화면과 다른 수준의 계산을 정의할 때 활용한다.
- FIXED는 지정한 Dimension으로, INCLUDE는 뷰에 기준을 더하여, EXCLUDE는 뷰에서 기준을 빼고 계산한다.
- 고객별 합계를 평균내는 것과 주문별 매출을 평균내는 것은 다르다.
- LOD 결과의 재집계와 반복 표시를 확인해야 한다.
- FIXED는 일반 Dimension Filter보다 먼저 계산된다.
- INCLUDE와 EXCLUDE는 일반 Dimension Filter 이후 계산된다.
- Context Filter는 FIXED 이전에 적용되어 계산 대상 범위를 제한할 수 있다.
- LOD 결과는 집계 수준과 필터 실행 순서를 함께 검증해야 한다.

---

## 오늘의 한 문장

> LOD 표현식은 화면의 수준과 계산의 수준을 분리하는 도구이며, 정확한 지표를 만들려면 집계 단위와 재집계 방식, 필터 실행 순서를 함께 이해해야 한다.
