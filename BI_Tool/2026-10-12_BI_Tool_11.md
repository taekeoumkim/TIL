# 2026-10-12 Tableau 인터랙티브 대시보드 종합 구현

## 1. 차트들을 하나의 분석 흐름으로 연결하기

**인터랙티브 대시보드**는 사용자가 조건을 선택하고, 요약에서 상세로 탐색하며, 여러 지표를 비교할 수 있도록 구성한 화면이다.

온라인 쇼핑몰의 성과를 분석한다면 전체 매출을 확인한 뒤 지역별 차이, 월별 변화와 상품별 수익성을 살펴볼 수 있다. 각 차트의 조건을 따로 바꾸기보다 하나의 선택이 관련 정보를 연결하도록 만드는 것이 중요하다.

대시보드의 목적은 차트를 많이 보여주는 것이 아니라 **사용자가 질문의 답을 자연스럽게 찾아가도록 돕는 것**이다.

---

## 2. 선택·드릴다운·비교

| 기능 | 의미 | 예시 |
|---|---|---|
| Select | 데이터나 분석 기준 선택 | 부산 지역, 이익 지표 선택 |
| Drill-down | 요약에서 상세 수준으로 탐색 | 지역별 성과에서 상품별 성과 확인 |
| Compare | 항목과 지표의 차이 확인 | 매출 규모와 이익 함께 비교 |

매출이 높아도 이익은 낮을 수 있다. 따라서 단일 지표를 보는 데서 끝나지 않고 여러 관점으로 확인할 수 있어야 한다.

필요한 정보 전부를 처음부터 표시할 필요는 없다. 핵심 요약을 먼저 제공하고 상세 정보는 선택에 따라 확인하도록 구성할 수 있다.

---

## 3. 분석 질문에 맞는 차트 구성

| 질문 | 필요한 정보 | 표현 예시 |
|---|---|---|
| 전체 성과는 어떠한가? | 총매출, 총이익, 주문 수 | KPI |
| 어느 지역의 성과가 높은가? | 지역별 지표 | 막대 차트 |
| 시간에 따라 어떻게 변하는가? | 월별 지표 | 라인 차트 |
| 어떤 상품이 매출에 기여하는가? | 상품별 매출 | 막대 차트 |
| 매출은 높지만 이익이 낮은 상품은? | 상품별 매출과 이익 | 산점도 |

산점도를 사용할 때는 점 하나가 어떤 상품을 의미하는지 분석 단위를 정의해야 한다. KPI도 어떤 기간과 범위의 값인지 명확하게 표시한다.

---

## 4. 분석 순서를 반영한 레이아웃

전체 성과를 먼저 보고 관심 영역을 발견한 뒤 상세를 확인하는 순서로 배치한다.

| 화면 영역 | 구성 예시 | 목적 |
|---|---|---|
| 상단 | 매출·이익·주문 수 KPI | 전체 성과 파악 |
| 중단 | 지역별 차트와 월별 추세 | 차이와 변화 확인 |
| 하단 | 상품별 매출·이익 | 상세 성과 탐색 |

관련된 차트를 가까이 두면 비교하기 쉽다. 주요 지표가 흩어져 있거나 흐름과 무관하게 배치되면 사용자가 어디부터 봐야 할지 판단하기 어렵다.

레이아웃은 장식이 아니라 **정보를 이해하는 순서**를 설계하는 것이다.

---

## 5. Tiled와 Floating

| 구분 | Tiled | Floating |
|---|---|---|
| 배치 | 공간을 나누어 정렬 | 위치와 크기를 자유롭게 지정 |
| 겹침 | 일반적으로 겹치지 않음 | 다른 개체 위에 겹칠 수 있음 |
| 장점 | 구조적인 정렬 | 세밀한 위치 조정 |
| 주의점 | 주변 개체 배치의 영향 | 화면 크기 변화에 따른 겹침과 가림 |
| 활용 | 주요 차트와 KPI | 설명이나 강조 요소 |

기본 구조를 Tiled로 만들고 필요한 일부 요소에 Floating을 사용할 수 있다. 자유로운 배치가 항상 좋은 것은 아니며, 다른 화면 크기에서도 차트를 가리지 않는지 확인해야 한다.

---

## 6. Layout Container와 화면 크기

**Layout Container**는 여러 개체를 일정한 방향으로 묶어 배치하고 관리하는 기능이다.

| 컨테이너 | 배치 방향 | 활용 |
|---|---|---|
| Horizontal | 좌우 | KPI를 한 줄에 배치 |
| Vertical | 위아래 | 요약과 차트를 순서대로 배치 |

화면의 크기 설정도 사용 환경에 맞게 선택한다.

| 설정 | 역할 |
|---|---|
| Fixed Size | 지정한 크기로 구성 |
| Automatic Size | 사용 가능한 공간에 맞춰 크기 조절 |
| Range | 최소·최대 크기 범위 지정 |
| Device Layout | 데스크톱·태블릿·모바일 등에 맞게 별도 구성 |

자동 크기라고 모든 차트가 잘 보이는 것은 아니다. 제목 잘림, 글자 크기, 필터 위치와 차트의 비율을 실제 화면에서 확인한다. 모바일에서는 같은 정보를 세로 흐름으로 재배치해야 할 수 있다.

---

## 7. 여러 워크시트의 반응 연결

지역별 매출 차트를 Source로 하고 월별 추세, 카테고리와 상품 차트를 Target으로 지정하면 지역 선택을 Filter Action으로 전달할 수 있다.

하지만 모든 차트가 똑같이 바뀌어야 하는 것은 아니다.

| 차트의 목적 | 선택에 대한 반응 |
|---|---|
| 부산 상품 실적에 집중 | Filter Action으로 부산만 표시 |
| 다른 지역과 부산 추세 비교 | 전체 지역을 유지하고 Highlight |
| 전국 평균을 비교 기준으로 제공 | 전국 범위 유지 |

전국 평균 차트까지 부산으로 제한하면 비교 기준의 의미가 바뀐다. 어떤 차트가 반응하고 어떤 차트가 기준을 유지할지 먼저 정의해야 한다.

Highlight로 지역별 선을 강조하려면 뷰에서 지역별 선이 구분되어 있어야 한다. 전체가 하나로 합쳐진 선에서는 지역별 흐름을 그대로 비교할 수 없다.

---

## 8. Parameter와 Action의 역할 분리

파라미터는 무엇을 분석할지, Filter Action은 어떤 데이터 범위를 분석할지 바꾸는 역할로 연결할 수 있다.

문자열 파라미터 [지표 선택]과 다음 계산식을 사용하면 지표를 전환할 수 있다.

```text
CASE [지표 선택]
WHEN '매출' THEN SUM([Sales])
WHEN '이익' THEN SUM([Profit])
WHEN '수량' THEN SUM([Quantity])
END
```

사용자는 먼저 이익을 선택하고, 부산을 선택한 뒤 부산의 월별·상품별 이익을 탐색할 수 있다.

지표 전환과 함께 제목, 축과 단위도 확인한다. 매출·이익의 금액과 수량의 개수를 같은 형식으로 표시하면 해석이 혼란스러울 수 있다.

---

## 9. Tooltip으로 필요한 상세 정보 제공

Tooltip은 마크에 마우스를 올렸을 때 추가 정보를 보여준다. 모든 값을 별도 차트나 레이블로 표시하지 않고 필요한 순간에 제공할 수 있다.

지역별 매출 차트의 툴팁에는 지역명, 매출, 이익과 이익률을 함께 표시할 수 있다.

| 항목 | 예시 |
|---|---|
| 지역 | 부산 |
| 매출 | 15,000,000원 |
| 이익 | 2,000,000원 |
| 이익률 | 약 13.3% |

이익률을 총이익 대비 총매출의 비율로 정의한다면 다음처럼 계산한다.

```text
SUM([Profit]) / SUM([Sales])
```

지표의 단위와 집계 기준을 명확하게 표시한다. 핵심 정보까지 Tooltip에만 숨기면 사용자가 놓칠 수 있으므로 항상 보여줄 정보와 보조 정보를 구분한다.

---

## 10. Viz in Tooltip과 조건부 색상

**Viz in Tooltip**은 툴팁 안에 다른 워크시트의 시각화를 표시하는 기능이다. 지역 막대 위에 마우스를 올렸을 때 해당 지역의 월별 추세를 작은 차트로 보여줄 수 있다.

툴팁에 표시되는 차트가 선택한 지역의 조건을 전달받는지 확인해야 한다. 작은 화면 안에 너무 많은 정보를 넣으면 읽기 어려워질 수 있다.

조건부 색상은 손실이나 목표 미달처럼 중요한 상태를 강조하는 데 활용한다.

```text
IF SUM([Profit]) < 0 THEN '손실'
ELSE '비손실'
END
```

상품 단위의 뷰에서 이 계산을 Color에 사용하면 손실 상품을 구분할 수 있다. 색의 의미를 일관되게 유지하고 레이블도 함께 활용하면 해석하기 쉽다.

---

## 11. 성능과 결과를 함께 검증하기

차트와 Action, 툴팁을 많이 연결하면 정보가 늘지만 처리 부담도 커질 수 있다. 사용자의 질문에 필요한 기능을 우선하고 응답 속도를 확인한다.

**Performance Recording**은 실행 성능을 살펴보고 병목을 파악하는 데 활용할 수 있다.

완성 후에는 다음을 점검한다.

- 다른 지역 선택 시 관련 차트가 올바르게 바뀌는가?
- 전체 비교가 필요한 차트는 기준을 유지하는가?
- 지표 변경 시 계산과 단위가 일치하는가?
- 선택 해제 시 의도한 상태로 돌아가는가?
- Tooltip과 작은 차트가 올바른 범위의 정보를 보여주는가?
- 화면 크기가 바뀌어도 차트와 컨트롤을 읽을 수 있는가?
- 사용자 행동에 대한 반응이 충분히 빠른가?

여러 차트가 움직인다는 사실보다 **올바른 지표와 데이터 범위를 표시하는지**가 중요하다.

---

## 12. 종합 구현 흐름

1. 사용자가 해결할 비즈니스 질문을 정의한다.
2. 필요한 지표와 분석 단위를 정한다.
3. 질문에 맞는 차트를 구성한다.
4. 전체와 상세 정보를 구분하여 레이아웃을 만든다.
5. Filter, Parameter와 Action의 역할을 연결한다.
6. Tooltip과 시각적 강조로 보조 정보를 제공한다.
7. 선택, 비교, 드릴다운과 복귀 흐름을 검증한다.
8. 실제 화면 크기와 성능을 점검한다.

각 기능을 개별적으로 구현하는 것에서 끝나지 않고 전체 탐색 과정이 자연스럽게 이어지도록 구성한다.

---

## 13. 핵심 정리

- 인터랙티브 대시보드는 선택·드릴다운·비교를 하나의 분석 흐름으로 연결한다.
- 분석 질문을 먼저 정한 뒤 KPI와 차트를 선택한다.
- Tiled는 구조적 배치, Floating은 자유로운 위치 조정에 적합하다.
- 컨테이너는 관련 개체를 가로·세로로 묶어 관리한다.
- 화면 크기와 Device Layout을 통해 기기별 가독성을 확인한다.
- 상세 차트는 필터링하고 비교 차트는 강조하는 등 목적에 맞게 반응을 나눈다.
- Parameter는 지표를, Filter Action은 데이터 범위를 바꾸는 역할로 연결할 수 있다.
- Tooltip과 Viz in Tooltip은 필요한 순간에 상세 정보를 제공한다.
- 조건부 색상은 손실과 같은 중요한 상태를 강조한다.
- 결과의 정확성, 사용자 탐색 흐름과 성능을 함께 검증한다.

---

## 오늘의 한 문장

> 인터랙티브 대시보드의 완성도는 차트와 기능의 수가 아니라, 사용자가 올바른 지표와 기준을 유지하며 질문의 답을 찾아갈 수 있는 흐름에 달려 있다.
