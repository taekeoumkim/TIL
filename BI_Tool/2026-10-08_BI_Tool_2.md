# 2026-10-08 Tableau 시작하기: 데이터 연결과 필드 이해

## 1. Tableau는 데이터를 어떻게 바라볼까?

Tableau에 데이터를 연결하면 각 열(Column)이 하나의 **필드(Field)**로 나타난다. 사용자는 분석 질문에 필요한 필드를 선택하고 배치하여 데이터를 그룹화하고 집계한다.

온라인 쇼핑몰 주문 데이터에 다음과 같은 필드가 있다고 가정하자.

| 필드 | 의미 |
|---|---|
| order_id | 주문 식별자 |
| order_date | 주문 날짜 |
| region | 지역 |
| category | 상품 카테고리 |
| customer_type | 고객 유형 |
| quantity | 주문 수량 |
| sales | 매출 |
| profit | 이익 |

같은 데이터를 사용해도 질문에 따라 필요한 필드와 사용 방식이 달라진다.

| 분석 질문 | 필요한 필드 | 생각할 내용 |
|---|---|---|
| 지역별 매출은 얼마인가? | region, sales | 지역으로 나누고 매출 집계 |
| 카테고리별 이익은 얼마인가? | category, profit | 카테고리로 나누고 이익 집계 |
| 월별 매출은 어떻게 변하는가? | order_date, sales | 날짜를 월 단위로 나누고 매출 집계 |

중요한 것은 필드를 드래그하는 방법만 외우는 것이 아니다. **무엇을 기준으로 나누고, 어떤 값을 어떻게 집계하며, 어떤 형태로 표현할지**를 판단해야 한다.

---

## 2. Tableau의 기본 화면

| 영역 | 역할 |
|---|---|
| 데이터 원본(Data Source) | 분석을 위해 연결한 파일이나 데이터베이스 등의 원본 |
| 데이터 창(Data Pane) | 연결된 데이터의 필드를 확인하는 영역 |
| 열·행 선반(Columns / Rows) | 필드를 배치하여 시각화의 구조를 구성하는 영역 |
| 마크 카드(Marks Card) | 색상, 크기, 레이블 등 표현 방법을 조절하는 영역 |
| 뷰(View) | 실제 시각화 결과가 나타나는 영역 |
| Show Me | 선택한 필드에 맞는 시각화 유형을 확인하는 기능 |

기본 작업은 데이터 연결, 필드 확인, 질문에 필요한 필드 선택, 배치, 결과 확인으로 이어진다.

Show Me가 제시하는 차트를 사용할 수 있더라도 분석 질문에 적합한지 판단해야 한다. 도구가 제공하는 선택지와 분석 목적은 함께 고려해야 한다.

---

## 3. Dimension: 데이터를 나누는 기준

**Dimension(차원)**은 데이터를 구분하거나 그룹화하는 기준으로 사용하는 필드이다. 분석 질문의 “~별”에 해당하는 기준으로 생각하면 이해하기 쉽다.

| Dimension 예시 | 데이터를 나누는 기준 |
|---|---|
| region | 지역별 |
| category | 상품 카테고리별 |
| customer_type | 고객 유형별 |
| order_date | 날짜별 |

region을 사용하면 주문 데이터를 Seoul, Busan 등 지역별 그룹으로 나눌 수 있다. order_date를 사용하면 연도별, 월별 등 날짜 수준에 따라 나눌 수 있다.

Dimension을 추가하거나 날짜 수준을 바꾸면 뷰에서 데이터를 묶는 상세 수준도 달라진다. 따라서 어떤 단위로 비교하려는지 먼저 정해야 한다.

---

## 4. Measure: 그룹별로 집계할 값

**Measure(측정값)**는 각 그룹에서 계산하여 확인하려는 값이다. 매출, 이익, 주문 수량 등을 Measure로 사용할 수 있다.

여러 행의 값을 합계, 평균, 최솟값, 최댓값 등으로 요약하는 것을 **집계(Aggregation)**라고 한다.

| 집계 표현 | 의미 |
|---|---|
| SUM(Sales) | 매출 합계 |
| AVG(Sales) | 매출 값의 평균 |
| MAX(Sales) | 가장 큰 매출 값 |
| MIN(Sales) | 가장 작은 매출 값 |

같은 sales 필드라도 집계 방법에 따라 답하는 질문이 달라진다. 지역별 총매출을 보려면 합계를, 행별 매출의 평균을 비교하려면 평균을 사용한다.

평균을 해석할 때는 원본 데이터 한 행의 단위를 확인해야 한다. 한 행이 주문 하나일 때와 주문 내 상품 하나일 때의 AVG(Sales)는 의미가 다르다. 행의 평균을 무조건 평균 주문 금액이라고 부르면 안 된다.

---

## 5. 숫자라고 항상 Measure일까?

고객 ID가 1001, 1002, 1003으로 저장되어 있어도 그 평균을 계산하는 것은 일반적으로 분석 목적에 맞지 않는다. 고객을 구분하는 식별자로 사용하는 것이 자연스럽다.

| 필드 | 저장된 값 | 적절한 역할 예시 |
|---|---|---|
| 고객 ID | 숫자 | 고객을 구분하는 Dimension |
| 매출 | 숫자 | 합계나 평균을 구하는 Measure |
| 주문 날짜 | 날짜 | 기간을 나누는 Dimension |

Dimension과 Measure는 자료형만으로 결정하는 개념이 아니다. **분석에서 어떤 역할로 사용하는가**가 기준이다.

숫자로 저장된 식별자가 자동으로 집계 대상으로 분류되었다면 필드의 의미를 확인하고 역할을 조정해야 한다.

---

## 6. 불연속형과 연속형

Dimension과 Measure가 분석 역할의 구분이라면, 불연속형과 연속형은 뷰의 표현 방식에 대한 구분이다.

| 구분 | 불연속형(Discrete) | 연속형(Continuous) |
|---|---|---|
| 표현 | 각각 구분된 항목 | 이어지는 범위 |
| 행·열 배치 시 일반적인 결과 | 머리글(Header) | 축(Axis) |
| Tableau 색상 | 파란색 | 초록색 |
| 활용 예시 | 지역별 항목 비교 | 매출의 수치 범위, 시간 흐름 표현 |

### 불연속형

Seoul, Busan, Daejeon처럼 항목을 나누어 보여준다. 각 범주를 구분해 비교하려는 목적에 적합하다.

### 연속형

값을 이어지는 축 위에 표현한다. 매출의 수치 범위나 시간에 따른 변화처럼 연속적인 흐름을 보여줄 때 활용한다.

Tableau의 파란색과 초록색은 **불연속형과 연속형**을 나타낸다. Dimension과 Measure를 나타내는 색이라고 외우면 안 된다.

---

## 7. 필드의 역할과 표현 방식은 별개이다

| 구분 기준 | 답하는 질문 |
|---|---|
| Dimension / Measure | 필드가 분석에서 어떤 역할을 하는가? |
| Discrete / Continuous | 필드를 뷰에서 어떻게 표현하는가? |
| Data Type | 값이 날짜, 숫자, 문자열 등 어떤 형태로 저장되어 있는가? |

예를 들어 order_date는 날짜별로 데이터를 나누는 Dimension이면서, 불연속형 또는 연속형으로 사용할 수 있다.

| 사용 목적 | 분석 역할 | 표현 방식 |
|---|---|---|
| 연도별 매출을 각각 비교 | Dimension | Discrete |
| 시간에 따른 매출 흐름 확인 | Dimension | Continuous |

따라서 Dimension은 반드시 파란색, Measure는 반드시 초록색이라는 관계가 성립하지 않는다.

---

## 8. 같은 날짜 필드도 다르게 표현할 수 있다

날짜를 사용할 때는 집계 수준과 표현 방식을 함께 선택해야 한다.

- 집계 수준: 연도, 분기, 월, 일 등
- 표현 방식: 불연속형 또는 연속형

연도별 값을 구분하여 비교한다면 불연속형 표현을 사용할 수 있다. 시간의 흐름에 따른 추세가 중요하다면 연속형 날짜 축을 고려할 수 있다.

여러 해의 월별 변화를 볼 때는 월 이름만 묶어 다른 해의 같은 달이 합쳐지는지 확인해야 한다. 실제 연월별 추세와 계절별 월 비교는 서로 다른 질문이다.

같은 날짜 필드라도 배치와 수준에 따라 다른 질문에 답하므로, 완성된 뷰가 의도한 기간과 단위를 보여주는지 확인한다.

---

## 9. 데이터 연결 후 확인할 사항

데이터가 연결되었다고 바로 분석을 시작하기보다 필드의 의미와 인식 상태를 확인한다.

| 확인 항목 | 이유 |
|---|---|
| 컬럼 이름과 의미 | 필요한 필드를 올바르게 선택하기 위해 |
| 데이터 유형 | 날짜·숫자가 문자열로 인식되지 않았는지 확인하기 위해 |
| 데이터 한 행의 단위 | 집계 결과의 의미를 정확히 해석하기 위해 |
| Dimension / Measure 역할 | 숫자 식별자 등이 잘못 집계되지 않도록 |
| 결측치와 중복 | 집계 결과의 신뢰성을 확인하기 위해 |
| 기간과 수집 범위 | 질문에 필요한 데이터가 포함되었는지 확인하기 위해 |

데이터 유형, 분석 역할과 표현 방식은 연결되어 있지만 서로 같은 개념은 아니다. 필드를 사용하기 전에 세 관점을 구분해 이해해야 한다.

---

## 10. 데이터 연결과 필드 배치의 전체 흐름

1. 답할 분석 질문을 정의한다.
2. 파일이나 데이터베이스 등의 데이터 원본을 연결한다.
3. 필드의 의미와 데이터 유형, 행의 단위를 확인한다.
4. 데이터를 나눌 Dimension을 정한다.
5. 집계할 Measure와 집계 방법을 정한다.
6. 불연속형·연속형 표현과 날짜 수준을 선택한다.
7. 선반과 마크 카드에 필드를 배치한다.
8. 뷰가 질문에 맞는 단위와 결과를 보여주는지 확인한다.

버튼 위치보다 중요한 것은 이 판단 과정을 이해하는 것이다. 같은 데이터로도 질문에 맞게 필드의 역할과 표현을 바꾸어 사용할 수 있어야 한다.

---

## 11. 핵심 정리

- Tableau에서는 연결한 데이터의 각 열이 필드로 나타난다.
- Dimension은 데이터를 나누는 기준이고, Measure는 집계하여 확인하는 값이다.
- 숫자로 저장된 고객 ID도 식별 기준이라면 Dimension으로 활용한다.
- Measure를 사용할 때는 합계·평균 등 집계 방법과 데이터 행의 단위를 확인한다.
- 불연속형은 구분된 항목을, 연속형은 이어지는 범위를 표현한다.
- 파란색은 불연속형, 초록색은 연속형을 나타낸다.
- Dimension / Measure와 Discrete / Continuous는 서로 다른 구분이다.
- 날짜는 같은 필드라도 목적에 따라 집계 수준과 표현 방식을 바꿀 수 있다.
- 데이터 연결 후 자료형과 의미를 확인하고 질문에 맞게 필드를 선택해야 한다.
