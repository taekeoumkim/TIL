# 2026-10-12 KPI 대시보드 구현과 인사이트 도출

## 1. 기획에서 구현과 의사결정으로 연결하기

KPI를 선정했다고 분석이 완성된 것은 아니다. 실제 데이터로 계산하고, 지표 정의와 결과가 일치하는지 검증한 뒤, 사용자가 문제 구간을 탐색할 수 있도록 표현해야 한다.

온라인 식료품몰의 매출 성장 정체를 분석한다면 전체 매출, 신규 고객 구매 전환율, 재구매율과 평균 주문 금액(AOV)을 함께 살펴볼 수 있다.

전체 과정은 **데이터 준비 → KPI 계산과 검증 → 대시보드 구성 → 결과 해석과 개선 제안**으로 이어진다.

---

## 2. KPI에 필요한 데이터 확인

| KPI | 필요한 정보 | 주요 데이터 |
|---|---|---|
| 전체 매출 | 주문ID, 금액, 주문일, 상태 | 주문 내역 |
| 신규 구매 전환율 | 고객ID, 가입일, 첫 유효 주문일 | 고객·주문 |
| 재구매율 | 고객ID, 주문ID와 주문일 | 고객별 구매 이력 |
| AOV | 유효 주문 금액과 고유 주문 수 | 주문 내역 |

컬럼이 있다는 사실만으로 충분하지 않다. 주문 취소와 환불 처리, 고객 식별과 관찰 기간 등 KPI 정의를 실제로 구현할 수 있는지 확인한다.

배송 기록은 배송 경험과 구매 행동의 관계를 추가로 탐색할 때 활용할 수 있지만, 주문과 다른 단위라는 점에 주의해야 한다.

---

## 3. 데이터 결합과 Granularity

**Granularity**는 한 행이 의미하는 단위이다.

| 테이블 | 한 행의 의미 | 식별 키 |
|---|---|---|
| 고객 | 고객 1명 | 고객ID |
| 주문 | 주문 1건 | 주문ID |
| 배송 | 배송 기록 1건 | 배송ID |

한 주문에 배송 기록이 여러 건이면 Join 후 주문 금액이 반복될 수 있다.

주문 금액이 50,000원, 30,000원, 40,000원이라면 실제 매출은 120,000원이다. 첫 주문의 배송 기록이 두 건이라면 단순 Join 결과에서는 50,000원이 두 번 나타나 합계가 170,000원으로 늘어날 수 있다.

실제 주문이 늘지 않았는데 매출이 커졌다면 Key의 중복과 일대다 결합을 확인해야 한다.

---

## 4. Relationship과 Join 선택 및 검증

| 방식 | 고려할 상황 |
|---|---|
| Relationship | 테이블별 구조와 세부 수준을 유지하며 분석 |
| Join | 행 수준의 명시적인 결합이 필요 |
| Union | 호환되는 구조의 월별·기간별 데이터 통합 |

관계를 사용한다고 모든 집계 오류가 자동으로 해결되는 것은 아니다. 연결 기준과 실제 결과를 확인한다. 필요하면 배송을 주문 단위로 먼저 요약하는 등 데이터 구조를 정리한다.

결합 전후에 행 수, 고유 주문 수, 매출 합계와 연결되지 않은 항목을 비교한다. 특히 COUNTD로 주문 수가 유지되어도 금액 합계는 중복될 수 있다.

## 5. KPI 정의를 계산 로직으로 바꾸기

| 지표 | 정의 예시 | 계산 단위 |
|---|---|---|
| 전체 매출 | 유효 주문 금액의 합계 | 주문 |
| 신규 구매 전환율 | 가입 후 30일 내 첫 구매 고객 / 해당 가입 코호트 | 고객 |
| 재구매율 | 첫 구매 후 90일 내 추가 구매 고객 / 해당 첫 구매 코호트 | 고객 |
| AOV | 유효 주문 매출 / 유효 주문 수 | 주문 |

30일과 90일은 사례의 기준이다. 분석 목적에 따라 달라질 수 있으며, 한번 정한 기준은 비교 대상에 일관되게 적용해야 한다.

전체 기간에 두 번 이상 구매한 고객 비율과 90일 재구매율도 다르다. 두 번째 구매가 90일 이후라면 전자에는 포함되지만 후자에는 포함되지 않는다.

## 6. 계산된 필드와 LOD 활용

유효 주문만 포함되고 한 주문이 한 행인 데이터에서 AOV는 다음과 같다.

```text
SUM([주문 금액]) / COUNTD([주문 ID])
```

120,000원의 매출과 3건의 주문이면 AOV는 40,000원이다. 데이터 결합으로 금액이 반복되면 이 식만으로 중복을 해결할 수는 없다.

고객별 최초 주문일은 FIXED LOD로 계산할 수 있다.

```text
{ FIXED [고객 ID] : MIN([주문일]) }
```

실제 최초 구매일로 사용하려면 유효 주문 기준을 반영해야 한다. 재구매율 구현에는 최초 구매일 외에도 추가 주문의 ID와 시점이 필요하다.

1. 고객별 유효 주문을 확인한다.
2. 최초 구매일을 구한다.
3. 첫 구매 이후의 추가 주문을 구분한다.
4. 90일 이내인지 판단한다.
5. 고객별 재구매 여부를 정의한다.
6. 코호트의 고유 고객 수를 분자와 분모로 계산한다.

같은 날의 추가 주문을 어떻게 처리할지도 정의해야 한다. 날짜만으로 첫 주문과 이후 주문을 항상 구분할 수 있는 것은 아니다.

## 7. 관찰 기간과 코호트 필터 구분

1월에 첫 구매한 고객을 분석해도 재구매 판단에는 이후 90일의 주문 이력이 필요하다.

| 조건 | 역할 |
|---|---|
| 첫 구매일이 1월 | 분석 대상 코호트 선택 |
| 첫 구매 후 90일의 주문 | 해당 고객의 재구매 판단 |

주문일을 1월로만 제한하면 필요한 이후 주문을 제거할 수 있다. **대상을 선택하는 조건과 행동 이력을 제한하는 조건은 다르다.**

첫 구매 후 90일이 지나지 않은 고객은 완전한 관찰 기회를 갖지 못한다. 기준일과 관찰 완료 여부를 확인하여 비교 가능한 집단을 선정한다.

FIXED와 필터의 실행 순서도 함께 검토한다. 최초 구매일이 필터로 잘려 재계산되면 고객의 코호트 분류가 달라질 수 있다.

---

## 8. 작은 데이터로 검산하기

고객 A와 D는 90일 이내 재구매, B는 90일 이후 재구매, C는 추가 구매가 없다고 가정하자. 모든 고객에게 90일의 관찰 기간이 확보되었다면 다음과 같다.

| 지표 | 결과 |
|---|---:|
| 전체 기간의 재구매 고객 | 3명 |
| 90일 내 재구매 고객 | 2명 |
| 첫 구매 고객 | 4명 |
| 90일 재구매율 | 50% |

Tableau 결과가 그럴듯한 범위에 있다는 이유만으로 정확하다고 판단해서는 안 된다. 원본 이력으로 직접 계산한 값과 비교한다.

| 검증 항목 | 확인 내용 |
|---|---|
| 정의 | 기획서와 계산식이 일치하는가? |
| 범위 | 기간과 유효 주문 기준이 맞는가? |
| 단위 | 고객과 주문을 혼동하지 않았는가? |
| 중복 | 결합으로 금액이 반복되지 않았는가? |
| 관찰 | 충분한 기간이 확보되었는가? |
| 필터 | 조건 변경 후에도 정의가 유지되는가? |

## 9. 전체 성과에서 상세 분석으로 배치

| 영역 | 지표와 표현 |
|---|---|
| 요약 | 매출·전환율·재구매율·AOV KPI 카드 |
| 변화 | 월별 매출, 코호트별 재구매율 라인 차트 |
| 집단 비교 | 지역·고객군별 지표 막대 차트 |
| 상세 | 선택 집단의 주문 행동과 성과 표 |

현재 값에는 과거 또는 목표와 같은 비교 기준을 제공한다. 재구매율 30%만으로는 변화나 목표 달성 여부를 알기 어렵다.

코호트별 비교는 같은 관찰 기간과 주문 처리 기준을 사용해야 한다. 화면 구성은 전체 성과, 변화, 문제 구간과 상세 정보로 자연스럽게 이어져야 한다.

## 10. 인터랙션과 KPI의 정확성

| 사용자 요구 | 활용 기능 |
|---|---|
| 특정 지역 선택 | Filter |
| 표시 지표 전환 | Parameter + Calculated Field |
| 고객군 선택 후 상세 분석 | Filter Action |
| 전체 집단 유지하며 강조 | Highlight Action |
| 상세 화면 이동 | Navigation과 조건 전달 구성 |

조건을 바꿀 때 차트가 움직이는 것만 확인하면 안 된다. KPI의 대상과 관찰 기간, 분자와 분모가 의도한 기준을 유지하는지 검증한다.

전체 결과, 특정 코호트, 특정 고객군을 차례로 확인하고 선택 해제 시 복귀 상태도 점검한다. 필요한 경우 직접 계산한 표와 비교한다.

## 11. KPI 변화에서 인사이트 도출

다음은 해석을 설명하기 위한 가상의 결과이다.

| KPI | 이전 | 최근 | 변화 |
|---|---:|---:|---|
| 월 매출 | 8,400만 원 | 8,500만 원 | 약 1.2% 증가 |
| 신규 구매 전환율 | 20% | 18% | 2%p 감소 |
| 90일 재구매율 | 35% | 30% | 5%p 감소 |
| AOV | 42,000원 | 42,000원 | 동일 |

관찰된 사실은 전환율과 재구매율의 하락, AOV 유지이다. 이를 근거로 구매 전환과 반복 구매 단계의 추가 분석이 필요하다고 판단할 수 있다.

하지만 재구매율 하락이 매출 정체의 원인이라고 확정할 수는 없다. 고객 구성, 유입 경로와 다른 변화도 확인해야 한다.

전체 변화에서 시작해 코호트와 고객군별 차이를 분석하는 Segmentation으로 문제 구간을 좁힌다.

## 12. 관찰·해석·가설·행동을 구분하기

| 구분 | 정리할 내용 |
|---|---|
| 관찰 | 어떤 지표가 언제 얼마나 변했는가? |
| 해석 | 비즈니스 문제에서 어떤 의미가 있는가? |
| 가설 | 무엇이 이 현상을 설명할 수 있는가? |
| 추가 검증 | 어떤 데이터와 실험이 필요한가? |
| 개선 제안 | 어떤 대상과 단계에 활동을 검토할 것인가? |

**Insight**는 패턴이나 차이를 비즈니스 문제와 연결한 해석이다. **Actionable Insight**는 의사결정이나 후속 행동으로 이어질 수 있는 해석이다.

“재구매율이 낮아졌다”에서 끝내기보다 어느 집단이 낮아졌는지와 다음에 확인할 사항을 구체화한다. 개선안을 제안하더라도 효과가 검증되었다고 표현하지 않으며, 적용 후 측정과 실험 계획을 함께 고려한다.

---

## 13. 프로젝트의 전체 흐름

1. 비즈니스 문제와 필요한 의사결정을 정의한다.
2. KPI 기획서의 대상·기간·계산 기준을 확인한다.
3. 데이터 단위와 연결 구조를 준비한다.
4. 계산된 필드와 LOD 등으로 지표를 구현한다.
5. 작은 표와 원본 데이터로 검산한다.
6. 질문에 맞는 차트와 레이아웃을 구성한다.
7. 필터·파라미터·Action을 연결한다.
8. 조건 변경 후 지표의 정확성을 검증한다.
9. 사실과 가설을 구분하여 인사이트를 정리한다.
10. 개선 방향과 추가 검증을 제안한다.

---

## 14. 핵심 정리

- KPI 구현은 데이터 준비부터 결과 해석까지 연결하는 과정이다.
- 테이블의 행 단위가 다르면 Join으로 금액이 반복될 수 있다.
- 지표별로 고객·주문 등 필요한 계산 단위를 확인한다.
- 전체 기간 재구매와 90일 재구매는 서로 다른 정의이다.
- 코호트 선택과 관찰에 필요한 주문 이력 범위를 구분한다.
- 계산식이 실행되어도 원본과 검산하여 정확성을 확인해야 한다.
- 대시보드는 전체 성과에서 집단별 상세 분석으로 연결한다.
- 필터와 Action 변경 후에도 KPI 정의가 유지되어야 한다.
- 인사이트는 관찰 사실을 비즈니스 문제에 연결하되 원인 가설과 구분한다.
- 개선 제안은 추가 검증과 실제 의사결정으로 이어져야 한다.

---

## 오늘의 한 문장

> KPI 대시보드의 완성은 차트가 표시되는 순간이 아니라, 지표의 정확성을 검증하고 변화의 의미를 해석하여 실행과 추가 검증의 방향을 제시할 때 이루어진다.
