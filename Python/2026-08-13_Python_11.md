## 디버깅 기초

### 디버깅(Debugging)이란?

프로그래밍을 하다 보면 예외 처리를 했더라도 프로그램이 강제 종료되지 않으면서 원하는 결과가 나오지 않는 **논리 에러**와 같은 문제가 발생할 수 있다.

이처럼 프로그램에서 **오류가 발생한 지점과 원인을 찾아 해결하는 과정**을 디버깅(Debugging)이라고 한다.

오늘은 Python의 **Traceback을 해석하는 방법**과 `print()`를 활용한 디버깅의 한계, 그리고 VS Code의 **Debug Cell, Breakpoint, Variables, Step Over, Step Into, Step Out, Continue**를 이용해 프로그램의 실행 흐름과 변수 상태를 확인하는 방법을 학습했다.

---

## 1. 에러 Traceback과 해석 방법

### 1.1 Traceback이란?

Traceback은 프로그램 실행 중 예외가 발생했을 때 Python 인터프리터가 출력하는 **공식 에러 리포트**이다.

프로그램이 멈추기 직전까지 함수들이 어떤 순서로 호출되었는지 그 경로를 역순으로 보여준다.

Traceback을 확인할 때는 **가장 아래쪽부터 위쪽으로 읽는 것**이 중요하다.

### Traceback 확인 순서

1. 가장 아래쪽에서 **예외 종류와 원인 메시지**를 확인한다.
2. 그 위쪽에서 오류가 발생한 **파일, 함수, 줄 번호**를 확인한다.
3. 함수가 어떤 순서로 호출되었는지 위쪽으로 역추적한다.
4. 오류가 발생한 값이 어디에서 전달되었는지도 확인한다.

예를 들어 다음과 같은 함수 호출 구조가 있다고 하자.

```python
def apply_discount(price):
    return price - discount_amount

def calculate_payment(price):
    return apply_discount(price)

def create_order():
    final_price = calculate_payment(50000)
    print(final_price)

create_order()
```

`discount_amount`가 정의되어 있지 않기 때문에 다음과 같은 오류가 발생할 수 있다.

```text
NameError: name 'discount_amount' is not defined
```

이때 가장 먼저 마지막 줄의 `NameError`를 확인하면 `discount_amount`라는 변수가 정의되지 않았다는 것을 알 수 있다.

그다음 호출 경로를 확인하면 다음과 같은 흐름으로 실행되었다는 것을 알 수 있다.

```text
create_order()
    ↓
calculate_payment()
    ↓
apply_discount()
    ↓
discount_amount에서 오류 발생
```

### 핵심

> Traceback은 **아래에서 위로** 읽으면서 최종 예외 → 오류 위치 → 호출 경로 순서로 확인한다.

## 2. 임시 `print()`를 통한 디버깅

가장 간단하게 변수의 상태를 확인하는 방법은 코드 중간에 `print()`를 추가하는 것이다.

예를 들어 재고가 주문에 따라 어떻게 변하는지 확인할 수 있다.

```python
stock = 20
orders = [2, 3, 4]

for order in orders:
    stock = stock - order
    print(f"주문 수량: {order}, 현재 재고: {stock}")

print(f"최종 재고: {stock}")
```

실행 결과는 다음과 같다.

```text
주문 수량: 2, 현재 재고: 18
주문 수량: 3, 현재 재고: 15
주문 수량: 4, 현재 재고: 11
최종 재고: 11
```

이처럼 `print()`를 사용하면 변수 값이

```text
20 → 18 → 15 → 11
```

로 변화하는 과정을 확인할 수 있다.

### `print()` 디버깅의 한계

간단한 프로그램에서는 유용하지만 프로그램이 복잡해질수록 한계가 있다.

- 반복문이 많으면 출력 결과가 지나치게 많아진다.
- 디버깅을 위해 추가한 `print()`를 나중에 직접 삭제해야 한다.
- 특정 코드에서 프로그램을 멈추기 어렵다.
- 특정 시점의 여러 변수 상태를 한 번에 확인하기 어렵다.

따라서 복잡한 프로그램에서는 전문적인 디버거를 사용하는 것이 효율적이다.

## 3. VS Code Debugger

VS Code에서는 주피터 노트북(`.ipynb`)의 코드 셀도 디버깅할 수 있다.

일반적인 코드 실행에서는 최종 결과만 확인할 수 있지만, **Debug Cell**을 사용하면 프로그램이 실행되는 과정을 단계적으로 확인할 수 있다.

예를 들어 다음 코드가 있다고 하자.

```python
product_price = 12000
product_count = 3

total_price = product_price * product_count

print(total_price)
```

일반 실행에서는 다음 결과만 확인한다.

```text
36000
```

반면 Debug Cell을 사용하면 실행 과정에서 다음 변수들의 상태를 확인할 수 있다.

```text
product_price
product_count
total_price
```

즉, 디버거는 단순히 **최종 결과를 확인하는 도구가 아니라 결과가 만들어지는 과정을 확인하는 도구**라고 볼 수 있다.

---

## 4. Python Debugger와 Debug Cell

주피터 노트북에서 Debug Cell을 사용하기 위해서는 VS Code의 **Python Debugger** 확장 기능이 필요하다.

설치 후 주피터 노트북 코드 셀의 일반 실행 버튼 옆에서 `Debug Cell`을 선택하면 비주얼 디버깅 모드를 사용할 수 있다.

이를 이용하면 코드의 실행 흐름을 단계별로 제어하고 변수 상태를 확인할 수 있다.

---

## 5. Breakpoint와 Variables

### 5.1 Breakpoint

Breakpoint(중단점)는 특정 코드가 실행되기 전에 **프로그램의 실행을 일시 정지시키는 기능**이다.

VS Code에서는 소스코드의 왼쪽 여백을 클릭하여 중단점을 설정할 수 있다.

예를 들어 다음 코드에서 계산 직전에 프로그램을 멈출 수 있다.

```python
price = 50000
discount = 10000

final_price = price - discount

print(final_price)
```

`final_price = price - discount` 줄에 Breakpoint를 설정하면 해당 코드가 실행되기 직전에 프로그램이 멈춘다.

---

### 5.2 Variables 패널

프로그램이 Breakpoint에서 멈추면 **Variables 패널**에서 현재 실행 시점에 존재하는 변수와 값을 확인할 수 있다.

예를 들어 다음과 같이 확인할 수 있다.

```text
price     50000
discount  10000
```

아직 계산이 실행되기 전이므로 `final_price`가 어떻게 계산되는지 확인하기 전에 입력값을 먼저 검증할 수 있다.

이후 코드를 한 단계 실행하면 다음과 같이 결과가 만들어지는 과정을 확인할 수 있다.

```text
final_price = 40000
```

### 핵심

- **Breakpoint**: 특정 코드에서 실행을 멈춘다.
- **Variables**: 현재 시점의 변수와 값을 확인한다.
- `print()`를 추가하지 않고도 변수 상태를 확인할 수 있다.

## 6. 디버거의 흐름 제어 명령어

VS Code 디버거에서는 프로그램을 한 단계씩 실행하면서 함수 내부로 들어갈지 여부를 선택할 수 있다.

### 6.1 Step Over

현재 줄을 실행하고 다음 줄로 이동한다.

현재 줄에 함수 호출이 있어도 **함수 내부로 들어가지 않고** 함수 실행 결과를 받은 뒤 다음 줄로 이동한다.

```text
Step Over
→ 현재 함수 내부는 확인하지 않음
→ 함수 실행 결과만 받고 다음 줄로 이동
```

---

### 6.2 Step Into

현재 줄에 함수 호출이 있다면 **호출된 함수 내부로 들어간다.**

함수의 내부 동작을 자세하게 확인하고 싶을 때 사용한다.

```text
Step Into
→ 호출된 함수 내부로 이동
→ 함수의 실행 과정을 단계별로 확인
```

---

### 6.3 Step Out

현재 함수 내부에서 더 이상 확인할 필요가 없을 때 사용한다.

현재 실행 중인 함수의 남은 코드를 실행한 뒤, 해당 함수를 호출했던 위치로 돌아간다.

```text
Step Out
→ 현재 함수 실행 완료
→ 호출한 위치로 복귀
```

---

### 6.4 Continue

현재 위치에서 **다음 Breakpoint를 만날 때까지 프로그램을 계속 실행**한다.

```text
Continue
→ 다음 Breakpoint까지 계속 실행
```

---

## 7. Step Over와 Step Into 비교

다음과 같은 코드가 있다고 하자.

```python
def calculate_delivery(price):
    delivery_fee = 3000
    return price + delivery_fee

product_price = 20000
final_price = calculate_delivery(product_price)

print(final_price)
```

`final_price = calculate_delivery(product_price)`에서 프로그램이 멈췄다고 가정한다.

### Step Into

`calculate_delivery()` 함수 내부로 들어간다.

```text
calculate_delivery()
    ↓
delivery_fee = 3000
    ↓
return price + delivery_fee
```

함수 내부의 상세한 동작을 확인할 수 있다.

### Step Over

함수 내부로 들어가지 않는다.

```text
calculate_delivery(product_price)
    ↓
계산 결과를 반환
    ↓
다음 줄로 이동
```

함수 내부가 이미 정상적으로 동작한다고 판단되거나 내부 과정이 필요하지 않을 때 사용할 수 있다.

## 8. Traceback과 디버거를 함께 활용하기

실제 디버깅에서는 Traceback과 디버거를 함께 사용할 수 있다.

예를 들어 주문 상품의 평균 가격을 계산하는 코드가 있다고 하자.

```python
def calculate_unit_price(total_price, quantity):
    return total_price / quantity

def create_order_summary():
    total_price = 30000
    quantity = 0

    unit_price = calculate_unit_price(total_price, quantity)

    print(unit_price)

create_order_summary()
```

실행하면 다음과 같은 오류가 발생한다.

```text
ZeroDivisionError: division by zero
```

먼저 Traceback의 마지막 줄을 확인하면 `0`으로 나누는 문제가 발생했다는 것을 알 수 있다.

그다음 호출 경로를 확인한다.

```text
create_order_summary()
    ↓
calculate_unit_price()
    ↓
total_price / quantity
```

그리고 `quantity` 값이 왜 `0`이 되었는지를 추가로 확인해야 한다.

### 디버깅 과정

```text
1. Traceback의 마지막 줄 확인
        ↓
2. 예외 종류와 원인 확인
        ↓
3. 오류가 발생한 코드 위치 확인
        ↓
4. 함수 호출 경로 역추적
        ↓
5. 문제가 되는 변수의 값 확인
        ↓
6. Breakpoint 설정
        ↓
7. Variables에서 변수 상태 확인
        ↓
8. Step Over / Step Into 등을 이용하여 실행 흐름 확인
        ↓
9. 원인 수정
```

## 9. 오늘 배운 내용 정리

### Traceback

- Python이 출력하는 공식 에러 리포트
- 오류가 발생하기까지의 함수 호출 경로를 보여준다.
- **가장 아래쪽부터 위쪽으로 읽는다.**
- 마지막 줄에서 예외 종류와 직접적인 원인을 확인한다.
- 위쪽으로 올라가면서 오류 발생 위치와 호출 경로를 확인한다.

### `print()` 디버깅

- 변수의 중간 값을 빠르게 확인할 수 있다.
- 간단한 프로그램에서는 유용하다.
- 반복문이나 복잡한 프로그램에서는 출력량이 많아질 수 있다.
- 디버깅 후 임시 `print()`를 직접 제거해야 한다.

### VS Code Debugger

| 기능 | 역할 |
| --- | --- |
| Debug Cell | 주피터 노트북 셀을 디버깅 |
| Breakpoint | 특정 코드에서 실행을 일시 정지 |
| Variables | 현재 변수와 값을 확인 |
| Step Over | 함수 내부로 들어가지 않고 다음 단계로 이동 |
| Step Into | 호출된 함수 내부로 이동 |
| Step Out | 현재 함수를 빠져나와 호출 위치로 복귀 |
| Continue | 다음 Breakpoint까지 계속 실행 |

## 10. 느낀 점

오늘 학습을 통해 에러가 발생했을 때 단순히 코드를 처음부터 끝까지 확인하는 것보다 **Traceback을 이용해 오류가 발생한 위치와 호출 경로를 먼저 좁히는 것이 중요하다**는 것을 알게 되었다.

특히 Traceback을 **아래에서 위로 읽는 방법**을 익힌 것이 가장 중요했다.

또한 지금까지는 문제가 발생하면 `print()`를 추가해서 변수 값을 확인하는 방법을 주로 생각했는데, VS Code Debugger를 사용하면 코드를 수정하지 않고도 Breakpoint에서 프로그램을 멈추고 Variables 패널을 통해 현재 변수 상태를 확인할 수 있다는 점을 배웠다.

앞으로 Python으로 데이터 분석 코드를 작성할 때 오류가 발생하면 무작정 코드를 수정하기보다,

```text
Traceback 확인
→ 오류 위치 파악
→ 호출 경로 확인
→ 변수 상태 확인
→ Debugger로 실행 흐름 검증
→ 원인 수정
```

순서로 문제를 해결하는 습관을 만들어야겠다.
