## 클래스(Class)

### 1. 객체지향 프로그래밍(OOP)

프로그램의 규모가 커지면 데이터와 함수가 복잡하게 얽혀 관리하기 어려워질 수 있다. 객체지향 프로그래밍(OOP)은 서로 관련 있는 **데이터와 기능을 객체 단위로 묶어 관리**하는 방식이다.

#### 절차지향과 객체지향의 차이

- **절차지향**: 데이터와 함수를 분리하고, 실행할 명령의 순서를 중심으로 프로그램을 구성한다.
- **객체지향**: 관련된 상태(데이터)와 행동(메서드)을 하나의 객체로 묶어 관리한다.

예를 들어 상품의 이름과 재고를 관리할 때, 객체지향 방식에서는 `Product`라는 클래스로 상품의 상태와 판매 기능을 함께 관리할 수 있다.

```python
class Product:
    def __init__(self, name, stock):
        self.name = name
        self.stock = stock

    def sell(self):
        self.stock -= 1


product = Product("노트북", 10)
product.sell()

print(f"{product.name} 재고: {product.stock}개")
# 노트북 재고: 9개
```

### 2. 클래스와 인스턴스

클래스는 객체를 만들기 위한 **설계도 또는 틀**이고, 인스턴스는 클래스를 바탕으로 실제 생성된 객체이다.

```python
class Member:
    pass

member_a = Member()
member_b = Member()

print(type(member_a))
# <class '__main__.Member'>

print(member_a is member_b)
# False
```

하나의 클래스로 여러 인스턴스를 생성할 수 있으며, 생성된 인스턴스들은 서로 다른 객체이다.

- 클래스 → 객체를 만들기 위한 설계도
- 인스턴스 → 클래스를 바탕으로 실제 생성된 객체
- 하나의 클래스 → 여러 개의 서로 다른 인스턴스 생성 가능

---

### 3. `__init__` 생성자

`__init__`은 인스턴스가 생성될 때 자동으로 호출되는 초기화 메서드이다.

객체가 처음 가져야 할 데이터를 설정하는 데 주로 사용한다.

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price


product = Product("무선 마우스", 30000)

print(product.name)
print(product.price)
```

`Product("무선 마우스", 30000)`을 실행하면 새로운 객체가 만들어지고 `__init__` 메서드가 자동으로 호출된다.

---

### 4. `self`

`self`는 **현재 메서드를 호출한 인스턴스 자신**을 가리킨다.

클래스 내부의 메서드에서는 첫 번째 매개변수로 `self`를 지정하며, `self.속성명` 형태로 현재 객체가 가진 속성에 접근할 수 있다.

```python
class Order:
    def __init__(self, order_number):
        self.order_number = order_number

    def show_order(self):
        print(f"현재 주문: {self.order_number}")


order_a = Order("A001")
order_b = Order("B002")

order_a.show_order()
# 현재 주문: A001

order_b.show_order()
# 현재 주문: B002
```

`order_a.show_order()`를 호출하면 `self`는 `order_a`를 가리키고, `order_b.show_order()`를 호출하면 `self`는 `order_b`를 가리킨다.

따라서 같은 메서드 정의를 여러 객체가 각자의 데이터에 맞게 사용할 수 있다.

### 5. 속성(Attribute)과 인스턴스 메서드(Method)

객체는 **상태와 행동**을 가진다.

- **속성(Attribute)**: 객체가 가지고 있는 상태나 데이터
- **인스턴스 메서드(Instance Method)**: 객체의 데이터를 조회하거나 변경하는 기능

```python
class Character:
    def __init__(self, name):
        self.name = name
        self.hp = 50

    def heal(self):
        self.hp += 20


character = Character("마법사")

print(character.hp)
# 50

character.heal()

print(f"{character.name}의 체력: {character.hp}")
# 마법사의 체력: 70
```

`name`과 `hp`는 객체의 속성이고, `heal()`은 객체의 `hp`를 변경하는 인스턴스 메서드이다.

특히 `self.hp += 20`과 같이 작성하면 **메서드를 호출한 현재 인스턴스의 데이터만 변경**된다.

### 6. 클래스 설계와 객체의 독립성

하나의 클래스로 여러 객체를 생성하더라도 각 인스턴스의 속성은 서로 독립적으로 관리된다.

```python
class GameCharacter:
    def __init__(self, name, hp):
        self.name = name
        self.hp = hp

    def take_damage(self, damage):
        self.hp -= damage
        print(f"{self.name} 체력: {self.hp}")


warrior = GameCharacter("전사", 100)
wizard = GameCharacter("마법사", 80)

warrior.take_damage(30)

print(f"전사 최종 체력: {warrior.hp}")
# 전사 최종 체력: 70

print(f"마법사 최종 체력: {wizard.hp}")
# 마법사 최종 체력: 80
```

`warrior`의 `hp`를 변경해도 `wizard`의 `hp`에는 영향을 주지 않는다.

즉, **같은 클래스로 만들어진 객체라도 각자의 속성은 독립적인 상태로 관리된다.**

### 7. BankAccount 클래스

클래스의 개념을 실제 객체 설계에 적용하면 은행 계좌처럼 상태와 기능이 함께 필요한 대상을 표현할 수 있다.

```python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount
        return self.balance

    def withdraw(self, amount):
        if self.balance >= amount:
            self.balance -= amount
        else:
            print("잔액이 부족합니다.")
        return self.balance
```

여기서

- `owner`, `balance` → 객체의 상태를 나타내는 속성
- `deposit()` → 잔액을 증가시키는 기능
- `withdraw()` → 잔액을 감소시키는 기능

으로 역할을 나눌 수 있다.

서로 다른 계좌를 생성하면 각각의 잔액이 독립적으로 관리된다.

```python
account_chulsoo = BankAccount("김철수", 5000)
account_younghee = BankAccount("이영희", 10000)

account_chulsoo.deposit(2000)
account_younghee.withdraw(3000)

print(account_chulsoo.balance)
# 7000

print(account_younghee.balance)
# 7000
```

### 8. `__str__`과 `__repr__`

클래스에서는 객체를 출력하거나 확인할 때 사용할 수 있는 특수 메서드도 정의할 수 있다.

#### `__str__`

`print(객체)`처럼 객체를 출력할 때 사용자가 보기 편한 형태의 문자열을 반환하는 데 사용한다.

```python
def __str__(self):
    return f"{self.owner}님의 계좌 (현재 잔액: {self.balance}원)"
```

#### `__repr__`

주피터 노트북 셀에서 객체를 직접 조회하거나 디버거 등에서 객체의 상태를 확인할 때 개발자가 데이터를 파악하기 위한 표현을 제공한다.

```python
def __repr__(self):
    return f"BankAccount(owner='{self.owner}', balance={self.balance})"
```

## 오늘 배운 내용 정리

1. **객체지향 프로그래밍(OOP)**은 관련된 상태와 행동을 객체 단위로 묶어 관리한다.
2. **클래스**는 객체를 만들기 위한 설계도이고, **인스턴스**는 클래스를 바탕으로 생성된 실제 객체이다.
3. `__init__`은 인스턴스가 생성될 때 자동으로 호출되며 객체의 초기 상태를 설정한다.
4. `self`는 현재 메서드를 호출한 인스턴스 자신을 의미한다.
5. **속성(Attribute)**은 객체의 상태를 나타내고, **인스턴스 메서드(Method)**는 객체의 데이터를 조회하거나 변경한다.
6. 같은 클래스로 여러 인스턴스를 만들 수 있으며, 각 인스턴스의 속성은 독립적으로 관리된다.
7. `__str__`과 `__repr__`을 활용하면 객체를 사람이 읽기 좋은 형태 또는 개발자가 상태를 파악하기 좋은 형태로 표현할 수 있다.

## 느낀 점

오늘은 단순히 변수와 함수를 따로 사용하는 것에서 벗어나, **데이터와 데이터를 다루는 기능을 하나의 객체로 묶는 방법**을 배웠다.

특히 `self`가 현재 메서드를 호출한 인스턴스를 가리킨다는 점과, 하나의 클래스로 여러 객체를 만들어도 각 객체의 데이터가 독립적으로 관리된다는 점이 중요하다고 느꼈다.

`BankAccount`처럼 실제 프로그램에서 관리해야 하는 대상을 클래스로 설계하면 데이터와 기능의 관계를 명확하게 만들 수 있기 때문에, 앞으로 객체지향 방식으로 코드를 작성할 때 클래스의 역할과 객체의 책임을 먼저 생각해보는 연습이 필요하겠다.
