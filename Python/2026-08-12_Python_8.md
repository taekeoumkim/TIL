## 1. 함수의 일급 객체와 고차 함수

### 1.1 일급 객체(First-class Object)

파이썬에서 함수는 단순한 명령문의 집합이 아니라 **데이터처럼 다룰 수 있는 일급 객체**의 특성을 가진다.

함수는 다음과 같이 사용할 수 있다.

- 변수에 대입할 수 있다.
- 다른 함수의 인수로 전달할 수 있다.
- 함수의 결과값으로 반환할 수 있다.

```python
def greet(name):
    return f"안녕하세요, {name}님!"

my_func = greet

print(my_func("코딩"))
```

출력:

```text
안녕하세요, 코딩님!
```

`greet`를 변수 `my_func`에 대입했기 때문에 `my_func()`를 통해 같은 함수를 실행할 수 있다.

### 1.2 고차 함수(Higher-order Function)

고차 함수는 다음 두 가지 조건 중 하나 이상을 만족하는 함수를 의미한다.

1. 다른 함수를 인수로 전달받는다.
2. 다른 함수를 결과값으로 반환한다.

#### 함수를 인수로 전달

```python
def greet(name):
    return f"안녕하세요, {name}님!"

def call_function(func, user_name):
    return func(user_name)

result = call_function(greet, "스파르타")

print(result)
```

출력:

```text
안녕하세요, 스파르타님!
```

`call_function()`에 `greet` 함수 자체를 전달하고, 내부에서 `func(user_name)` 형태로 실행한다.

#### 함수를 결과로 반환

```python
def get_greeter():
    return greet

my_func = get_greeter()

print(my_func("코딩"))
```

`get_greeter()`는 `greet` 함수 자체를 반환한다.

## 2. 클로저(Closure)

### 2.1 클로저란?

클로저는 **내부 함수가 자신을 둘러싼 외부 함수의 변수를 기억한 채로 반환되어 독립적으로 유지되는 구조**이다.

일반적으로 함수의 지역 변수는 함수 실행이 끝나면 더 이상 사용할 수 있지만, 클로저에서는 내부 함수가 외부 함수의 변수를 참조하고 있기 때문에 해당 환경이 유지된다.

이를 활용하면 **전역 변수를 사용하지 않고 특정 함수만의 데이터를 유지**할 수 있다.

### 2.2 클로저 동작 방식

```python
def make_multiplier(n):
    def multiply(x):
        return x * n

    return multiply

times_three = make_multiplier(3)
times_five = make_multiplier(5)

print(times_three(10))
print(times_five(10))
```

출력:

```text
30
50
```

`make_multiplier(3)`을 호출하면 내부 함수 `multiply`가 `n = 3`인 환경을 기억한다.

`make_multiplier(5)`는 `n = 5`인 환경을 기억한다.

```text
make_multiplier(3)
        ↓
multiply 함수 생성
        ↓
n = 3 기억
        ↓
times_three
```

```text
make_multiplier(5)
        ↓
multiply 함수 생성
        ↓
n = 5 기억
        ↓
times_five
```

외부 함수인 `make_multiplier()`의 실행이 종료된 이후에도 각각의 함수는 자신이 생성될 당시의 `n` 값을 기억한다.

## 3. 데코레이터(Decorator)

### 3.1 데코레이터란?

데코레이터는 **기존 함수의 소스코드를 직접 수정하지 않고 함수 호출 전후에 부가 기능을 추가하여 기능을 확장하는 구조**이다.

여러 함수에 공통적으로 필요한 로그 기록, 실행 시간 측정, 권한 검사 등의 기능을 별도로 관리할 때 활용할 수 있다.

### 3.2 데코레이터의 동작 원리

데코레이터는 **고차 함수와 클로저를 기반으로 동작**한다.

```text
원본 함수
   ↓
데코레이터에 전달
   ↓
wrapper 함수 생성
   ↓
부가 기능 + 원본 함수 실행
   ↓
wrapper 반환
```

```python
def display_decorator(original_function):
    def wrapper():
        print("--- [데코레이터] 함수 실행을 시작합니다 ---")

        original_function()

        print("--- [데코레이터] 함수 실행이 완료되었습니다 ---")

    return wrapper


def core_logic():
    print("핵심 비즈니스 로직을 구현 중입니다.")


decorated_logic = display_decorator(core_logic)

decorated_logic()
```

원본 함수 `core_logic()`을 데코레이터에 전달하면 `wrapper`가 생성되고 반환된다. 이후 `decorated_logic()`을 호출하면 `wrapper`가 실행되면서 원본 함수 전후에 부가 기능이 수행된다.

## 4. `@` 문법을 이용한 데코레이터

직접 다음과 같이 작성할 수도 있다.

```python
decorated_logic = display_decorator(core_logic)
```

하지만 파이썬에서는 `@데코레이터이름` 문법을 이용하여 데코레이터 적용을 간결하게 표현할 수 있다.

```python
@display_decorator
def simple_task():
    print("간단한 업무 처리를 수행합니다.")

simple_task()
```

`@display_decorator`는 다음과 같은 연결을 선언적으로 표현한 것이다.

```python
simple_task = display_decorator(simple_task)
```

따라서 함수 정의부만 보더라도 어떤 데코레이터가 적용되었는지 쉽게 확인할 수 있다.

## 5. 실행 성능을 측정하는 `@timer` 데코레이터

학습 자료에서는 `time` 모듈을 활용하여 함수가 시작되고 완료될 때까지 걸린 시간을 측정하는 `@timer` 데코레이터를 구현했다.

```python
import time

def timer(original_func):
    def wrapper(*args, **kwargs):
        start_time = time.time()

        result = original_func(*args, **kwargs)

        end_time = time.time()

        process_time = end_time - start_time

        print(
            f"[{original_func.__name__}] "
            f"함수 총 소요시간: {process_time:.6f}초"
        )

        return result

    return wrapper
```

여기서 `*args`, `**kwargs`를 사용하면 다양한 형태의 인자를 전달받아 원본 함수에 그대로 전달할 수 있다.

```python
result = original_func(*args, **kwargs)
```

### 5.1 `@timer` 사용

```python
@timer
def heavy_calculation(n):
    print(f"{n}까지의 정수 합산 반복 루프를 가동합니다.")

    total_sum = sum(range(1, n + 1))

    return total_sum


calc_result = heavy_calculation(5000000)

print(f"최종 연산 결과값: {calc_result}")
```

실행 흐름:

```text
heavy_calculation() 호출
        ↓
timer의 wrapper 실행
        ↓
start_time 기록
        ↓
heavy_calculation() 실행
        ↓
end_time 기록
        ↓
실행 시간 계산
        ↓
실행 시간 출력
        ↓
원본 함수의 결과 반환
```

학습 자료에서는 `heavy_calculation(5000000)`의 최종 연산 결과값이 `12500002500000`으로 반환된다.

## 6. 자동 로깅(Logging) 데코레이터

데코레이터를 이용하면 함수 호출 정보를 자동으로 기록할 수도 있다.

학습 자료의 `auto_logger`는 다음 정보를 출력한다.

- 호출된 함수 이름
- 위치 인수
- 키워드 인수
- 함수 실행 종료 여부

```python
def auto_logger(original_func):
    def wrapper(*args, **kwargs):
        print(f"▶ [LOG] 호출된 함수명: {original_func.__name__}")

        print(
            f"▶ [LOG] 주입된 인수 데이터: "
            f"위치인수={args}, 키워드인수={kwargs}"
        )

        result = original_func(*args, **kwargs)

        print(
            f"◀ [LOG] {original_func.__name__} "
            f"함수의 정상 연산이 종료되었습니다."
        )

        return result

    return wrapper
```

### 6.1 `@auto_logger` 적용

```python
@auto_logger
def login_process(user_id, password):
    if user_id == "admin" and password == "1234":
        return "로그인 성공"
    else:
        return "로그인 실패"


login_status = login_process(
    "admin",
    password="password99"
)

print(f"결과: {login_status}")
```

`login_process()`가 호출되면 `auto_logger`의 `wrapper`가 먼저 실행된다. 함수 이름과 전달된 인수를 기록한 뒤 원본 함수가 실행되고, 마지막에 종료 로그가 출력된다.

입력된 비밀번호가 `"password99"`이므로 최종 결과는 `로그인 실패`이다.

## 7. 클로저와 데코레이터의 관계

오늘 배운 개념은 서로 연결되어 있다.

```text
일급 객체
   ↓
함수를 변수에 저장 / 전달 / 반환
   ↓
고차 함수
   ↓
함수를 인수로 받고 새로운 함수를 반환
   ↓
클로저
   ↓
외부 함수의 환경을 기억하는 내부 함수
   ↓
데코레이터
   ↓
원본 함수를 감싸 새로운 기능을 추가
```

데코레이터는 원본 함수를 인수로 받고 `wrapper` 함수를 만들어 반환한다. 이때 `wrapper`는 외부 함수의 `original_func`를 기억하기 때문에 클로저의 특성이 활용된다.

따라서 **일급 객체 → 고차 함수 → 클로저 → 데코레이터**가 서로 연결된 개념이라는 것을 이해하는 것이 중요하다.

## 8. 핵심 정리

### 일급 객체

- 파이썬의 함수는 데이터처럼 다룰 수 있다.
- 변수에 대입할 수 있다.
- 다른 함수의 인수로 전달할 수 있다.
- 다른 함수의 결과로 반환할 수 있다.

### 고차 함수

- 다른 함수를 인수로 받을 수 있다.
- 다른 함수를 반환할 수 있다.

### 클로저

- 내부 함수가 외부 함수의 변수를 기억한다.
- 외부 함수가 종료된 이후에도 기억한 환경을 유지한다.
- 전역 변수를 사용하지 않고 상태를 유지하는 데 활용할 수 있다.

### 데코레이터

- 기존 함수의 소스코드를 수정하지 않고 기능을 확장할 수 있다.
- 원본 함수를 인수로 받아 `wrapper` 함수를 생성하고 반환한다.
- `@데코레이터이름` 문법으로 간결하게 적용할 수 있다.
- 로깅, 실행 시간 측정, 권한 검사 등의 공통 기능에 활용할 수 있다.

## 9. 오늘 배운 내용에서 느낀 점

오늘은 이전에 배운 **일급 객체와 고차 함수**가 실제로 클로저와 데코레이터에서 어떻게 활용되는지 연결해서 학습했다.

특히 클로저에서 외부 함수가 종료된 이후에도 내부 함수가 외부 변수의 값을 기억한다는 점이 인상적이었다. 단순히 함수의 실행 결과를 반환하는 것이 아니라 **함수와 함수가 기억하고 있는 환경을 함께 유지할 수 있다는 개념**을 이해하는 것이 중요하다고 느꼈다.

데코레이터는 처음에는 문법이 복잡해 보였지만, `원본 함수 → 데코레이터 → wrapper → 원본 함수 실행`의 흐름으로 생각하니 구조를 이해하기 쉬웠다.

또한 `@timer`와 `@auto_logger` 예제를 통해 데코레이터가 단순한 문법이 아니라 실제 개발에서 **여러 함수에 반복적으로 필요한 기능을 한 곳에서 관리하고 적용할 수 있는 방법**이라는 것을 알게 되었다.

앞으로 데이터사이언스를 공부하면서 코드가 복잡해질수록 함수의 역할과 공통 기능을 분리하는 것이 중요할 것 같다. 오늘 배운 클로저와 데코레이터의 원리를 직접 여러 번 작성해 보면서 익숙하게 만들어야겠다.
