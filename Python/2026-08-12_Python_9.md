## 📚 오늘 배운 내용

### 1. 오픈소스 생태계와 의존성 관리

현대적인 Python 개발에서는 필요한 기능을 직접 구현하기보다 이미 만들어진 오픈소스 패키지를 가져와 프로젝트에 활용한다.

Python의 대표적인 중앙 저장소인 **PyPI(Python Package Index)**에는 `pandas`, `matplotlib` 등 다양한 패키지가 등록되어 있으며, 패키지 관리 도구를 통해 필요한 패키지를 프로젝트에 추가할 수 있다.

#### 의존성(Dependency)이란?

프로젝트가 정상적으로 동작하기 위해 필요한 외부 패키지와 그 관계를 의미한다.

예를 들어 다음과 같은 구조가 있을 수 있다.

```text
내 프로젝트
  ↓
A 패키지
  ↓
B 패키지
```

내가 직접 A 패키지를 설치했더라도 A가 B를 필요로 한다면 B 역시 프로젝트의 의존성으로 관리되어야 한다.

따라서 패키지 관리 도구는 직접 추가한 패키지뿐만 아니라 그 패키지가 필요로 하는 다른 패키지까지 추적하고 관리한다.

---

### 2. `uv add`를 활용한 선언적 의존성 관리

`uv add`는 단순히 패키지를 다운로드하는 명령이 아니라 **프로젝트가 어떤 외부 패키지를 사용하는지 선언하고 관리하는 명령**이다.

```bash
uv add pandas
```

여러 패키지를 한 번에 추가할 수도 있다.

```bash
uv add pandas matplotlib
```

`uv add`를 실행하면 다음 과정이 이루어진다.

```text
uv add pandas
    ↓
필요한 패키지 확인
    ↓
관련 의존성 확인
    ↓
프로젝트 환경에 설치
    ↓
프로젝트 의존성 정보 갱신
```

기존의 `pip` 방식과 달리 uv는 프로젝트의 의존성을 명시적으로 관리하는 구조를 사용한다.

또한 uv는 Rust 기반의 고속 병렬 알고리즘을 사용하여 의존성 그래프를 식별하고 패키지를 다운로드하기 때문에 빠르고 안정적인 의존성 관리를 지원한다.

---

### 3. `pyproject.toml`의 역할

`pyproject.toml`은 **프로젝트가 어떤 패키지를 필요로 하는지 기록하는 명세 파일**이다.

예를 들어 `pandas`와 `matplotlib`을 사용한다면 의존성 정보가 다음과 같이 기록될 수 있다.

```toml
[project]
dependencies = [
    "matplotlib>=3.10.0",
    "pandas>=2.3.0",
]
```

직접 파일을 수정할 수도 있지만 `uv add`를 사용하면 패키지를 추가하는 과정에서 `pyproject.toml`의 의존성 정보가 자동으로 갱신된다.

```text
uv add pandas
    ↓
패키지 추가
    ↓
pyproject.toml 갱신
    ↓
"이 프로젝트는 pandas가 필요함" 기록
```

따라서 `pyproject.toml`을 확인하면 현재 프로젝트가 어떤 외부 패키지를 필요로 하는지 파악할 수 있다.

---

### 4. `uv.lock`의 역할

`pyproject.toml`이 **필요한 패키지와 버전 조건을 정의하는 명세서**라면, `uv.lock`은 **실제로 해결된 정확한 패키지 버전과 의존성 정보를 기록하는 잠금 파일**이다.

둘의 차이를 정리하면 다음과 같다.

| 파일 | 역할 |
| --- | --- |
| `pyproject.toml` | 프로젝트가 필요로 하는 패키지와 버전 조건을 선언 |
| `uv.lock` | 실제로 해결된 정확한 패키지 버전과 의존성 정보를 고정 |

예를 들어 다음과 같이 선언할 수 있다.

```toml
pandas>=2.0
```

이때 `uv.lock`에는 실제 사용되는 정확한 버전과 패키지의 고유 Hash 등의 정보가 기록된다.

이를 통해 여러 개발자가 같은 프로젝트를 사용할 때 서로 다른 패키지 버전이 설치되는 **버전 충돌 문제를 방지**할 수 있다.

---

### 5. `uv sync`를 통한 환경 복원

`uv.lock`은 프로젝트의 의존성 환경을 재현하기 위한 스냅샷 역할을 한다.

Git에서 프로젝트를 내려받았거나 기존 가상환경이 삭제된 경우에도 `pyproject.toml`과 `uv.lock`이 있다면 다음 명령으로 환경을 다시 구성할 수 있다.

```bash
uv sync
```

동작 과정은 다음과 같다.

```text
프로젝트 다운로드
    ↓
pyproject.toml + uv.lock 확인
    ↓
uv sync
    ↓
프로젝트 실행 환경 구성
```

예를 들어 기존 `.venv`를 삭제했다면:

```text
기존 .venv 삭제
    ↓
프로젝트 설정 확인
    ↓
uv sync
    ↓
새로운 .venv 구성
    ↓
필요한 패키지 설치
    ↓
프로젝트 실행 가능
```

즉, `.venv` 자체를 공유하는 것이 아니라 **`pyproject.toml`과 `uv.lock`을 기준으로 각자의 개발 환경을 다시 구성**할 수 있다.

### 6. 프로젝트 생성부터 패키지 설치까지

uv를 사용하면 프로젝트 생성과 외부 패키지 관리까지 프로젝트 단위로 관리할 수 있다.

먼저 Python 버전을 지정하여 프로젝트를 생성한다.

```bash
uv init my_dependency_project --python 3.13
```

프로젝트 디렉터리로 이동한다.

```bash
cd my_dependency_project
```

필요한 패키지를 추가한다.

```bash
uv add pandas matplotlib
```

이후 `pyproject.toml`을 확인하면 `pandas`와 `matplotlib`이 프로젝트의 의존성으로 등록되어 있는 것을 확인할 수 있다.

전체적인 흐름은 다음과 같다.

```text
프로젝트 생성
    ↓
uv init my_dependency_project --python 3.13
    ↓
프로젝트 폴더 이동
    ↓
cd my_dependency_project
    ↓
필요한 패키지 추가
    ↓
uv add pandas matplotlib
    ↓
pyproject.toml / uv.lock 갱신
```

## 💡 오늘 배운 핵심

- **PyPI**는 Python 패키지를 공유하는 공식 중앙 저장소이다.
- **Dependency(의존성)**는 프로젝트가 정상적으로 동작하기 위해 필요한 외부 패키지와 그 관계를 의미한다.
- `uv add`는 패키지를 설치하는 것뿐만 아니라 프로젝트의 의존성을 **선언하고 관리**한다.
- `pyproject.toml`은 프로젝트가 필요로 하는 패키지와 버전 조건을 기록하는 **명세 파일**이다.
- `uv.lock`은 실제 해결된 정확한 패키지 버전을 기록하여 **동일한 개발 환경을 재현**할 수 있도록 한다.
- `uv sync`를 사용하면 `pyproject.toml`과 `uv.lock`을 기준으로 개발 환경을 다시 구성할 수 있다.
- 협업에서는 `.venv`를 공유하기보다 `pyproject.toml`과 `uv.lock`을 함께 관리하는 것이 중요하다.

## 📝 느낀 점

이번 학습을 통해 의존성 관리는 단순히 필요한 라이브러리를 설치하는 작업이 아니라, **프로젝트에서 어떤 라이브러리를 어떤 환경으로 사용할 것인지 명확하게 기록하고 재현하는 과정**이라는 것을 이해했다.

특히 `pyproject.toml`과 `uv.lock`의 역할을 구분하는 것이 중요했다. `pyproject.toml`이 프로젝트의 요구사항을 정의한다면 `uv.lock`은 실제로 사용될 버전을 고정하기 때문에, 여러 개발자가 함께 작업하거나 새로운 컴퓨터에서 프로젝트를 다시 구성할 때 동일한 환경을 만들 수 있다.

앞으로 Python 프로젝트를 구성할 때 단순히 패키지를 설치하는 것보다 프로젝트의 의존성을 명확하게 선언하고 관리하는 습관을 가져야겠다.
