## 예외 처리

### 예외 처리란?

프로그램을 작성할 때 논리적으로 코드를 잘 설계하더라도 잘못된 외부 데이터가 입력되거나 존재하지 않는 파일을 호출하는 등 **프로그램 실행 중 예기치 않은 오류**가 발생할 수 있다.

이러한 상황에서 예외 처리가 되어 있지 않으면 프로그램이 중단될 수 있기 때문에, 예외가 발생하더라도 프로그램이 비정상적으로 종료되지 않도록 처리하는 것이 중요하다.

오늘은 Python의 **구문 오류(SyntaxError)​**와 **런타임 예외(Exception)​**의 차이를 알아보고, `try-except-else-finally`와 `raise`를 활용한 예외 처리 및 데이터 유효성 검증 방법을 학습했다.

---

## 1. 구문 오류와 런타임 예외

### 1.1 구문 오류(Syntax Error)

**SyntaxError**는 Python의 문법 규칙을 지키지 않았을 때 발생한다.

대표적인 경우는 다음과 같다.

- 콜론(`:`) 누락
- 괄호 누락
- 잘못된 들여쓰기
- 문법에 맞지 않는 코드 작성

예를 들어 조건문에서 콜론을 작성하지 않으면 실행 전에 구문 오류가 발생한다.

```python
if price >= 10000
    print("무료 배송입니다.")
```

```text
SyntaxError: expected ':'
```

즉, **Python이 코드를 정상적으로 해석할 수 없는 경우**에 발생하는 오류이다.

---

### 1.2 런타임 예외(Exception)

**Exception**은 문법적으로는 문제가 없지만 프로그램을 실행하는 과정에서 예상하지 못한 문제가 발생했을 때 나타난다.

대표적인 예가 0으로 나누는 경우이다.

```python
total_price = 15000
people = 0

price_per_person = total_price / people
```

```text
ZeroDivisionError: division by zero
```

코드의 문법 자체는 올바르기 때문에 실행은 시작되지만, 실제 연산 과정에서 문제가 발생한다.

### 핵심 차이

| 구분 | SyntaxError | Exception |
| --- | --- | --- |
| 발생 시점 | 실행 전 | 프로그램 실행 중 |
| 원인 | Python 문법 규칙 위반 | 실행 중 예기치 않은 상황 |
| 예시 | 콜론 누락, 괄호 누락 | 0으로 나누기, 잘못된 인덱스 |
| 처리 | 문법 수정 | `try-except` 등을 이용한 예외 처리 |

SyntaxError는 문법 자체의 문제이고, Exception은 문법은 올바르지만 실행 과정에서 문제가 발생하는 경우라고 이해하면 된다.

## 2. Python의 대표적인 예외

데이터를 처리하다 보면 다양한 상황에서 예외가 발생할 수 있다.

### 2.1 IndexError

존재하지 않는 인덱스에 접근하면 `IndexError`가 발생한다.

```python
products = ["노트북", "마우스", "키보드"]

print(products[5])
```

```text
IndexError: list index out of range
```

리스트의 길이가 3이므로 사용할 수 있는 인덱스는 `0`, `1`, `2`뿐이다.

```python
numbers = [10, 20, 30]

print(numbers[5])
```

따라서 존재하지 않는 위치를 조회하면 `IndexError`가 발생한다.

---

### 2.2 ValueError

함수가 기대하는 자료형의 값이 전달되었지만 **그 값 자체가 적절하지 않은 경우** 발생한다.

예를 들어 문자열을 정수로 변환할 때 숫자로 변환할 수 없는 문자열을 전달하면 `ValueError`가 발생한다.

```python
quantity = "세 개"

number = int(quantity)
```

```text
ValueError: invalid literal for int()
```

또 다른 예시는 다음과 같다.

```python
text = "스파르타"

number = int(text)
```

문자열 타입 자체는 `int()`에 전달할 수 있지만 `"스파르타"`라는 값은 숫자로 변환할 수 없기 때문에 `ValueError`가 발생한다.

---

### 2.3 TypeError

서로 맞지 않는 자료형끼리 연산하거나 호출할 수 없는 대상을 호출하는 경우 발생한다.

```python
price = 10000
delivery_fee = "3000"

total_price = price + delivery_fee
```

```text
TypeError
```

정수와 문자열은 직접 더할 수 없기 때문에 `TypeError`가 발생한다.

```python
result = 10 + "20"
```

이 경우에도 `int`와 `str`의 연산이므로 `TypeError`가 발생한다.

---

### 2.4 ZeroDivisionError

숫자를 0으로 나누려고 할 때 발생한다.

```python
total_price = 30000
people = 0

price_per_person = total_price / people
```

```text
ZeroDivisionError: division by zero
```

0으로 나누는 연산은 허용되지 않기 때문에 `ZeroDivisionError`가 발생한다.

---

### 대표 예외 정리

| 예외 | 발생 상황 |
| --- | --- |
| `IndexError` | 존재하지 않는 인덱스에 접근 |
| `ValueError` | 값이 적절하지 않아 처리할 수 없음 |
| `TypeError` | 서로 맞지 않는 자료형을 연산 |
| `ZeroDivisionError` | 숫자를 0으로 나눔 |

---

## 3. try-except 제어 구조

실행 중 발생할 수 있는 예외를 처리하기 위해 Python에서는 `try-except` 구조를 사용할 수 있다.

`try` 블록에는 예외가 발생할 가능성이 있는 코드를 작성하고, `except` 블록에서는 해당 예외가 발생했을 때 대응한다.

기본 구조는 다음과 같다.

```python
try:
    # 예외가 발생할 가능성이 있는 코드
    ...
except 예외이름:
    # 예외가 발생했을 때 실행
    ...
```

예를 들어 문자열을 정수로 변환하는 과정에서 `ValueError`가 발생할 수 있다.

```python
quantity_text = "세 개"

try:
    quantity = int(quantity_text)
except ValueError:
    print("수량은 숫자로 입력해야 합니다.")
```

이렇게 작성하면 `ValueError`가 발생하더라도 프로그램이 해당 예외를 처리할 수 있다.

---

## 4. try-except-else-finally

Python에서는 `try-except`뿐만 아니라 `else`와 `finally`를 함께 사용할 수 있다.

```python
try:
    # 예외 발생 가능 코드
except:
    # 예외 발생 시
else:
    # 예외가 발생하지 않았을 때
finally:
    # 항상 실행
```

각 블록의 역할은 다음과 같다.

### try

예외가 발생할 가능성이 있는 핵심 로직을 작성한다.

### except

예외가 실제로 발생했을 때 실행된다.

특정 예외의 이름을 지정하면 해당 예외에 맞는 처리를 할 수 있다.

### else

`try` 블록에서 예외가 발생하지 않고 정상적으로 실행되었을 때만 실행된다.

### finally

예외 발생 여부와 관계없이 **항상 마지막에 실행**된다.

파일을 닫거나 데이터베이스 연결을 종료하는 등 반드시 수행해야 하는 마무리 작업에 활용할 수 있다.

---

### 예제

```python
quantity_text = "3"

try:
    quantity = int(quantity_text)

except ValueError:
    print("수량은 숫자로 입력해야 합니다.")

else:
    print(f"{quantity}개의 상품 주문을 접수했습니다.")

finally:
    print("주문 입력 처리를 종료합니다.")
```

실행 결과:

```text
3개의 상품 주문을 접수했습니다.
주문 입력 처리를 종료합니다.
```

`"3"`은 정상적으로 정수로 변환되므로 `except`는 실행되지 않고 `else`가 실행된다.

그리고 성공 여부와 관계없이 `finally`가 실행된다.

---

## 5. 다중 예외 처리

하나의 `try` 블록에서 여러 종류의 예외가 발생할 수 있다면 여러 개의 `except`를 사용할 수 있다.

```python
customers = ["민수", "지수", "철수"]
input_value = "1"

try:
    customer_index = int(input_value)
    customer = customers[customer_index]

except ValueError:
    print("고객 번호는 숫자로 입력해야 합니다.")

except IndexError:
    print("해당 번호의 고객이 존재하지 않습니다.")

else:
    print(f"고객 조회 성공: {customer}")

finally:
    print("고객 조회 작업을 종료합니다.")
```

입력값이 `"abc"`라면 문자열을 정수로 변환하는 과정에서 `ValueError`가 발생한다.

반대로 `"10"`처럼 숫자로 변환할 수 있는 값이지만 리스트에 존재하지 않는 인덱스라면 `IndexError`가 발생한다.

각 예외에 맞는 `except` 블록만 실행되며, 예외가 발생하지 않는다면 `else`, 마지막에는 항상 `finally`가 실행된다.

## 6. raise를 이용한 의도적인 예외 발생

`raise`는 개발자가 **의도적으로 예외를 발생시키기 위해 사용하는 키워드**이다.

Python 문법상 문제가 없는 값이라도 서비스의 비즈니스 규칙에 맞지 않는 경우가 있을 수 있다.

예를 들어 쇼핑몰에서는 주문 수량이 0개 이하가 될 수 없다고 가정할 수 있다.

```python
def check_order_quantity(quantity):
    if quantity <= 0:
        raise ValueError("주문 수량은 1개 이상이어야 합니다.")

    return quantity
```

```python
order_quantity = 0

check_order_quantity(order_quantity)
```

실행 결과:

```text
ValueError: 주문 수량은 1개 이상이어야 합니다.
```

`quantity = 0`은 Python 문법상 문제가 없다.

하지만 서비스의 규칙에는 맞지 않기 때문에 `raise ValueError()`를 이용하여 개발자가 직접 예외를 발생시킨 것이다.

---

## 7. raise를 활용한 데이터 유효성 검증

`raise`는 데이터가 비즈니스 규칙에 맞는지 검증하는 데 활용할 수 있다.

예를 들어 회원 포인트는 음수가 될 수 없다고 가정해보자.

```python
def save_user_point(point):
    if point < 0:
        raise ValueError("회원 포인트는 음수가 될 수 없습니다.")

    print(f"{point} 포인트가 저장되었습니다.")


try:
    user_point = -500
    save_user_point(user_point)

except ValueError as error:
    print(f"[포인트 저장 실패] {error}")
```

실행 결과:

```text
[포인트 저장 실패] 회원 포인트는 음수가 될 수 없습니다.
```

함수 내부에서 데이터의 유효성을 먼저 검사하고, 잘못된 값이면 `raise`로 예외를 발생시킨다.

발생한 예외는 함수를 호출한 바깥쪽의 `try-except`에서 처리할 수 있다.

이러한 구조를 사용하면 **데이터를 사용하는 코드와 데이터의 유효성을 검사하는 코드를 명확하게 관리**할 수 있다.

## 8. 오늘 배운 내용 정리

### 예외의 종류

- `SyntaxError`: Python 문법 규칙을 위반했을 때 발생
- `IndexError`: 존재하지 않는 인덱스에 접근할 때 발생
- `ValueError`: 값이 적절하지 않아 처리할 수 없을 때 발생
- `TypeError`: 서로 맞지 않는 자료형을 연산할 때 발생
- `ZeroDivisionError`: 숫자를 0으로 나눌 때 발생

### 예외 처리 구조

```text
try
 ↓
예외 발생?
 ├─ Yes → except
 │
 └─ No  → else
          ↓
       finally
```

- `try`: 예외 발생 가능성이 있는 코드
- `except`: 예외가 발생했을 때 처리
- `else`: 예외 없이 정상 실행되었을 때 처리
- `finally`: 성공/실패와 관계없이 항상 실행

### raise

- 개발자가 직접 예외를 발생시킬 때 사용
- Python 문법상 문제가 없는 값도 비즈니스 규칙에 맞지 않으면 차단 가능
- 데이터 유효성 검증에 활용할 수 있음

---

## 9. 느낀 점

오늘 학습을 통해 예외 처리는 단순히 에러 메시지를 없애는 것이 아니라 **프로그램이 예상하지 못한 상황에서도 안정적으로 동작하도록 만드는 과정**이라는 것을 알게 되었다.

특히 `try-except`를 사용하면 실행 중 발생할 수 있는 오류에 대응할 수 있고, `raise`를 사용하면 프로그램의 비즈니스 규칙에 맞지 않는 데이터를 사전에 차단할 수 있다는 점이 중요했다.

데이터 사이언스를 공부하면서 앞으로 다양한 데이터를 다루게 될 텐데, 실제 데이터에는 항상 예상하지 못한 값이나 잘못된 입력이 포함될 수 있기 때문에 **데이터 유효성 검증과 예외 처리가 데이터 처리 과정에서도 중요한 역할을 한다는 점**을 기억해야겠다.
