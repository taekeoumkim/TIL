## 1. uv를 활용한 모던 Python 프로젝트 시작

### 1.1 시스템 전역 설치의 문제

Python을 시스템 전역에 설치하고 여러 프로젝트에서 함께 사용하는 경우 프로젝트마다 필요한 패키지 버전이 달라질 수 있다.

예를 들어,

- A 프로젝트 → 최신 버전의 패키지 필요
- B 프로젝트 → 과거 버전의 패키지 필요

이때 전역 공간에 패키지를 추가하거나 변경하면 기존 프로젝트가 영향을 받을 수 있다. 이러한 의존성 충돌을 `Dependency Hell`이라고 한다.

따라서 프로젝트마다 독립적인 가상환경을 만들어 서로 영향을 주지 않도록 격리하는 것이 중요하다.

### 1.2 기존 가상환경 관리 방식의 한계

기존 Python 환경에서는 다음과 같이 여러 도구를 조합해서 사용해야 했다.

- `pyenv` → Python 버전 관리
- `venv` → 가상환경 격리
- `pip` → 패키지 설치
- `requirements.txt` → 의존성 기록

도구가 분리되어 있어 환경을 구성하고 관리하는 과정이 복잡해질 수 있다.

### 1.3 uv

`uv`는 Rust로 작성된 Python 툴체인으로, Python 버전 관리부터 가상환경 생성, 패키지 설치 및 Lock까지 하나의 도구로 관리할 수 있다.

학습 자료에서는 기존 Python 도구보다 빠른 속도와 자동화된 Python 버전 관리, 통합된 환경 관리를 주요 장점으로 설명한다.

## 2. uv 설치

### Windows PowerShell

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://astral.sh/uv/0.11.12/install.ps1 | iex"
```

### macOS / Linux

```bash
curl -LsSf https://astral.sh/uv/0.11.12/install.sh | sh
```

설치 후에는 기존 터미널을 완전히 종료하고 다시 실행한다.

```bash
uv --version
```

정상적으로 설치되었다면 `uv 0.x.x` 형태의 버전 정보가 출력된다.

터미널을 다시 실행하는 이유는 `uv` 설치 과정에서 시스템의 `PATH` 환경 변수가 변경되기 때문이다.

## 3. uv init으로 프로젝트 초기화

먼저 프로젝트 폴더를 생성하고 이동한다.

```bash
mkdir first-project
cd first-project
```

프로젝트를 초기화한다.

```bash
uv init
```

초기화가 완료되면 프로젝트의 기본 파일들이 생성된다.

### 주요 파일

```text
first-project/
├── .python-version
├── main.py
└── pyproject.toml
```

- `.python-version` → 프로젝트에서 사용할 Python 버전
- `main.py` → 기본 Python 실행 파일
- `pyproject.toml` → 프로젝트 메타데이터와 의존성을 선언하는 명세 파일

`uv init` 단계에서는 Python이 바로 다운로드되거나 `.venv`가 생성되는 것이 아니라 프로젝트 환경 설정을 위한 기본 파일이 먼저 만들어진다.

실제 Python 다운로드와 가상환경 생성은 이후 프로젝트를 실행하거나 패키지를 추가할 때 진행된다.

```bash
uv run main.py
```

또는

```bash
uv add 라이브러리명
```

## 4. Python 버전 지정

프로젝트 초기화 시 `--python` 옵션으로 사용할 Python 버전을 지정할 수 있다.

```bash
uv init --python 3.13
```

이 경우 `.python-version`과 `pyproject.toml`의 Python 버전 조건에 해당 버전이 반영된다.

이미 생성된 프로젝트의 Python 버전을 변경할 때는 다음 명령어를 사용할 수 있다.

```bash
uv python pin 3.12
```

## 5. pyproject.toml

`pyproject.toml`은 현대 Python 프로젝트에서 프로젝트 설정과 의존성 등을 선언적으로 관리하는 표준 명세 파일이다.

기본적인 구조는 다음과 같다.

```toml
[project]
name = "first-project"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.13"
dependencies = []
```

### 주요 항목

#### `name`, `version`

프로젝트 이름과 버전을 정의한다.

#### `requires-python`

프로젝트가 정상적으로 동작하기 위해 필요한 최소 Python 버전을 지정한다.

```toml
requires-python = ">=3.13"
```

#### `dependencies`

프로젝트에서 사용하는 외부 라이브러리 목록을 관리한다.

```toml
dependencies = []
```

이후 `uv add`로 라이브러리를 추가하면 의존성이 이 영역에 기록된다.

### 선언적 환경 관리의 장점

- 프로젝트 설정을 하나의 파일에서 중앙 집중적으로 관리할 수 있다.
- 프로젝트에서 사용하는 패키지와 버전 구조를 명확하게 기록할 수 있다.
- 다른 개발자나 배포 환경에서 동일한 실행 환경을 재현하기 쉽다.
- `uv`뿐만 아니라 Poetry, Hatch, Flit 등 다른 현대적인 Python 도구와도 호환할 수 있다.

## 6. 프로젝트 실행

`uv init`으로 생성된 `main.py`에는 기본 실행 코드가 작성되어 있다.

```python
def main():
    print("Hello from first-project!")


if __name__ == "__main__":
    main()
```

다음 명령어로 실행한다.

```bash
uv run main.py
```

첫 실행 과정에서 프로젝트에 필요한 Python이 없거나 `.venv`가 없다면 `uv`가 필요한 Python 인터프리터를 다운로드하고 프로젝트 전용 가상환경을 구성한다.

정상적으로 실행되면 다음과 같은 결과가 출력된다.

```text
Hello from first-project!
```

## 7. 가상환경 활성화

가상환경은 단순히 만들어 놓는 것뿐만 아니라 활성화하여 해당 환경을 사용하도록 전환할 수 있다.

### Windows

```bash
.venv\Scriptsctivate
```

### macOS / Linux

```bash
source .venv/bin/activate
```

정상적으로 활성화되면 터미널 프롬프트 앞에 프로젝트 이름이 괄호 형태로 표시된다.

```text
(project-name)
```

이를 통해 현재 터미널이 프로젝트의 가상환경을 사용하고 있음을 확인할 수 있다.

## 8. Python 실행 방식

Python은 크게 `REPL`과 `스크립트` 방식으로 실행할 수 있다.

### 8.1 REPL

REPL은 `Read-Eval-Print Loop`의 약자이다.

1. 코드를 입력한다. `Read`
2. Python이 실행한다. `Eval`
3. 결과를 출력한다. `Print`
4. 다음 입력을 기다린다. `Loop`

터미널에서 다음과 같이 실행한다.

```bash
python
```

그러면 `>>>` 프롬프트가 나타난다.

```python
>>> 1 + 1
2

>>> 10 * 5
50
```

종료할 때는 다음과 같이 입력한다.

```python
>>> exit()
```

REPL은 간단한 문법 테스트나 수식 검증처럼 결과를 즉시 확인할 때 유용하다.

하지만 터미널이나 세션을 종료하면 작성했던 코드가 메모리에서 사라지기 때문에 코드를 영구적으로 보존하거나 실제 프로그램을 만들기에는 적합하지 않다.

## 9. 스크립트 실행

실제 프로그램은 Python 코드를 `.py` 파일에 저장하고 실행하는 스크립트 방식을 사용한다.

예를 들어 `hello.py` 파일을 만들고 다음 코드를 작성한다.

```python
print("Hello World")
```

스크립트 방식은 코드를 파일로 저장하기 때문에 코드가 영구적으로 보존된다.

### REPL과 스크립트 비교

| 구분 | REPL | 스크립트 |
| --- | --- | --- |
| 실행 단위 | 한 줄씩 즉시 실행 | `.py` 파일 전체를 위에서 아래로 실행 |
| 코드 영속성 | 세션 종료 시 사라짐 | 파일로 저장되어 보존 |
| 주요 목적 | 문법 테스트, 수식 검증 | 기능 구현, 자동화, 서비스 개발 |

## 10. VS Code와 가상환경

VS Code에서 프로젝트 폴더를 열면 대부분 프로젝트의 `.venv`가 Python 인터프리터로 자동 연결된다.

자동으로 연결되지 않는 경우:

```text
Ctrl + Shift + P
→ Python: Select Interpreter
→ .venv 인터프리터 선택
```

Windows에서는 다음 경로의 인터프리터를 선택할 수 있다.

```text
.venv\Scripts\python.exe
```

VS Code에서 터미널을 빠르게 열고 닫을 때는 다음 단축키를 사용할 수 있다.

```text
Ctrl + `
```

## 오늘의 핵심 정리

- 프로젝트마다 **독립된 가상환경**을 사용하면 프로젝트 간 패키지 충돌을 방지할 수 있다.
- `uv init`은 Python 프로젝트의 기본 구조와 환경 설정 파일을 생성한다.
- `pyproject.toml`은 프로젝트 메타데이터와 Python 버전, 의존성을 선언적으로 관리한다.
- `uv run`을 사용하면 프로젝트에 필요한 Python과 가상환경을 자동으로 구성하여 실행할 수 있다.
- `REPL`은 짧은 코드와 수식을 즉시 테스트할 때 적합하다.
- 실제 프로그램은 `.py` 파일에 코드를 저장하는 **스크립트 방식**으로 실행한다.
- VS Code에서 프로젝트의 `.venv` 인터프리터를 연결하면 프로젝트 전용 Python 환경에서 개발할 수 있다.
