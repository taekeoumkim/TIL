## 검증 가능한 질문으로 재정의

### 분석 결과와 결론은 다르다

데이터 분석에서는 분석 결과가 나왔다고 해서 바로 결론을 확정하면 안 된다.

예를 들어 광고비가 증가한 시기에 매출도 증가했다면,

> 광고비를 늘렸더니 매출이 증가했다.

라고 생각하기 쉽다.

하지만 매출 증가에는 광고비 외에도 여러 요인이 영향을 줄 수 있다.

- 계절적 성수기
- 할인 행사
- 경쟁사 이슈
- 신제품 출시
- 기존 고객의 재구매 증가

따라서 더 안전한 해석은 다음과 같다.

> 광고비가 증가한 기간에 매출도 함께 증가했다. 광고비 증가가 매출 상승에 영향을 주었는지는 프로모션, 유입 채널, 신규 고객 비중, 객단가 등을 추가로 확인해야 한다.

즉, **관찰된 사실과 원인에 대한 해석을 구분하는 것**이 중요하다.

### 단정적인 결론이 위험한 이유

데이터 하나만으로 모든 원인을 설명할 수는 없다.

특히 다음과 같은 경우에는 결론을 조심해야 한다.

- 표본 수가 적은 경우
- 특정 기간의 데이터만 본 경우
- 이상치가 포함된 경우
- 비교 기준이 명확하지 않은 경우
- 상관관계만 확인한 경우
- 숨은 변수를 통제하지 않은 경우
- 데이터 수집 방식이 변경된 경우

예를 들어 수강생 만족도가 낮아졌다고 해서 바로 **"강의 품질이 떨어졌다"**고 결론 내릴 수 없다.

만족도에는 다음과 같은 요인이 함께 영향을 줄 수 있다.

- 과제 난이도
- 운영 방식
- 질문 응답 속도
- 수강생의 기대 수준
- 설문을 실시한 시점

따라서 분석 결과를 봤을 때는 다음 질문을 먼저 해야 한다.

```text
이 결과는 어떤 조건에서 나온 것인가?
다른 설명 가능성은 없는가?
이 결론을 확인하려면 어떤 데이터가 더 필요한가?
지금 말할 수 있는 것과 아직 말할 수 없는 것은 무엇인가?
```

### 검증 가능한 질문

검증 가능한 질문은 **데이터나 관찰을 통해 실제로 확인할 수 있는 질문**이다.

예를 들어,

> 우리 서비스가 별로인가?

는 범위가 너무 넓고 객관적으로 확인하기 어렵다.

반면 다음과 같은 질문은 데이터를 이용해 검증할 수 있다.

- 최근 4주 동안 신규 가입자의 7일 리텐션이 이전 4주 대비 하락했는가?
- 리텐션 하락이 특정 유입 채널에서 더 크게 나타나는가?
- 첫 사용 과정에서 이탈한 사용자의 비율이 증가했는가?
- 신규 가입자의 첫 핵심 기능 사용률이 감소했는가?

이런 질문은 답을 구하는 과정에서 **다음에 어떤 행동을 해야 하는지까지 연결하기 쉽다.**

> 검증 가능한 질문은 좋은 분석의 출발점이자 좋은 결론의 마무리이다.

### 분석 결과를 검증 가능한 질문으로 바꾸기

예를 들어,

> 3주차 이후 과제 제출률이 하락했다.

라는 결과가 나왔다고 하자.

여기서 분석을 끝내지 않고 다음과 같이 질문을 확장할 수 있다.

```text
3주차 과제의 난이도가 이전 주차보다 높았는가?
        ↓
3주차 이후 출석률도 함께 하락했는가?
        ↓
특정 반이나 특정 수강생 그룹에서 더 크게 하락했는가?
        ↓
3주차 과제 관련 질문이 증가했는가?
        ↓
마감 전 안내나 리마인드가 충분했는가?
```

이렇게 질문을 구체화하면 단순히 **"제출률이 낮다"**에서 끝나지 않고 실제 원인을 찾기 위한 다음 분석으로 이어갈 수 있다.

### 좋은 결론의 특징

좋은 결론은 단순히 결과를 한 문장으로 정리하는 것이 아니다.

다음 내용을 함께 포함하는 것이 좋다.

1. **관찰된 사실**
2. **가능한 해석**
3. **근거**
4. **한계**
5. **추가 검증 사항**
6. **제안할 액션**

예를 들어,

```text
나쁜 결론
→ 매출이 줄었다.

좋은 결론
→ 최근 3개월 동안 신규 고객 매출이 감소했으며,
  특히 광고 유입 고객의 구매 전환율 하락이
  주요 원인일 가능성이 있다.
```

좋은 결론은 **어디에서 문제가 발생했는지, 왜 그런 가능성이 있는지, 무엇을 더 확인해야 하는지**를 함께 보여준다.

## AI 시대의 데이터 리터러시

### AI가 발전할수록 데이터 리터러시가 중요한 이유

생성형 AI와 데이터 분석 도구가 발전하면서 데이터를 다루는 진입장벽이 낮아졌다.

과거에는 SQL을 직접 작성하거나 Python 코드를 작성해야 했던 작업도 이제는 자연어로 요청할 수 있다.

예를 들어 다음과 같은 요청이 가능하다.

```text
지난 6개월간 월별 매출 추이를 분석해 줘.
고객군별 재구매율을 비교해 줘.
이 데이터에서 이상치를 찾아 줘.
구매 전환율이 낮아진 원인을 추정해 줘.
분석 결과를 보고서 형태로 요약해 줘.
```

AI는 데이터를 요약하고, 그래프를 만들고, 코드를 작성하고, 분석 방법을 추천하는 등 다양한 작업을 빠르게 수행할 수 있다.

하지만 **빠르게 답을 만들어 준다는 것과 그 답이 항상 옳다는 것은 다르다.**

오히려 자연스러운 문장과 깔끔한 표 때문에 잘못된 결론을 더 쉽게 믿을 수도 있다.

따라서 AI 시대의 데이터 리터러시는 단순히 데이터를 분석하는 능력을 넘어,

> **AI가 만든 결과를 읽고, 의심하고, 검증하고, 의사결정에 맞게 활용하는 능력**

이라고 생각할 수 있다.

### AI는 분석을 도와주지만 판단을 책임지지 않는다

AI가 할 수 있는 일은 많다.

- 데이터 요약
- 코드 작성
- 그래프 생성
- 이상치 탐색
- 분석 방법 추천
- 보고서 초안 작성

하지만 AI는 사용자가 제공한 **데이터와 질문을 바탕으로** 답을 만든다.

따라서 문제가 잘못 정의되어 있거나, 데이터가 편향되어 있거나, 질문이 모호하면 AI의 답도 잘못된 방향으로 나올 수 있다.

예를 들어,

```text
"매출이 줄어든 원인을 분석해 줘."
```

라고만 요청하면 AI는 주어진 데이터 안에서 가능한 설명을 만들어낸다.

하지만 다음과 같은 데이터가 빠져 있다면 AI는 이를 알 수 없다.

- 광고비 데이터 → 광고 효율 문제
- 재고 데이터 → 품절로 인한 매출 감소
- 프로모션 일정 → 할인 종료 효과

즉,

> **AI는 강력한 분석 도구이지만 분석의 목적과 맥락을 책임지는 것은 사람이다.**

### AI의 분석 결과를 그대로 믿으면 안 되는 이유

#### 1. 데이터의 맥락을 충분히 모를 수 있다

특정 날짜의 매출이 급증했다고 하자.

AI는 이를 성장 신호로 해석할 수 있지만 실제로는,

- 일회성 할인 행사
- 대량 구매 고객 한 명
- 특정 이벤트

때문일 수도 있다.

데이터의 숫자만 보고 상황 전체를 알 수 있는 것은 아니다.

#### 2. 그럴듯하지만 틀린 설명을 만들 수 있다

AI는 자연스러운 문장을 매우 잘 만든다.

하지만 문장이 자연스럽다고 해서 내용까지 반드시 정확한 것은 아니다.

특히 다음과 같은 분석에서는 더욱 주의해야 한다.

- 원인 분석
- 인과관계 해석
- 미래 예측

#### 3. 제공된 데이터 안에서만 판단한다

필요한 데이터가 빠져 있다면 분석 결과 역시 제한될 수밖에 없다.

따라서 AI에게 분석을 요청하기 전에 **어떤 데이터가 포함되어 있고 어떤 데이터가 빠져 있는지** 확인해야 한다.

#### 4. 질문이 모호하면 답도 모호해진다

```text
나쁜 질문
→ 이 데이터 분석해 줘.

좋은 질문
→ 최근 6개월 동안 월별 구매 전환율 변화를 분석해 줘.
  신규 고객과 기존 고객을 나누어 비교하고,
  전환율이 하락한 구간과 가능한 원인,
  추가로 확인해야 할 데이터를 정리해 줘.
```

좋은 질문은 AI에게 더 좋은 분석 결과를 제공하도록 만드는 중요한 입력이다.

## AI를 활용한 데이터 분석 과정

AI에게 한 번 질문하고 결과를 그대로 사용하는 것이 아니라 **질문 → 분석 → 검증 → 재질문 → 의사결정**의 과정을 반복해야 한다.

```text
질문 정의
   ↓
AI 분석 요청
   ↓
결과 검증
   ↓
재질문·보완
   ↓
의사결정
```

### 1. 좋은 질문을 던지는 능력

AI에게 분석을 요청할 때는 다음 내용을 명확하게 전달하는 것이 좋다.

- 분석 목적
- 분석 기간
- 분석 대상
- 핵심 지표
- 비교 기준
- 원하는 결과 형태
- 주의해야 할 점

질문이 구체적일수록 분석 결과를 해석하고 활용하기도 쉬워진다.

### 2. 데이터 품질을 확인하는 능력

AI에게 분석을 맡기기 전에 데이터 자체가 믿을 만한지 확인해야 한다.

다음 항목을 확인한다.

```text
결측치가 있는가?
이상치가 있는가?
중복 데이터가 있는가?
측정 기준이 바뀐 적이 있는가?
수집 기간이 충분한가?
분석 대상이 전체를 대표하는가?
필요한 변수가 빠져 있지는 않은가?
```

> 데이터 품질이 낮으면 아무리 좋은 AI 도구를 사용해도 좋은 분석 결과를 만들 수 없다.

### 3. 결과를 비판적으로 해석하는 능력

AI가 만든 결과를 그대로 받아들이지 말고 근거와 한계를 확인해야 한다.

다음 질문을 활용할 수 있다.

```text
이 결론은 어떤 데이터에 근거하는가?
다른 해석 가능성은 없는가?
상관관계를 인과관계처럼 말하고 있지는 않은가?
평균만 보고 데이터의 분포를 놓치고 있지는 않은가?
특정 집단의 차이가 전체 평균에 가려져 있지는 않은가?
추가로 확인해야 할 데이터는 무엇인가?
```

결국 AI 시대의 데이터 리터러시는 **AI의 답을 잘 받아 적는 능력이 아니라 AI의 답을 검토하고 더 나은 질문으로 발전시키는 능력**이다.

### 4. 분석 결과를 의사결정으로 연결하기

AI가 분석 결과를 정리해 주더라도 최종적으로 어떤 행동을 할지는 사람이 결정해야 한다.

예를 들어 AI가,

> 결제 단계 이탈률이 높다.

라는 결과를 제공했다고 하자.

다음 중 어떤 액션을 먼저 할지는 추가적인 판단이 필요하다.

- 결제 오류 로그 확인
- 결제 UI 개선
- 간편결제 옵션 추가
- 배송비 안내 문구 수정
- A/B 테스트 진행

따라서 데이터 분석의 목적은 단순히 결과를 만드는 것이 아니라 **의사결정을 돕는 것**이다.

AI는 결과를 만드는 속도를 높여줄 수 있지만, **의사결정의 책임은 사람에게 있다.**

## AI에게 데이터 분석을 요청하는 방법

AI에게 데이터 분석을 요청할 때는 다음 요소를 포함하면 좋다.

| 요소 | 확인할 내용 |
| --- | --- |
| 분석 목적 | 무엇을 알고 싶은가? |
| 분석 대상 | 어떤 데이터, 고객, 기간을 볼 것인가? |
| 핵심 지표 | 무엇을 기준으로 판단할 것인가? |
| 비교 기준 | 전월/전년/고객군/채널 등 무엇과 비교할 것인가? |
| 결과물 | 표/그래프/요약/보고서/액션 아이템 중 무엇이 필요한가? |
| 주의점 | 인과관계 단정, 평균의 함정, 이상치 등 무엇을 주의할 것인가? |

이렇게 질문을 구조화하면 AI의 분석 결과를 더 구체적이고 검증 가능한 형태로 받을 수 있다.

## 오늘 배운 내용 정리

이번 학습에서는 **데이터 분석 결과를 어떻게 안전하게 해석하고, AI를 데이터 분석에 어떻게 활용해야 하는지**를 배웠다.

특히 기억할 내용은 다음과 같다.

- 분석 결과와 결론은 다르다.
- 데이터가 보여주는 사실과 원인에 대한 해석을 구분해야 한다.
- 상관관계를 확인했다고 해서 인과관계를 단정하면 안 된다.
- 분석 결과를 검증 가능한 질문으로 바꾸면 다음 분석 방향이 명확해진다.
- 좋은 결론은 사실, 해석, 근거, 한계, 추가 검증, 액션을 함께 고려한다.
- 생성형 AI는 데이터 분석을 빠르게 도와주지만 판단과 책임까지 대신할 수는 없다.
- AI의 답은 입력된 데이터와 질문의 품질에 영향을 받는다.
- AI가 만든 결과도 데이터의 맥락, 편향, 이상치, 분포, 인과관계를 비판적으로 검토해야 한다.
- AI를 잘 활용하기 위해서는 **좋은 질문을 만드는 능력**이 중요하다.
- AI에게 한 번 질문하고 끝내는 것이 아니라 **질문 → 분석 → 검증 → 재질문 → 의사결정**의 과정을 반복해야 한다.

### 한 줄 회고

> **AI 시대의 데이터 리터러시는 AI에게 답을 얻는 능력이 아니라, 그 답을 검증하고 더 나은 질문과 의사결정으로 연결하는 능력이다.**
