## 1. Feature가 많을수록 항상 좋을까?

데이터를 분석하다 보면 Feature의 개수가 수십 개에서 수백, 수천 개까지 늘어날 수 있다. Feature가 많아지면 더 많은 정보를 사용할 수 있지만, 모든 Feature가 유용한 것은 아니다.

불필요한 Feature나 서로 비슷한 정보를 담은 Feature까지 계속 추가하면 다음과 같은 문제가 발생할 수 있다.

- 데이터가 고차원 공간에 희소하게 퍼진다.
- 데이터 사이의 거리와 구조를 구분하기 어려워진다.
- 모델이 노이즈와 불필요한 정보까지 학습할 수 있다.
- 학습과 예측에 필요한 계산량이 증가한다.
- Overfitting 가능성이 커질 수 있다.
- 사람이 데이터를 직접 시각화하고 해석하기 어려워진다.

따라서 Feature의 개수가 많다고 무조건 좋은 것은 아니다. 각 Feature가 실제로 유용한지 확인하고, 필요하다면 중요한 정보를 최대한 유지하면서 차원을 줄여야 한다.

---

## 2. 차원과 차원의 저주

### 차원(Dimension)

데이터의 차원은 데이터가 가진 Feature의 개수를 의미한다.

예를 들어 고객 데이터에 월 방문 횟수와 월 구매 금액만 있으면 2차원 데이터이다. 여기에 나이, 가입 기간, 쿠폰 사용 횟수, 상품 조회 횟수를 추가하면 6차원 데이터가 된다.

~~~python
import pandas as pd

customers = pd.DataFrame({
    "visit_count": [3, 5, 8],
    "purchase_amount": [50, 80, 120],
    "age": [24, 35, 42],
    "membership_months": [5, 18, 36],
    "coupon_count": [4, 2, 1],
    "product_views": [30, 55, 80],
})

print("데이터 크기:", customers.shape)
print("Feature 개수:", customers.shape[1])
~~~

실행 결과:

~~~text
데이터 크기: (3, 6)
Feature 개수: 6
~~~

행은 고객 3명을 나타내고 열은 Feature 6개를 나타내므로, 이 데이터는 6차원이다.

### 차원의 저주(Curse of Dimensionality)

차원의 저주는 차원이 증가할수록 같은 수의 데이터가 더 넓은 공간에 퍼지면서 희소해지고, 데이터 사이의 거리가 서로 비슷해져 가까운 데이터와 먼 데이터를 구분하기 어려워지는 현상이다.

고차원 공간에서는 데이터의 구조를 파악하기 위해 더 많은 데이터와 계산량이 필요할 수 있다. 특히 데이터 사이의 거리를 사용하는 알고리즘은 차원의 저주로 인해 성능이 저하될 수 있다.

| 문제 | 설명 |
|---|---|
| 데이터 희소성 | 같은 수의 데이터가 더 넓은 공간에 퍼진다. |
| Feature 중복 | 서로 비슷한 정보를 담은 Feature가 많아질 수 있다. |
| Overfitting 위험 | 불필요한 Feature나 노이즈까지 학습할 가능성이 커진다. |
| 계산 비용 증가 | 학습과 예측에 필요한 계산량이 증가한다. |
| 시각화 어려움 | 고차원 데이터를 원래 공간 그대로 이해하기 어렵다. |

## 3. 차원 축소(Dimensionality Reduction)

차원 축소는 원본 데이터가 가진 중요한 정보를 최대한 유지하면서 Feature의 개수를 줄이는 방법이다.

단순히 Feature를 삭제하는 방법도 있지만, 서로 연관된 여러 Feature의 정보를 하나로 압축할 수도 있다. 대표적인 차원 축소 방법이 **PCA(Principal Component Analysis)**이다.

PCA는 기존 Feature 중 일부를 선택하는 것이 아니다. 여러 Feature를 선형 결합하여 새로운 축인 **주성분(Principal Component)**을 만들고, 앞쪽의 중요한 주성분만 사용해 더 낮은 차원으로 데이터를 표현한다.

~~~text
원본 Feature
    ↓ 표준화
스케일이 맞춰진 데이터
    ↓ PCA 학습
새로운 주성분 생성
    ↓ 일부 주성분 선택
저차원 데이터
~~~

사진을 압축하면 파일 크기는 줄지만 눈으로 보이는 중요한 내용은 대부분 유지되는 것처럼, PCA도 데이터의 차원을 줄이면서 중요한 변동을 최대한 보존한다.

---

## 4. PCA와 주성분의 원리

PCA는 데이터가 가장 넓게 퍼져 있는 방향, 즉 **분산이 가장 큰 방향**을 첫 번째 주성분으로 선택한다.

첫 번째 주성분을 찾은 뒤에는 그 축과 직교하면서 남아 있는 분산을 가장 많이 설명하는 방향을 두 번째 주성분으로 선택한다. 이후 주성분도 같은 방식으로 차례대로 찾는다.

### 주성분(Principal Component)

주성분은 기존 Feature를 선형 결합하여 만든 새로운 Feature이다.

두 Feature \(x_1\), \(x_2\)로 만든 첫 번째 주성분을 단순화하면 다음과 같이 표현할 수 있다.

$$
PC_1 = w_1x_1 + w_2x_2
$$

\(w_1\)과 \(w_2\)는 각 Feature가 새로운 축을 만드는 데 기여하는 가중치이다.

PCA의 핵심은 다음과 같다.

- 기존 Feature 하나를 그대로 선택하거나 제거하지 않는다.
- 기존 Feature들의 정보를 조합하여 새로운 축을 만든다.
- 첫 번째 주성분은 데이터의 분산을 가장 많이 설명한다.
- 다음 주성분은 앞의 주성분과 직교하며 남은 분산을 최대한 설명한다.
- 앞쪽 주성분 몇 개만 사용하여 전체 데이터의 중요한 변동을 최대한 유지한다.

PCA는 분산이 큰 방향에 데이터의 중요한 정보가 많이 담겨 있다고 가정한다.

---

## 5. 키와 몸무게를 하나의 주성분으로 압축하기

일반적으로 키가 큰 사람은 몸무게도 어느 정도 증가하는 경향이 있다. 이처럼 두 Feature가 비슷한 정보를 포함한다면 PCA로 정보를 압축할 수 있다.

PCA는 키나 몸무게 중 하나를 삭제하지 않고, 두 Feature를 조합하여 데이터가 가장 많이 퍼진 방향을 새로운 축으로 만든다.

~~~python
import pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

data = pd.DataFrame({
    "height": [155, 160, 165, 170, 175, 180],
    "weight": [48, 52, 57, 63, 69, 75],
})

scaler = StandardScaler()
X_scaled = scaler.fit_transform(data)

pca = PCA(n_components=1)
X_pca = pca.fit_transform(X_scaled)

print("원본 데이터 크기:", data.shape)
print("PCA 적용 후 크기:", X_pca.shape)
print("설명 분산 비율:", pca.explained_variance_ratio_)
~~~

실행 결과 예시:

~~~text
원본 데이터 크기: (6, 2)
PCA 적용 후 크기: (6, 1)
설명 분산 비율: [0.99872093]
~~~

원본 데이터에는 키와 몸무게라는 2개의 Feature가 있지만, PCA 적용 후에는 하나의 주성분으로 표현된다.

설명 분산 비율이 약 0.9987이라는 것은 첫 번째 주성분 하나가 원본 데이터 전체 분산의 약 99.87%를 설명한다는 뜻이다. 이 데이터에서는 차원을 2개에서 1개로 줄여도 대부분의 변동이 유지된다.

---

## 6. PCA 전에 Feature Scaling이 필요한 이유

PCA는 데이터의 분산이 큰 방향을 중요하게 본다. 따라서 Feature의 측정 단위와 값의 범위가 크게 다르면 값의 범위가 큰 Feature가 주성분을 과도하게 결정할 수 있다.

예를 들어 키는 150~180 정도이고 몸무게는 40~80 정도라면 두 Feature의 값의 범위가 다르다. 더 큰 단위를 사용하는 Feature가 실제 중요도와 관계없이 더 큰 분산을 만들 수 있다.

**StandardScaler**를 사용하면 각 Feature를 평균 0, 표준편차 1인 형태로 변환할 수 있다.

$$
z = \frac{x-\mu}{\sigma}
$$

- \(x\): 원래 값
- \(\mu\): Feature의 평균
- \(\sigma\): Feature의 표준편차

표준화를 적용하면 서로 다른 단위와 범위를 가진 Feature를 같은 기준에서 비교할 수 있다. 따라서 PCA를 적용하기 전에는 일반적으로 Feature Scaling을 먼저 수행한다.

---

## 7. 설명 분산 비율

**explained_variance_ratio_**는 각 주성분이 원본 데이터의 전체 분산을 얼마나 설명하는지 나타낸다.

예를 들어 PC1, PC2, PC3의 설명 분산 비율이 각각 0.70, 0.20, 0.07이라면 첫 번째와 두 번째 주성분의 누적 설명 분산 비율은 다음과 같다.

$$
0.70 + 0.20 = 0.90
$$

즉, 원본 데이터 분산의 90%를 두 개의 주성분으로 표현한다.

~~~python
explained_variance = pca.explained_variance_ratio_
cumulative_variance = explained_variance.sum()

print("누적 설명 분산:", cumulative_variance)
~~~

주성분 개수를 선택할 때는 단순히 차원을 많이 줄이는 것만 목표로 삼으면 안 된다. 차원을 지나치게 줄이면 원본 데이터의 중요한 정보도 함께 손실될 수 있으므로, 누적 설명 분산 비율을 확인하며 적절한 개수를 결정해야 한다.

## 8. 판매 지표를 두 개의 주성분으로 압축하기

쇼핑몰 상품의 주문 횟수, 판매 수량, 매출액, 조회 수, 장바구니 추가 수는 서로 비슷하게 움직일 수 있다. 예를 들어 주문 횟수가 많은 상품은 판매 수량과 매출액도 높은 경우가 많다.

이처럼 상관된 Feature가 여러 개 존재하면 PCA를 이용하여 정보를 더 적은 수의 주성분으로 압축할 수 있다.

~~~python
import pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

data = pd.DataFrame({
    "order_count": [10, 20, 30, 50, 70, 90],
    "sales_count": [12, 24, 35, 60, 82, 105],
    "revenue": [100, 210, 310, 520, 730, 940],
    "views": [200, 350, 480, 700, 950, 1200],
    "cart_count": [15, 25, 40, 65, 90, 115],
})

scaler = StandardScaler()
X_scaled = scaler.fit_transform(data)

pca = PCA(n_components=2)
X_pca = pca.fit_transform(X_scaled)

print("기존 Feature 수:", data.shape[1])
print("변환 후 Feature 수:", X_pca.shape[1])
print("누적 설명 분산:", pca.explained_variance_ratio_.sum())
~~~

실행 결과 예시:

~~~text
기존 Feature 수: 5
변환 후 Feature 수: 2
누적 설명 분산: 0.9998832605670367
~~~

5개의 Feature를 2개의 주성분으로 줄였지만, 두 주성분이 전체 분산의 약 99.99%를 설명한다. 서로 비슷하게 움직이는 판매 지표들의 정보가 주성분에 압축되었기 때문에 적은 수의 Feature로도 대부분의 변동을 표현할 수 있다.

## 9. Feature Engineering으로서의 PCA

PCA로 만든 주성분을 원래 Feature 대신 머신러닝 모델의 입력으로 사용하는 것도 Feature Engineering의 한 방법이다.

| 기대 효과 | 설명 |
|---|---|
| 계산 효율 향상 | Feature 수가 줄어 학습과 예측에 필요한 계산량이 감소한다. |
| 중복 정보 압축 | 서로 상관된 Feature를 더 적은 수의 주성분으로 표현한다. |
| 노이즈 감소 | 분산이 작은 방향을 제거하여 노이즈가 줄어들 수 있다. |
| Overfitting 완화 | 차원이 감소하여 과대적합 위험을 줄이는 데 도움이 될 수 있다. |
| 시각화 | 고차원 데이터를 2차원이나 3차원으로 변환해 구조를 살펴볼 수 있다. |

PCA를 적용한다고 항상 모델 성능이 향상되는 것은 아니다. 원본 데이터의 구조와 선택한 주성분 개수에 따라 중요한 정보가 손실될 수도 있으므로, PCA 적용 전후의 모델 성능을 비교해야 한다.

---

## 10. PCA의 한계와 고려사항

### 원본 Feature보다 해석하기 어렵다

PC1과 PC2는 여러 Feature가 섞여 만들어진 값이다. 따라서 원본 Feature를 그대로 사용할 때보다 각 값의 의미를 직관적으로 설명하기 어렵다.

예를 들어 PCA 적용 후에는 “매출이 예측에 얼마나 영향을 주었는가?”와 같은 질문에 원본 Feature 기준으로 답하기 어려워질 수 있다.

### 중요한 정보가 손실될 수 있다

PCA는 분산이 큰 방향을 중요한 정보로 간주한다. 그러나 분석 문제에 따라 분산이 작은 방향에도 예측에 중요한 정보가 있을 수 있다. 너무 적은 주성분만 선택하면 필요한 정보까지 제거될 수 있다.

### Feature Scaling의 영향을 받는다

스케일을 맞추지 않으면 값의 범위가 큰 Feature가 주성분을 지배할 수 있다. PCA 전처리 과정과 실제 서비스의 데이터 처리 과정에서 동일한 Scaling 기준을 유지해야 한다.

### 해석 가능성과 효율성 사이의 선택이 필요하다

수백 개의 상관된 센서 Feature로 예측 모델을 만들고 개별 Feature의 의미가 중요하지 않다면 PCA가 유용할 수 있다. 반대로 각 Feature가 결과에 미치는 영향을 설명해야 한다면 원본 Feature를 유지하거나 해석 가능한 Feature 선택 방법을 고려할 수 있다.

## 11. PCA 적용 흐름

~~~text
1. 분석 목적과 원본 Feature를 확인한다.
2. 식별자처럼 분석에 의미 없는 Feature를 제거한다.
3. 학습 데이터를 기준으로 Feature를 표준화한다.
4. PCA를 학습하고 데이터를 주성분으로 변환한다.
5. 설명 분산 비율을 확인한다.
6. 사용할 주성분 개수를 결정한다.
7. 변환된 주성분을 모델의 입력으로 사용한다.
8. PCA 적용 전후의 성능과 해석 가능성을 비교한다.
~~~

실제 머신러닝 문제에서는 데이터 누수를 막기 위해 StandardScaler와 PCA를 학습 데이터에만 fit하고, 검증 데이터와 테스트 데이터에는 학습 데이터에서 구한 변환 기준으로 transform해야 한다.

## 12. 핵심 정리

- 데이터의 차원은 Feature의 개수를 의미한다.
- 차원이 지나치게 증가하면 데이터 희소성, 거리 구분의 어려움, 계산 비용 증가, Overfitting 위험이 발생할 수 있다.
- PCA는 원본 Feature를 단순히 선택하거나 삭제하지 않고 선형 결합하여 새로운 주성분을 만든다.
- 첫 번째 주성분은 데이터의 분산이 가장 큰 방향이다.
- 다음 주성분은 앞선 주성분과 직교하면서 남은 분산을 가장 많이 설명한다.
- 앞쪽 주성분 일부만 사용하면 중요한 변동을 최대한 유지하면서 차원을 줄일 수 있다.
- PCA 전에는 일반적으로 Feature의 스케일을 맞춰야 한다.
- 설명 분산 비율을 통해 각 주성분이 보존한 정보의 크기를 확인할 수 있다.
- PCA는 계산 효율 향상, 중복 정보 압축, 노이즈 감소, Overfitting 완화에 도움이 될 수 있다.
- 너무 많은 차원을 제거하면 중요한 정보가 손실되고, 주성분은 원본 Feature보다 해석하기 어렵다.

## 오늘의 한 문장

> PCA는 Feature를 단순히 버리는 방법이 아니라, 서로 겹치는 정보를 분산이 큰 새로운 축에 압축하여 더 적은 차원으로 표현하는 방법이다.
