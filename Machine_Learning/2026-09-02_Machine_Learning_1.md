## 1. AI, 머신러닝, 딥러닝, 생성형 AI의 관계

AI, 머신러닝, 딥러닝, 생성형 AI는 완전히 분리된 기술이 아니라 서로 포함되고 연결된 개념이다.

```text
인공지능(AI)
└── 머신러닝(ML)
    └── 딥러닝(DL)
        └── 오늘날 많은 생성형 AI의 기반 기술
```

생성형 AI가 반드시 딥러닝과 같은 개념인 것은 아니지만, 현재 널리 사용되는 생성형 AI는 대부분 딥러닝 모델을 기반으로 한다.

| 구분 | 의미 | 활용 예시 |
|---|---|---|
| 인공지능(AI) | 사람의 지능적인 문제 해결 능력을 컴퓨터로 구현하는 가장 넓은 개념 | 추론, 판단, 탐색, 계획 |
| 머신러닝(ML) | 데이터에서 패턴을 학습해 새로운 데이터를 예측·판단하는 AI의 한 분야 | 고객 이탈 예측, 사기 거래 탐지 |
| 딥러닝(DL) | 여러 층의 인공신경망으로 복잡한 패턴을 학습하는 머신러닝의 한 분야 | 이미지 분류, 음성 인식, 자연어 처리 |
| 생성형 AI | 학습한 패턴을 바탕으로 새로운 콘텐츠를 생성하는 AI | 텍스트, 이미지, 코드 생성 |

온라인 쇼핑몰에서는 다음과 같이 활용할 수 있다.

```python
ai_services = {
    "상품 구매 가능성 예측": "머신러닝",
    "상품 이미지 분류": "딥러닝",
    "고객 질문에 대한 답변 생성": "생성형 AI",
}

for service, technology in ai_services.items():
    print(f"{service}: {technology}")
```

### 머신러닝과 딥러닝의 차이

전통적인 머신러닝에서는 분석가가 예측에 중요한 특성을 직접 선택하거나 가공하는 경우가 많다. 딥러닝은 여러 신경망 층을 거치면서 데이터에서 필요한 특징을 자동으로 학습할 수 있다는 장점이 있다.

예를 들어 이미지 분류에서 딥러닝 모델은 초기 층에서 선과 모서리, 중간 층에서 눈과 귀 같은 부분, 깊은 층에서 동물 전체의 형태처럼 점점 복잡한 특징을 학습할 수 있다.

## 2. 머신러닝이란?

머신러닝은 사람이 모든 규칙을 직접 작성하지 않고, 데이터로부터 패턴과 규칙을 학습하여 새로운 데이터에 대한 예측이나 판단을 수행하는 기술이다.

예를 들어 금융 거래의 사기 여부를 예측하려면 과거의 정상 거래와 사기 거래를 모델에 제공한다. 모델은 거래 금액, 시간, 지역, 사용 패턴 등의 특성과 실제 사기 여부 사이의 관계를 학습하고, 이후 처음 보는 거래의 사기 가능성을 예측한다.

머신러닝에서 컴퓨터가 ‘학습한다’는 말은 사람처럼 공부한다는 뜻이 아니다. 학습 데이터에 대한 예측 오차를 줄이도록 모델 내부의 파라미터를 조정하는 과정이라고 이해할 수 있다.

### 머신러닝의 핵심 목적

- 학습 데이터에 존재하는 패턴 찾기
- 처음 보는 데이터에 대한 예측 또는 판단
- 사람이 모든 조건을 직접 규칙으로 정의하기 어려운 문제 해결

모델이 학습 데이터만 잘 기억하는 것이 아니라 새로운 데이터에도 잘 작동하는 능력을 **일반화(Generalization)**라고 한다.

## 3. 전통적인 프로그래밍과 머신러닝의 차이

두 방식의 가장 큰 차이는 **문제 해결 규칙을 누가 만드는가**이다.

### 전통적인 프로그래밍

사람이 규칙을 직접 코드로 작성하고 컴퓨터는 규칙에 따라 결과를 출력한다.

```text
데이터 + 사람이 작성한 규칙 → 결과
```

```python
login_count = 2
days_since_last_login = 25

if login_count <= 3 and days_since_last_login >= 20:
    print("탈퇴 위험 고객")
else:
    print("일반 고객")
```

### 머신러닝

학습 데이터와 정답을 제공하면 컴퓨터가 데이터와 정답 사이의 패턴을 학습해 모델을 만든다.

```text
학습 데이터 + 정답(Label) → 학습 알고리즘 → 모델
새로운 데이터 + 학습된 모델 → 예측 결과
```

| 구분 | 전통적인 프로그래밍 | 머신러닝 |
|---|---|---|
| 사람이 하는 일 | 규칙을 직접 작성 | 데이터와 정답을 준비하고 모델을 선택·평가 |
| 컴퓨터가 하는 일 | 규칙에 따라 결과 계산 | 데이터에서 예측 패턴 학습 |
| 학습 단계의 출력 | 결과 | 학습된 모델 |
| 적합한 문제 | 규칙이 명확하고 안정적인 문제 | 규칙이 복잡하거나 데이터에 패턴이 숨어 있는 문제 |

### 머신러닝이 항상 더 좋은 것은 아니다

주문 금액이 50,000원 이상이면 무료 배송이고, 그렇지 않으면 배송비가 3,000원인 정책은 규칙이 명확하다.

```python
order_amount = 43000

if order_amount >= 50000:
    shipping_fee = 0
else:
    shipping_fee = 3000

print(f"배송비: {shipping_fee:,}원")
```

이 문제에 머신러닝을 사용하면 예측 오차가 발생할 수 있고 구현도 더 복잡해진다. 반면 스팸 메일, 고객 이탈, 이미지 인식처럼 모든 조건을 사람이 나열하기 어려운 문제에서는 머신러닝이 유용하다.

따라서 모델을 만들기 전에 다음을 먼저 확인해야 한다.

1. 규칙만으로 정확하게 해결할 수 있는가?
2. 학습에 필요한 데이터가 충분히 존재하는가?
3. 예측해야 하는 대상이 명확한가?
4. 예측 결과가 실제 비즈니스 행동으로 연결되는가?

## 4. 머신러닝의 학습 유형

학습 유형은 우선 **정답(Label)의 존재 여부**로 구분할 수 있다.

| 학습 유형 | 정답 유무 | 목적 | 대표 작업 |
|---|---|---|---|
| 지도학습 | 있음 | 입력과 정답의 관계를 학습해 새로운 값 예측 | 분류, 회귀 |
| 비지도학습 | 없음 | 데이터 안의 숨은 구조와 패턴 탐색 | 군집화, 차원 축소 |

## 5. 지도학습(Supervised Learning)

지도학습은 입력 데이터와 정답이 함께 있는 데이터로 모델을 학습하는 방식이다. 모델은 특성과 정답 사이의 관계를 학습한 뒤 처음 보는 입력의 정답을 예측한다.

지도학습은 예측하려는 정답의 형태에 따라 분류와 회귀로 나뉜다.

### 분류(Classification)

미리 정해진 범주 중 하나를 예측하는 문제이다.

- 고객의 다음 달 재구매 여부: 재구매 / 미구매
- 이메일의 스팸 여부: 스팸 / 정상
- 금융 거래의 사기 여부: 사기 / 정상
- 이미지 속 상품 종류: 운동화 / 셔츠 / 가방

범주가 숫자 `0`, `1`로 표현되더라도 그 숫자가 범주의 이름 역할을 한다면 분류 문제이다.

### 회귀(Regression)

연속적인 수치를 예측하는 문제이다.

- 다음 달 고객 구매 금액
- 아파트 가격
- 다음 주 매출
- 예상 배송 시간

### 분류와 회귀를 구분하는 질문

```text
예측하려는 정답이 무엇인가?
        ↓
종류·상태·여부인가? → 분류
연속적인 숫자인가? → 회귀
```

예를 들어 고객의 구매 금액과 구매 횟수를 이용하더라도 ‘재구매 여부’를 예측하면 분류이고 ‘다음 달 구매 금액’을 예측하면 회귀이다. 입력 데이터가 아니라 **예측 대상의 형태**가 문제 유형을 결정한다.

## 6. 비지도학습(Unsupervised Learning)

비지도학습은 정답이 없는 데이터에서 구조나 패턴을 찾는 방식이다.

### 군집화(Clustering)

서로 비슷한 데이터를 같은 그룹으로 묶는다.

- 구매 행동이 비슷한 고객끼리 그룹화
- 이용 패턴이 비슷한 사용자 세분화
- 유사한 상품 묶기

군집의 이름과 의미는 모델이 자동으로 알려주는 정답이 아니다. 분석가가 각 군집의 특성을 살펴보고 ‘고가 상품 선호 고객’, ‘이탈 위험 고객’처럼 비즈니스 의미를 해석해야 한다.

### 차원 축소(Dimensionality Reduction)

많은 특성에 포함된 정보를 가능한 한 유지하면서 더 적은 수의 새로운 특성으로 표현한다.

- 고차원 데이터 시각화
- 데이터 압축
- 중복 정보 감소
- 모델 학습 전 데이터 구조 탐색

### 쇼핑몰 문제 구분하기

| 문제 | 학습 유형 |
|---|---|
| 고객이 다음 달 구독을 해지할지 예측 | 지도학습 - 분류 |
| 다음 달 예상 구매 금액 예측 | 지도학습 - 회귀 |
| 정답 없이 구매 행동이 비슷한 고객 그룹화 | 비지도학습 - 군집화 |

## 7. 강화학습은 무엇인가?

강화학습(Reinforcement Learning)은 지도학습이나 비지도학습과 구분되는 또 다른 학습 방식이다. 에이전트가 환경에서 행동하고 보상이나 벌점을 받으면서 장기적인 누적 보상을 크게 만드는 행동 전략을 학습한다.

```text
상태 관찰 → 행동 선택 → 보상과 다음 상태 확인 → 행동 전략 개선
```

게임 플레이, 로봇 제어, 자원 배분 등 순차적인 의사결정 문제에 활용된다. 정답 레이블을 직접 제공받는 지도학습과 달리 행동의 결과로 얻은 보상을 학습 신호로 사용한다.

## 8. 머신러닝의 구성 요소와 기본 용어

집값 예측 데이터를 예로 들면 다음과 같다.

| 면적(㎡) | 방 개수 | 건축 연도 | 집값(억 원) |
|---:|---:|---:|---:|
| 59 | 2 | 2018 | 6.5 |
| 84 | 3 | 2020 | 9.2 |
| 102 | 4 | 2016 | 11.8 |
| 74 | 3 | 2022 | 8.3 |

| 용어 | 의미 | 집값 예측 예시 |
|---|---|---|
| 데이터셋(Dataset) | 모델 학습·평가에 사용하는 데이터의 전체 집합 | 표 전체 |
| 데이터(Data) | 데이터셋을 구성하는 하나의 사례 | 한 채의 집에 대한 한 행 |
| 특성(Feature) | 모델이 예측에 사용하는 입력 속성 | 면적, 방 개수, 건축 연도 |
| 레이블(Label) | 모델이 예측해야 하는 정답 | 집값 |
| 모델(Model) | 입력을 받아 예측값을 출력하는 함수 | 특성으로 집값을 계산하는 함수 $f(X)$ |
| 학습(Training) | 데이터와 정답의 관계를 모델이 익히는 과정 | 예측 오차가 작아지도록 모델 조정 |
| 예측(Prediction) | 학습된 모델로 새로운 입력의 결과를 계산하는 과정 | 새로운 집의 가격 예측 |

일반적으로 여러 샘플의 특성을 모은 입력을 대문자 $X$, 정답을 $y$로 표현한다.

```python
import pandas as pd

houses = pd.DataFrame({
    "면적": [59, 84, 102, 74],
    "방개수": [2, 3, 4, 3],
    "건축연도": [2018, 2020, 2016, 2022],
    "집값": [6.5, 9.2, 11.8, 8.3],
})

X = houses[["면적", "방개수", "건축연도"]]
y = houses["집값"]

print("특성 데이터")
print(X)
print("\n레이블")
print(y)
```

### 특성이 많을수록 좋은 모델일까?

반드시 그렇지는 않다. 예측과 관련된 의미 있는 특성은 도움이 되지만, 관련 없는 특성이나 품질이 낮은 데이터는 잡음을 늘려 모델의 성능과 해석 가능성을 떨어뜨릴 수 있다.

따라서 EDA와 전처리를 통해 다음을 확인해야 한다.

- 결측치와 이상치
- 잘못된 자료형
- 중복되거나 불필요한 특성
- 데이터 누수 가능성이 있는 특성
- 예측 시점에 실제로 사용할 수 있는 특성

## 9. 머신러닝 프로젝트의 기본 흐름

머신러닝 프로젝트는 모델 학습부터 시작하지 않는다. 해결할 비즈니스 문제와 예측 결과의 활용 방법을 먼저 정의해야 한다.

고객 이탈 예측을 예로 들면 다음과 같은 흐름으로 진행할 수 있다.

1. **문제 정의**
   - 이탈의 기준과 예측 시점을 정한다.
   - 예측 결과로 어떤 고객에게 어떤 조치를 할지 정한다.
2. **데이터 수집 및 이해**
   - 로그인, 구매, 문의, 구독 상태 등의 데이터를 확보한다.
   - 각 행과 열의 의미, 수집 기간, 품질을 확인한다.
3. **EDA와 전처리**
   - 결측치, 이상치, 중복, 클래스 불균형을 확인한다.
   - 모델이 사용할 특성과 레이블을 만든다.
4. **학습·검증 데이터 분리**
   - 모델을 학습할 데이터와 성능을 확인할 데이터를 분리한다.
5. **모델 학습**
   - 문제 유형에 맞는 알고리즘을 선택하고 학습한다.
6. **평가와 개선**
   - 비즈니스 목적에 맞는 평가 지표로 성능을 확인한다.
   - 특성, 모델, 하이퍼파라미터를 개선한다.
7. **배포와 모니터링**
   - 실제 서비스에서 예측 결과를 사용한다.
   - 데이터 변화와 성능 저하를 지속적으로 확인한다.

정확도가 높은 모델을 만드는 것만으로 프로젝트가 끝나는 것은 아니다. 예측이 실제 의사결정에 활용되고 비즈니스 문제를 개선해야 의미가 있다.

## 10. 코딩 테스트 사전 학습: 이분 탐색

이분 탐색(Binary Search)은 **정렬된 데이터**에서 가운데 값과 목표값을 비교하며 탐색 범위를 절반씩 줄이는 알고리즘이다.

예를 들어 `[10, 20, 30, 40, 50, 60, 70]`에서 60을 찾는다면 가운데 값 40보다 크므로 왼쪽 절반을 버리고 `[50, 60, 70]`만 탐색한다.

### 사용자 ID 찾기

```python
def solution(user_ids, target):
    left = 0
    right = len(user_ids) - 1

    while left <= right:
        mid = (left + right) // 2

        if user_ids[mid] == target:
            return mid
        elif user_ids[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1


print(solution([101, 203, 305, 407, 509], 305))  # 2
print(solution([10, 20, 30, 40, 50, 60], 60))   # 5
print(solution([2, 4, 6, 8, 10], 7))             # -1
```

### 이분 탐색 핵심

- 데이터가 반드시 정렬되어 있어야 한다.
- `left`와 `right`는 현재 탐색 범위의 양 끝 인덱스이다.
- `mid = (left + right) // 2`로 가운데 인덱스를 계산한다.
- 목표가 가운데 값보다 크면 `left = mid + 1`로 이동한다.
- 목표가 가운데 값보다 작으면 `right = mid - 1`로 이동한다.
- 값을 찾지 못하고 반복문이 끝나면 `-1`을 반환한다.
- 시간 복잡도는 $O(\log n)$으로, 선형 탐색의 $O(n)$보다 큰 정렬 데이터에서 효율적이다.

학습 자료의 풀이 과정에는 마지막에 `1`을 반환한다는 문장이 있지만, 문제 설명과 입출력 예시에 따라 찾지 못했을 때 반환해야 하는 값은 `-1`이다.

## 11. 오늘 배운 내용 정리

1. AI는 가장 넓은 개념이며 머신러닝은 AI, 딥러닝은 머신러닝의 하위 분야이다.
2. 현재의 많은 생성형 AI는 딥러닝을 기반으로 텍스트, 이미지, 코드 등의 새로운 콘텐츠를 만든다.
3. 전통적인 프로그래밍은 사람이 규칙을 작성하고, 머신러닝은 데이터에서 모델이 패턴을 학습한다.
4. 규칙이 명확한 문제에는 전통적인 프로그래밍이 더 적합할 수 있다.
5. 정답이 있는 데이터로 학습하면 지도학습, 정답 없이 구조를 찾으면 비지도학습이다.
6. 지도학습에서 범주를 예측하면 분류, 연속적인 숫자를 예측하면 회귀이다.
7. 특성은 예측에 사용하는 입력이고 레이블은 모델이 예측해야 하는 정답이다.
8. 특성의 개수가 많다고 항상 성능이 좋아지는 것은 아니며 데이터 품질과 관련성이 중요하다.
9. 머신러닝 프로젝트는 비즈니스 문제 정의와 데이터 준비에서 시작해야 한다.
10. 이분 탐색은 정렬된 데이터의 탐색 범위를 절반씩 줄여 $O(\log n)$에 값을 찾는다.

## 12. 느낀 점

AI, 머신러닝, 딥러닝, 생성형 AI를 서로 다른 기술로만 생각했는데, 이번 학습을 통해 포함 관계와 각 기술의 역할을 구분할 수 있게 되었다. 특히 머신러닝은 사람이 아무것도 하지 않아도 컴퓨터가 알아서 학습하는 기술이 아니라, 사람이 문제를 정의하고 적절한 데이터와 특성을 준비해야 하는 과정이라는 점이 중요하게 느껴졌다.

또한 어떤 문제든 머신러닝으로 해결하는 것이 좋은 것은 아니며, 배송비 정책처럼 규칙이 명확한 문제는 일반적인 코드가 더 정확하고 단순하다는 점을 배웠다. 앞으로 프로젝트를 진행할 때 모델부터 선택하지 않고 해결하려는 비즈니스 문제, 예측 대상, 정답 데이터의 존재 여부를 먼저 확인한 뒤 분류·회귀·비지도학습 중 적절한 접근을 선택해야겠다.
