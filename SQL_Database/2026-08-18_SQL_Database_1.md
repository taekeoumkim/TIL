## SQL, Data 기초

### 데이터 사이언티스트와 SQL

데이터 사이언티스트는 단순히 머신러닝 모델을 만드는 사람이 아니라, **데이터 수집 → 전처리 및 분석 → 모델링 → 평가 → 비즈니스 적용**까지 연결하여 비즈니스 문제를 해결하는 역할을 한다.

특히 실제 업무에서는 데이터가 데이터베이스에 저장되어 있기 때문에, 모델링을 시작하기 전에 필요한 데이터를 정확하게 정의하고 추출하는 과정이 중요하다.

SQL을 활용하면 개발자나 데이터 엔지니어에게 데이터를 매번 요청하지 않고 직접 필요한 데이터를 조회하고, 분석에 적합한 형태로 필터링·결합·집계할 수 있다.

데이터 사이언티스트에게 필요한 핵심 역량은 다음과 같다.

- **SQL**: 데이터베이스에서 필요한 데이터를 직접 추출하고 가공
- **Python**: 데이터 전처리, 분석, 시각화, 머신러닝 모델링
- **통계 및 머신러닝**: 데이터의 패턴을 이해하고 예측·분류 모델 설계
- **비즈니스 커뮤니케이션**: 분석 결과를 실제 문제 해결로 연결

---

### Data, Database, Query, SQL

각 개념을 쇼핑몰의 주문 데이터를 기준으로 이해할 수 있다.

- **Data**: 이름, 금액, 날짜와 같은 개별적인 사실이나 값
- **Database**: 데이터를 체계적으로 저장하고 관리하는 공간
- **Query**: 데이터베이스에 보내는 질문이나 명령
- **SQL**: Query를 작성하기 위해 사용하는 표준화된 언어

예를 들어 `2026년 7월에 발생한 주문을 보여주세요`라는 요청을 SQL로 표현하면 다음과 같다.

```sql
SELECT *
FROM orders
WHERE order_date >= '2026-07-01'
  AND order_date < '2026-08-01';
```

SQL은 데이터베이스에 원하는 데이터를 요청하기 위한 언어이며, 실제 요청을 처리하는 역할은 DBMS가 담당한다.

---

### DBMS

**DBMS(Database Management System)**는 데이터베이스를 생성·관리·운영하는 소프트웨어 시스템이다.

사용자가 SQL을 통해 데이터를 요청하면 DBMS가 SQL을 해석하여 데이터를 조회하거나 저장·수정·삭제한다.

대표적인 DBMS는 다음과 같다.

| DBMS | 특징 | 주요 사용처 |
| --- | --- | --- |
| MySQL | 오픈소스, 가볍고 빠름 | 웹 서비스, 스타트업 |
| PostgreSQL | 오픈소스, 기능이 풍부하고 안정적 | 데이터 분석, 대기업 |
| Oracle | 상용, 대용량 처리에 강함 | 금융, 공공기관 |
| SQL Server | Microsoft, Windows 환경 최적화 | 기업 환경 |
| SQLite | 초경량, 파일 기반 | 모바일, 임베디드 |
| MariaDB | MySQL에서 파생된 오픈소스 | 웹 서비스 |

DBMS가 달라도 `SELECT`, `WHERE`, `GROUP BY`, `JOIN`과 같은 SQL의 핵심 개념은 대부분 비슷하다.

다만 함수, 데이터 타입, 날짜 처리나 데이터 개수 제한 방법처럼 세부 문법은 DBMS마다 차이가 있을 수 있다.

이번 학습에서는 **PostgreSQL**을 기준으로 SQL을 학습한다.

### 관계형 데이터베이스

관계형 데이터베이스(RDBMS)는 데이터를 **테이블 형태**로 저장한다.

예를 들어 고객 정보와 주문 정보를 하나의 거대한 공간에 저장하는 대신 각각의 테이블로 나누어 관리할 수 있다.

```text
[customers]
customer_id | name
------------+-------
1           | 김민수
2           | 이지수

[orders]
order_id | customer_id | amount
---------+-------------+-------
101      | 1           | 30000
102      | 1           | 50000
103      | 2           | 20000
```

두 테이블이 `customer_id`라는 공통된 값을 가지고 있기 때문에 서로 연결하여 분석할 수 있다.

```sql
SELECT customers.name, orders.amount
FROM customers
JOIN orders
  ON customers.customer_id = orders.customer_id;
```

관계형 데이터베이스의 장점은 데이터를 여러 테이블로 나누어 관리하면서도 필요할 때 관계를 이용해 다시 연결할 수 있다는 것이다.

#### 데이터 저장 모델

데이터를 저장하고 관계를 표현하는 방식에 따라 다음과 같이 구분할 수 있다.

- **계층형(HDBMS)**: 트리 구조, 부모-자식 관계
- **관계형(RDBMS)**: 테이블의 행과 열로 구성
- **망형(NDBMS)**: 네트워크 구조, 다대다 관계 표현

관계형 데이터베이스는 테이블 형태라 직관적으로 이해하기 쉽고, 여러 테이블을 연결하여 복잡한 데이터 관계를 표현할 수 있다는 장점이 있다.

---

### Table, Row, Column, Cell

관계형 데이터베이스의 테이블은 엑셀과 비슷하게 **행(Row)**과 **열(Column)**로 구성된다.

```text
customer_id | name   | grade  | point
------------+--------+--------+------
1           | 김민수  | GOLD   | 3500
2           | 이지수  | SILVER | 1200
3           | 박서준  | GOLD   | 2800
```

- **Table**: 관련된 데이터의 집합
- **Row**: 하나의 데이터 항목 또는 하나의 개체에 대한 정보
- **Column**: 데이터가 가지고 있는 속성
- **Cell**: 특정 행과 열이 만나는 하나의 값

예를 들어 김민수 고객의 전체 정보는 하나의 Row이고, `name`, `grade`, `point`는 각각 Column이다. 김민수의 `3500`은 특정 Row와 Column이 만나는 Cell이다.

특정 Column만 조회할 수도 있다.

```sql
SELECT name, point
FROM customers;
```

### SQL 작성 순서와 실행 순서

SQL은 작성하는 순서와 실제 데이터베이스에서 처리되는 순서가 다르다.

일반적인 SQL 작성 순서는 다음과 같다.

```text
SELECT
FROM
WHERE
GROUP BY
HAVING
ORDER BY
```

반면 실제 실행 순서는 다음과 같다.

```text
FROM
→ WHERE
→ GROUP BY
→ HAVING
→ SELECT
→ ORDER BY
```

예시:

```sql
SELECT category,
       SUM(amount) AS total_amount
FROM orders
WHERE status = '완료'
GROUP BY category
HAVING SUM(amount) >= 100000
ORDER BY total_amount DESC;
```

실제 처리 과정은 다음과 같다.

1. `FROM`에서 `orders` 테이블을 가져온다.
2. `WHERE`에서 완료된 주문만 남긴다.
3. `GROUP BY`에서 category별로 그룹화한다.
4. `HAVING`에서 합계가 100000 이상인 그룹만 남긴다.
5. `SELECT`에서 필요한 결과를 만든다.
6. `ORDER BY`에서 결과를 정렬한다.

이 실행 순서를 이해하면 복잡한 SQL에서 오류가 발생했을 때 원인을 파악하기 쉽다.

특히 `SELECT`에서 정의한 별칭(alias)을 `WHERE`에서 사용할 수 없는 이유도 실행 순서로 이해할 수 있다. `WHERE`가 `SELECT`보다 먼저 실행되기 때문이다.

### PostgreSQL 환경 구축

이번 강의에서는 PostgreSQL을 사용한다.

설치 과정은 다음과 같다.

1. PostgreSQL 공식 다운로드 페이지에서 Windows Installer를 다운로드한다.
2. 설치 프로그램을 실행하고 기본 설정으로 설치한다.
3. `postgres` 관리자 계정의 비밀번호를 설정한다.
4. Port는 기본값인 `5432`를 사용한다.
5. 기본 옵션으로 설치를 진행한다.
6. `pgAdmin 4`가 설치되었는지 확인하고 실행한다.
7. `default workspace → PostgreSQL 18 → Database`를 선택하고 비밀번호를 입력한다.

SQL을 보다 편하게 관리하기 위한 도구로 **DBeaver**도 설치할 수 있다.

## 오늘 배운 핵심

1. 데이터 사이언티스트에게 SQL은 단순 조회 도구가 아니라 데이터 탐색, 전처리, 특성 생성, 모델링 데이터셋 구축에 활용되는 핵심 역량이다.
2. Data는 개별적인 값이고, Database는 데이터를 체계적으로 저장하는 공간이며, Query는 데이터베이스에 보내는 질문이나 명령이다.
3. SQL은 데이터베이스에 명령을 전달하는 언어이고, DBMS는 SQL을 해석하여 실제 데이터베이스를 관리한다.
4. 관계형 데이터베이스는 데이터를 테이블로 나누어 관리하고, 공통된 값을 이용하여 테이블을 연결할 수 있다.
5. Table은 데이터의 집합이고, Row는 데이터 항목, Column은 속성, Cell은 하나의 값이다.
6. SQL의 **작성 순서와 실제 실행 순서는 다르다.**
7. SQL의 기본 실행 순서는 `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`이다.
8. 이번 과정에서는 PostgreSQL을 기준으로 SQL을 학습한다.

## 느낀 점

이번 학습을 통해 SQL을 단순히 데이터를 조회하는 문법으로 생각하기보다, 데이터 사이언스 업무를 시작하기 위한 기본 도구로 이해하게 되었다.

특히 **SQL 작성 순서와 실제 실행 순서가 다르다는 점**이 중요하다고 느꼈다. 앞으로 복잡한 SQL을 작성하면서 오류가 발생했을 때 단순히 문법만 확인하는 것이 아니라 실제 실행 흐름을 기준으로 원인을 생각해야겠다.

또한 데이터 사이언티스트의 업무가 모델링에서 끝나는 것이 아니라 데이터 추출부터 분석, 모델 평가, 비즈니스 적용까지 이어진다는 점을 기억하고, SQL과 Python을 함께 활용할 수 있는 역량을 키워야겠다.
