# 2026-08-21 SQL 서브쿼리: WHERE절, 인라인 뷰, 스칼라 서브쿼리

## 학습 목표

-   서브쿼리(Subquery)의 개념과 외부 쿼리(Outer Query)의 관계를
    이해한다.
-   서브쿼리가 위치하는 `WHERE`, `FROM`, `SELECT`절에 따라 역할이
    달라지는 것을 구분한다.
-   `WHERE`절 서브쿼리와 비교 연산자를 사용하여 동적인 조건을 작성한다.
-   `IN` / `NOT IN`을 이용해 서브쿼리가 반환한 여러 값과 비교한다.
-   `EXISTS`를 이용해 관련 데이터의 존재 여부를 조건으로 확인한다.
-   `FROM`절의 인라인 뷰(Inline View)를 이용해 집계 결과를 임시
    테이블처럼 활용한다.
-   `SELECT`절의 스칼라 서브쿼리(Scalar Subquery)를 이용해 단일 값을
    새로운 열로 추가한다.
-   상관 서브쿼리(Correlated Subquery)의 기본 구조를 이해한다.
-   서브쿼리와 `JOIN`의 차이를 이해하고 상황에 맞게 선택한다.

## 1. 서브쿼리(Subquery)란?

서브쿼리는 **하나의 SQL 쿼리 안에 포함된 또 다른 `SELECT` 쿼리**이다.

바깥쪽 쿼리를 **외부 쿼리(Outer Query)**, 안쪽 쿼리를 **서브쿼리(Inner
Query)**라고 한다.

서브쿼리는 보통 괄호 `( )` 안에 작성하며, 외부 쿼리가 필요로 하는 값을
먼저 계산하거나 필요한 데이터를 찾아 전달하는 역할을 한다.

예를 들어 전체 상품의 평균 가격보다 비싼 상품을 찾는다면 먼저 평균
가격을 계산해야 한다.

``` sql
SELECT AVG(list_price)
FROM products;
```

이 쿼리를 `WHERE` 조건 안에 넣으면 다음과 같이 작성할 수 있다.

``` sql
SELECT product_id,
       product_name,
       list_price
FROM products
WHERE list_price > (
    SELECT AVG(list_price)
    FROM products
);
```

실행 흐름은 다음과 같이 이해할 수 있다.

``` text
서브쿼리 실행
    ↓
전체 상품의 평균 가격 계산
    ↓
계산된 값을 외부 쿼리에 전달
    ↓
list_price와 평균 가격 비교
    ↓
평균보다 비싼 상품 조회
```

수학의 `f(g(x))`처럼 **안쪽 쿼리의 결과가 바깥쪽 쿼리의 입력으로
사용되는 구조**라고 생각하면 이해하기 쉽다.

### 핵심

-   서브쿼리는 SQL 문 안에 포함된 또 다른 `SELECT` 문이다.
-   서브쿼리는 `( )` 안에 작성한다.
-   외부 쿼리에서 필요한 값을 계산하거나 데이터를 찾는 데 사용할 수
    있다.

## 2. 위치에 따른 서브쿼리 종류

서브쿼리는 SQL 문에서 어디에 위치하는지에 따라 역할과 특징이 달라진다.

  -----------------------------------------------------------------------
  위치                    명칭                    주요 역할
  ----------------------- ----------------------- -----------------------
  `WHERE`절               WHERE절 서브쿼리        조건값을 동적으로 계산

  `FROM`절                인라인 뷰(Inline View)  가상의 임시 테이블처럼
                                                  사용

  `SELECT`절              스칼라 서브쿼리(Scalar  하나의 행, 하나의 열에
                          Subquery)               해당하는 단일 값 반환
  -----------------------------------------------------------------------

즉, 서브쿼리를 사용할 때는 단순히 "쿼리 안에 쿼리를 넣는다"고
생각하기보다 **서브쿼리의 결과를 어디에서 어떤 목적으로 사용할
것인지**를 먼저 생각하는 것이 중요하다.

``` text
WHERE  → 조건을 만들기 위한 값
FROM   → 다시 조회할 수 있는 임시 테이블
SELECT → 결과에 추가할 하나의 값
```

## 3. WHERE절 서브쿼리

`WHERE`절 서브쿼리는 **조건에 사용할 값을 동적으로 계산할 때** 사용할 수
있다.

예를 들어 평균 재고 수량보다 재고가 많은 기록을 찾는 경우 평균값을 직접
계산하여 숫자로 입력할 수도 있지만, 데이터가 바뀌면 평균도 달라진다.

따라서 평균값 자체를 서브쿼리에서 계산하면 데이터가 변경되어도 쿼리를
수정할 필요가 없다.

``` sql
SELECT store_id,
       product_id,
       quantity
FROM stocks
WHERE quantity > (
    SELECT AVG(quantity)
    FROM stocks
);
```

괄호 안의 서브쿼리는 전체 재고의 평균 수량을 계산한다.

``` sql
SELECT AVG(quantity)
FROM stocks;
```

외부 쿼리는 이 결과를 이용하여 `quantity`가 평균보다 큰 행만 선택한다.

### 단일 값을 반환하는 서브쿼리

`AVG()`, `MAX()`, `MIN()`처럼 하나의 값을 반환하는 서브쿼리는 비교
연산자와 함께 사용할 수 있다.

``` text
>
<
=
```

예를 들어 평균 주문 금액보다 큰 주문만 찾는다면 다음과 같이 작성할 수
있다.

``` sql
SELECT order_id,
       customer_id,
       amount
FROM orders
WHERE amount > (
    SELECT AVG(amount)
    FROM orders
);
```

### 핵심

`WHERE`절 서브쿼리는 **고정된 숫자를 조건에 직접 입력하는 대신
데이터로부터 조건값을 계산한다**는 점이 중요하다.

## 4. IN + 서브쿼리

서브쿼리가 하나가 아니라 **여러 개의 값을 반환하는 경우**에는 `=` 대신
`IN`을 사용할 수 있다.

예를 들어 1번 매장에 재고 정보가 등록된 상품만 찾는다고 하자.

먼저 1번 매장에 등록된 상품 번호를 조회한다.

``` sql
SELECT product_id
FROM stocks
WHERE store_id = 1;
```

이 쿼리는 여러 개의 `product_id`를 반환할 수 있다.

따라서 외부 쿼리에서는 `IN`을 이용하여 각 상품 번호가 서브쿼리 결과
목록에 포함되어 있는지 확인한다.

``` sql
SELECT product_id,
       product_name,
       list_price
FROM products
WHERE product_id IN (
    SELECT product_id
    FROM stocks
    WHERE store_id = 1
);
```

실행 흐름은 다음과 같다.

``` text
stocks에서 1번 매장의 product_id 목록 조회
    ↓
예: [1, 3, 5, ...]
    ↓
products.product_id가 목록에 포함되는지 확인
    ↓
포함된 상품만 조회
```

### 기억할 점

-   서브쿼리가 여러 값을 반환하면 `IN`을 사용할 수 있다.
-   `IN`은 서브쿼리 결과 목록에 포함된 값을 찾는다.

------------------------------------------------------------------------

## 5. NOT IN + 서브쿼리와 NULL 주의사항

`NOT IN`은 `IN`과 반대로 **서브쿼리 결과 목록에 포함되지 않은 값**을
찾을 때 사용한다.

예를 들어 주문을 한 번도 하지 않은 고객을 찾는다면 다음과 같은 형태로
작성할 수 있다.

``` sql
SELECT customer_id,
       name
FROM customers
WHERE customer_id NOT IN (
    SELECT DISTINCT customer_id
    FROM orders
);
```

하지만 `NOT IN`을 사용할 때는 중요한 주의사항이 있다.

> **서브쿼리 결과에 `NULL`이 포함되면 전체 결과가 빈 값으로 나올 수
> 있다.**

따라서 `NOT IN`을 사용할 때는 서브쿼리가 반환하는 열에 `NULL`이 없는지
확인하는 습관이 필요하다.

학습 자료에서는 이러한 경우 `NOT EXISTS`를 사용하는 것이 더 안전할 수
있다고 설명했다.

------------------------------------------------------------------------

## 6. EXISTS를 이용한 존재 여부 확인

`EXISTS`는 서브쿼리에서 필요한 값의 목록 자체보다 **조건을 만족하는
데이터가 존재하는지**를 확인하고 싶을 때 사용할 수 있다.

예를 들어 각 매장에 재고 데이터가 하나라도 등록되어 있는지 확인한다고
하자.

``` sql
SELECT s.store_id,
       s.store_name
FROM stores s
WHERE EXISTS (
    SELECT 1
    FROM stocks st
    WHERE st.store_id = s.store_id
);
```

여기서 중요한 질문은 다음과 같다.

``` text
"이 매장의 재고 데이터가 존재하는가?"
```

즉, 상품 번호 목록을 직접 가져오는 것이 목적이 아니라 **해당 조건을
만족하는 행의 존재 여부**가 중요할 때 `EXISTS`를 사용할 수 있다.

------------------------------------------------------------------------

## 7. FROM절 서브쿼리: 인라인 뷰(Inline View)

`FROM`절에 위치한 서브쿼리를 **인라인 뷰(Inline View)**라고 한다.

인라인 뷰는 서브쿼리의 결과를 **데이터베이스에 실제로 저장되지 않는 임시
테이블처럼 사용**하는 방식이다.

예를 들어 매장별 상품 종류와 전체 재고 수량을 먼저 집계한 뒤, 전체
재고가 500개 이상인 매장만 조회할 수 있다.

``` sql
SELECT store_id,
       product_count,
       total_stock
FROM (
    SELECT store_id,
           COUNT(product_id) AS product_count,
           SUM(quantity) AS total_stock
    FROM stocks
    GROUP BY store_id
) AS store_summary
WHERE total_stock >= 500;
```

안쪽 쿼리가 먼저 실행되어 매장별 데이터를 집계한다.

``` sql
SELECT store_id,
       COUNT(product_id) AS product_count,
       SUM(quantity) AS total_stock
FROM stocks
GROUP BY store_id;
```

그 결과에 `store_summary`라는 별칭을 붙이면 외부 쿼리에서는 일반
테이블처럼 사용할 수 있다.

``` text
stocks 원본 데이터
    ↓
GROUP BY store_id
    ↓
매장별 집계 결과 생성
    ↓
store_summary라는 인라인 뷰
    ↓
WHERE total_stock >= 500
    ↓
조건에 맞는 매장만 조회
```

### 인라인 뷰의 주요 특징

-   `FROM`절의 서브쿼리를 인라인 뷰라고 한다.
-   서브쿼리의 결과를 임시 테이블처럼 외부 쿼리에서 사용할 수 있다.
-   집계 결과를 다시 필터링하거나 다른 데이터와 결합할 때 유용하다.
-   **반드시 별칭(alias)을 붙여야 한다.**
-   여러 열을 포함할 수 있다.
-   외부 쿼리에서 인라인 뷰의 열을 참조할 수 있다.

------------------------------------------------------------------------

## 8. SELECT절 서브쿼리: 스칼라 서브쿼리(Scalar Subquery)

`SELECT`절에 위치하여 **하나의 값을 반환하고 하나의 열처럼 사용되는
서브쿼리**를 스칼라 서브쿼리라고 한다.

`Scalar`는 단일 값을 의미한다.

예를 들어 각 상품의 가격 옆에 전체 상품 중 가장 비싼 가격을 함께 표시할
수 있다.

``` sql
SELECT product_id,
       product_name,
       list_price,
       (
           SELECT MAX(list_price)
           FROM products
       ) AS max_price
FROM products;
```

서브쿼리 부분은 전체 상품의 최고 가격 하나만 반환한다.

``` sql
SELECT MAX(list_price)
FROM products;
```

그 값이 `max_price`라는 새로운 열로 추가되기 때문에 각 상품의 가격과
전체 최고 가격을 한 화면에서 비교할 수 있다.

### 스칼라 서브쿼리의 조건

스칼라 서브쿼리는 반드시 다음 조건을 만족해야 한다.

``` text
1개의 행
+
1개의 열
=
1개의 값
```

`AVG()`, `MAX()`, `COUNT()` 같은 집계 함수를 사용하면 단일 값을 만들기
쉽다.

### 여러 행을 반환하면?

스칼라 서브쿼리가 여러 행을 반환하면 PostgreSQL에서 오류가 발생한다.

``` text
more than one row returned by a subquery used as an expression
```

따라서 스칼라 서브쿼리를 작성할 때는 `WHERE` 조건이나 `AVG`, `COUNT`,
`SUM` 등의 집계 함수를 이용해 **결과가 단 하나의 값이 되도록 해야
한다.**

## 9. 상관 서브쿼리(Correlated Subquery)

서브쿼리 안에서 **외부 쿼리의 현재 행 정보를 참조하는 방식**을 상관
서브쿼리라고 한다.

예를 들어 각 주문과 함께 해당 고객의 전체 주문 횟수를 표시할 수 있다.

``` sql
SELECT o.order_id,
       o.customer_id,
       o.amount,
       (
           SELECT COUNT(*)
           FROM orders o2
           WHERE o2.customer_id = o.customer_id
       ) AS total_orders_by_customer
FROM orders o;
```

여기서 서브쿼리 안의

``` sql
o2.customer_id = o.customer_id
```

부분은 외부 쿼리의 `o.customer_id`를 참조한다.

즉, 외부 쿼리의 각 행에 따라 서브쿼리가 참조하는 조건이 달라진다.

``` text
외부 쿼리의 현재 주문 행
    ↓
o.customer_id 확인
    ↓
서브쿼리에서 같은 customer_id의 주문 수 계산
    ↓
total_orders_by_customer 열에 추가
```

## 10. 서브쿼리와 JOIN 비교

서브쿼리와 `JOIN`은 서로 대체할 수 있는 경우가 많지만, 어떤 데이터를
결과에 사용하려는지에 따라 더 자연스러운 방법이 달라질 수 있다.

### 다른 테이블의 데이터를 조건으로만 사용하는 경우

예를 들어 주문한 적이 있는 고객의 목록만 확인하려면 `orders`의 열 자체가
필요한 것이 아니라 **해당 고객이 orders에 존재하는지**가 중요하다.

``` sql
SELECT customer_id,
       first_name,
       last_name
FROM customers
WHERE customer_id IN (
    SELECT customer_id
    FROM orders
);
```

이 경우 서브쿼리를 사용하면 조건 로직을 명확하게 분리할 수 있다.

### 다른 테이블의 열까지 함께 조회하는 경우

고객 이름과 함께 실제 주문 날짜까지 보고 싶다면 `orders.order_date`가
결과에 필요하다.

``` sql
SELECT c.customer_id,
       c.first_name,
       c.last_name,
       o.order_date
FROM customers c
JOIN orders o
    ON c.customer_id = o.customer_id;
```

이 경우에는 두 테이블의 열을 함께 가져오는 `JOIN`이 자연스럽다.

### 비교

  -----------------------------------------------------------------------
  비교 항목               서브쿼리                JOIN
  ----------------------- ----------------------- -----------------------
  가독성                  조건/계산 로직을        여러 테이블의 관계를
                          명확하게 분리           한눈에 파악

  반환 구조               외부 쿼리 기준의 열     여러 테이블의 열을
                          선택                    자유롭게 선택

  성능 관점               단순 조건 필터링에      대용량 데이터에서
                          유리할 수 있음          JOIN에 최적화된 경우가
                                                  많음

  NULL 처리               `EXISTS` 사용 시        `OUTER JOIN`으로 NULL
                          안전하게 처리 가능      제어 가능
  -----------------------------------------------------------------------

### 선택 기준

``` text
다른 테이블의 데이터를
조건으로만 사용할 것인가?
        ↓
     서브쿼리

다른 테이블의 열까지
결과에 함께 가져올 것인가?
        ↓
       JOIN
```

같은 결과를 만드는 방법이 여러 개라면 **가독성, 성능, 실행 계획, 실제
상황**을 함께 고려해야 한다.

## 11. 오늘의 핵심 SQL 패턴

### 평균보다 큰 값 찾기

``` sql
SELECT *
FROM table_name
WHERE value > (
    SELECT AVG(value)
    FROM table_name
);
```

### 여러 값 중 포함되는 데이터 찾기

``` sql
SELECT *
FROM table_a
WHERE id IN (
    SELECT id
    FROM table_b
);
```

### 데이터 존재 여부 확인하기

``` sql
SELECT *
FROM table_a a
WHERE EXISTS (
    SELECT 1
    FROM table_b b
    WHERE b.id = a.id
);
```

### 집계 결과를 임시 테이블처럼 사용하기

``` sql
SELECT *
FROM (
    SELECT group_column,
           SUM(value) AS total_value
    FROM table_name
    GROUP BY group_column
) AS summary
WHERE total_value >= 100;
```

### 단일 값을 새로운 열로 추가하기

``` sql
SELECT id,
       value,
       (
           SELECT AVG(value)
           FROM table_name
       ) AS avg_value
FROM table_name;
```

## 12. 오늘 배운 내용 정리

### 서브쿼리

-   SQL 쿼리 안에 포함된 또 다른 `SELECT` 쿼리
-   `( )` 안에 작성
-   외부 쿼리에 필요한 값이나 데이터를 먼저 계산할 수 있음

### WHERE절 서브쿼리

-   조회 조건에 필요한 값을 동적으로 계산
-   단일 값이면 `>`, `<`, `=` 등의 비교 연산자와 함께 사용 가능

### IN / NOT IN

-   `IN` → 서브쿼리 결과 목록에 포함된 값 조회
-   `NOT IN` → 서브쿼리 결과 목록에 포함되지 않은 값 조회
-   `NOT IN`은 서브쿼리 결과에 `NULL`이 포함되는 경우 주의

### EXISTS

-   실제 값의 목록보다 **조건을 만족하는 행이 존재하는지** 확인할 때
    사용

### 인라인 뷰

-   `FROM`절의 서브쿼리
-   서브쿼리 결과를 임시 테이블처럼 사용
-   집계 결과를 다시 필터링할 때 유용
-   별칭(alias)이 필요

### 스칼라 서브쿼리

-   `SELECT`절의 서브쿼리
-   반드시 하나의 행, 하나의 열에 해당하는 단일 값을 반환
-   계산 결과를 새로운 열처럼 추가할 때 사용

### 상관 서브쿼리

-   서브쿼리에서 외부 쿼리의 현재 행 정보를 참조

### 서브쿼리 vs JOIN

-   다른 테이블의 데이터를 **조건으로 활용** → 서브쿼리가 직관적일 수
    있음
-   여러 테이블의 **열을 함께 조회** → `JOIN`이 자연스러움
-   한 가지 방식이 항상 정답인 것은 아니며 가독성과 실행 계획도 고려해야
    함

## 13. 느낀 점

오늘은 SQL에서 단순히 한 테이블을 조회하는 것을 넘어, **쿼리의 결과를
다른 쿼리의 조건이나 데이터처럼 활용하는 서브쿼리**를 배웠다.

처음에는 쿼리 안에 또 다른 `SELECT`문이 들어가는 구조가 복잡하게 느껴질
수 있지만, 실제로는 **안쪽 쿼리가 먼저 필요한 값을 만들고 바깥쪽 쿼리가
그 결과를 사용한다**는 흐름으로 생각하니 이해하기 쉬웠다.

특히 서브쿼리의 위치에 따라 역할이 달라진다는 점이 중요했다.
`WHERE`절에서는 조건값을 만들고, `FROM`절에서는 집계 결과를 임시
테이블처럼 사용하며, `SELECT`절에서는 하나의 값을 새로운 열로 추가할 수
있었다.

또한 `IN`과 `NOT IN`을 사용하면 여러 값을 반환하는 서브쿼리를 조건에
활용할 수 있지만, `NOT IN`은 `NULL`이 포함되는 경우 주의해야 한다는 점도
기억해야겠다.

서브쿼리와 `JOIN`을 비교하면서 두 방법 중 하나가 무조건 더 좋은 것이
아니라 **다른 테이블을 조건으로만 사용할지, 아니면 다른 테이블의 열까지
결과에 가져올지**에 따라 적절한 방법을 선택해야 한다는 점도 알게 되었다.

앞으로 SQL 문제를 풀 때 바로 하나의 긴 쿼리를 작성하기보다,

> **필요한 값을 먼저 계산하고 → 그 결과를 어디에서 사용할지 결정하고 →
> WHERE / FROM / SELECT 중 적절한 위치에 서브쿼리를 작성하는 흐름**

을 생각하면서 연습해야겠다.
