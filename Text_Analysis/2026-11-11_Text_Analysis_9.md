# TIL | 2026-11-11 — LLM 워크플로우 설계와 단계별 검증

`quotes_clean.csv`의 명언을 분류하고 후속 분석하는 사례를 통해 단일 호출, 순차 처리, 조건부 분기를 배웠다. 처리 방식을 고를 때는 결과가 몇 개인지보다 **이전 결과가 다음 작업에 필요한지, 결과에 따라 실행할 작업이 달라지는지**를 살핀다.

## 1. 분석 목적에 맞는 처리 방식

| 방식 | 선택 기준 | 명언 분석 예시 | 고려할 점 |
| --- | --- | --- | --- |
| 단일 호출 | 한 요청으로 필요한 결과를 얻을 수 있다. | 명언을 분류하거나 `category`와 `summary`를 함께 반환한다. | 요청이 간단하고 호출 횟수가 적다. 한 요청에 작업을 많이 넣으면 결과별 확인이 어려워질 수 있다. |
| 순차 처리 | 다음 단계가 앞선 단계의 결과를 사용한다. | 주제를 먼저 분류하고, 그 주제와 원문을 함께 전달해 핵심 메시지를 설명한다. | 중간 결과를 따로 확인할 수 있다. 호출이 늘면 시간과 비용이 증가할 수 있고 앞 단계의 오류도 이어질 수 있다. |
| 조건부 분기 | 입력이나 중간 결과에 따라 다음 작업이 달라진다. | 성장 명언에서 실천 행동을 추출하고, 관계 명언에서 인간관계의 교훈을 정리한다. | 분기 조건과 실행할 작업을 미리 정하고, 누락되거나 예상 밖인 값의 처리도 정한다. |

*Small steps can lead to big changes.*에서 주제와 요약만 필요하다면 한 번의 요청으로 두 값을 받을 수 있다. 분류 결과를 확인한 뒤 그 주제의 관점에서 해석해야 한다면 단계로 나눈다. 주제에 따라 **요약의 관점**을 바꾸는 수준을 넘어 **분석 작업 자체**가 달라진다면 분기를 둔다.

분기 조건은 LLM이 반환한 분류값이나 프로그램에 이미 있는 데이터와 규칙을 사용할 수 있다. 이번 워크플로우에서는 프로그램이 미리 정한 경로를 선택한다. Agent는 다음 행동을 모델이 선택하는 방식으로 학습자료에서 구분했다.

## 2. 단계별 입력과 출력 연결

```text
명언 원문 → 주제 분류 → 분류 결과 검증 → 분석 경로 선택
→ 원문과 선택한 분석 지시 전달 → 후속 결과 확인 및 저장
```

| 단계 | 입력 | 출력 또는 처리 |
| --- | --- | --- |
| 주제 분류 | 명언 원문과 분류 기준 | `성장`, `관계`, `기타` 중 하나 |
| 분기 선택 | 검증한 분류값 | 성장 → 실천 행동 추출, 관계 → 관계의 교훈 정리, 기타 → 일반적인 핵심 의미 요약 |
| 후속 분석 | 명언 원문과 선택한 분석 지시 | 해당 주제에 맞는 메시지 |
| 저장 | 문서 ID, 원문, 중간 결과, 후속 결과 | 문서별 분석 결과와 처리 상태 |

*Kindness makes relationships stronger.*가 `관계`로 분류되면 관계의 교훈을 정리하는 경로를 선택한다. 후속 단계에서 **분류값은 분석 방향을 정하고, 명언 원문은 메시지를 작성하는 근거가 된다.**

## 3. 중간 결과 검증과 오류 전파

분기 전에는 분류 결과가 존재하고 허용된 범주에 속하는지 확인한다. `우정`처럼 허용 목록에 없는 값이나 빈 결과는 오류 상태로 기록하고 후속 분석을 멈춘다. `기타`는 정상 분류 범주로 따로 관리한다.

허용값 검사와 내용 평가는 별개다. 인간관계에 관한 명언을 `성장`으로 잘못 분류하면 허용값 검사는 통과하지만 성장 분석이 실행된다. 이처럼 이전 단계의 오류가 다음 작업이나 결과에 영향을 주는 현상을 **오류 전파**라고 한다.

| 문제가 발생한 단계 | 확인할 내용 |
| --- | --- |
| 입력 준비 | 명언 본문이 있는가? |
| 주제 분류 | 결과가 반환됐고 허용 범주에 속하는가? |
| 분기 선택 | 분류값에 맞는 분석 작업이 실행됐는가? |
| 후속 분석 | API 요청이 완료됐고 필요한 결과가 반환됐는가? |
| 결과 저장 | 모든 문서 ID에 처리 상태가 기록됐고 결과가 원본에 올바르게 연결됐는가? |

## 4. 문서별 처리 상태와 재시도

| 문서 ID | 분류 | 후속 결과 | 처리 상태 |
| --- | --- | --- | --- |
| Q001 | 성장 | 작은 행동이 변화를 만듦 | 성공 |
| Q002 | 관계 | 배려가 관계를 강화함 | 성공 |
| Q003 | — | — | 주제 분류 실패 |
| Q004 | 성장 | — | 후속 분석 실패 |

Q003은 분류 단계부터 확인한다. Q004는 저장된 분류 결과를 재사용할 수 있다면 후속 단계만 다시 실행할 수 있다. 재시도 전에는 이전 요청이 완료됐는지와 결과가 이미 저장됐는지 확인한다.

## 배운 점

후속 분석 결과가 비어 있다는 사실만으로는 어디서 다시 시작해야 할지 알 수 없다. 원문과 함께 분류값, 선택한 경로, 실패 단계를 기록하면 단계 간 연결을 검증하고 필요한 작업만 다시 실행할 수 있다.
