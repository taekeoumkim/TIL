# TIL | 2026-11-09 — 텍스트 데이터와 분석 목적별 전처리

## 오늘의 학습 주제

텍스트 데이터의 특성과 전체 분석 흐름을 이해하고, 텍스트 정제·토큰화·형태소 분석의 역할을 배웠다. 같은 문장이라도 키워드 추출, 의미 검색, 분류·요약 중 무엇을 하려는지에 따라 필요한 전처리와 결과 구조가 달라진다는 점을 학습했다.

## 1. 텍스트 데이터의 특징

평점이나 구매 금액은 평균과 분포를 계산할 수 있지만, 리뷰에는 여러 대상에 대한 평가와 맥락이 함께 담겨 있다.

> 배송은 빨랐지만 상품이 파손되어 왔어요.

이 문장은 배송 속도에는 긍정적이고 상품 상태에는 부정적이다. 평점 하나나 단어 개수만으로는 이러한 관계를 충분히 설명하기 어렵다.

| 구분 | 정형 데이터 | 텍스트 데이터 |
| --- | --- | --- |
| 예시 | 평점, 나이, 구매 금액 | 리뷰, 기사, 명언 |
| 형태 | 숫자·범주 등 정해진 값 | 길이와 표현이 다양한 자연어 |
| 정보 파악 | 집계와 조건 비교 | 내용과 맥락 해석 |
| 주요 분석 | 평균, 분포, 상관관계 | 키워드, 유사도, 분류, 정보 추출, 요약 |

텍스트를 DataFrame 컬럼에 저장하더라도 문장 자체가 일정한 길이와 구조를 갖는 것은 아니다.

### 표현의 차이와 의미의 차이 구분

- **같은 의미를 다른 표현으로 전달할 수 있다.** `배송이 빨라요`와 `상품이 금방 도착했어요`는 단어가 달라도 의미가 유사하다.
- **같은 대상을 다른 문자열로 표현할 수 있다.** `상품이`와 `상품은`은 조사가 달라 그대로 비교하면 다른 문자열이다.
- **한 문장에 여러 평가가 섞일 수 있다.** `가격은 저렴하지만 품질은 아쉬워요`에는 긍정과 부정이 함께 있다.

따라서 단어의 일치 여부와 문장의 의미를 구분해서 생각해야 한다.

## 2. 텍스트 분석의 목적과 전체 과정

자연어 처리(NLP)는 컴퓨터로 사람이 사용하는 언어를 분석하고 처리하는 기술이다. 텍스트 분석은 텍스트에서 분석 목적에 필요한 키워드·주제·감정 등의 정보를 추출하는 과정이다.

| 분석 작업 | 얻고자 하는 결과 | 예시 |
| --- | --- | --- |
| 키워드 추출 | 중요한 단어 | 리뷰의 주요 관심 대상 |
| 유사도 분석 | 문서 사이의 유사성 | 비슷한 문의 검색 |
| 텍스트 분류 | 정해진 범주 | 배송·환불·교환 문의 구분 |
| 정보 추출 | 필요한 항목 | 상품명과 문제 유형 추출 |
| 요약 | 핵심 내용 | 여러 리뷰의 주요 불만 정리 |

전체 흐름은 다음과 같다.

```text
데이터 확보 → 데이터 확인·전처리 → 텍스트 표현·분석 → 결과 검증
```

| 단계 | 수행 내용 |
| --- | --- |
| 데이터 확보 | 분석에 필요한 텍스트 수집 |
| 확인·전처리 | 결측, 공백, 불필요한 요소와 형식 확인 |
| 표현·분석 | TF-IDF, 임베딩, LLM 등 목적에 맞는 방법 적용 |
| 결과 검증 | 키워드의 적절성, 분류·요약 결과 검토, 정답이 있다면 성능 평가 |

전처리와 수치 변환을 모든 분석에서 똑같이 수행할 필요는 없다. 예를 들어 TF-IDF는 문서를 단어 가중치로 표현하고, LLM API를 활용할 때는 사용자가 문맥이 담긴 텍스트와 지시사항을 전달할 수 있다.

## 3. 텍스트 정제·토큰화·형태소 분석

### 텍스트 정제: 불필요한 요소 정리

텍스트 정제는 앞뒤 공백이나 분석을 방해하는 HTML 태그 등을 정리하는 과정이다.

```text
정제 전: "   상품이 좋아요! 배송은 느려요.   "
정제 후: "상품이 좋아요! 배송은 느려요."
```

느낌표와 물음표는 감정의 강도나 의도를 나타낼 수 있다. 정제 여부는 제거 가능한 문자 수보다 **분석에 필요한 정보가 유지되는지**를 기준으로 결정한다.

### 토큰화: 분석할 단위로 분리

토큰화는 문장을 분석에 사용할 작은 단위인 토큰으로 나누는 과정이다. 단순히 공백을 기준으로 나누면 다음과 같다.

```text
"상품이 좋아요. 배송은 느려요."
→ ["상품이", "좋아요.", "배송은", "느려요."]
```

이 방식은 간단하지만 `상품이`와 `상품은`을 서로 다른 토큰으로 처리하고 문장부호도 붙어 있다. 한국어 키워드 분석에서는 이러한 한계를 고려해야 한다.

### 형태소 분석: 의미·문법 단위로 분석

형태소 분석은 단어를 의미나 문법적 기능을 가진 단위로 분석하는 과정이다. 품사 태깅은 각 형태소가 명사·동사·형용사 등 어떤 품사인지 구분하는 작업이다.

| 원래 표현 | 주요 형태소 | 구조 |
| --- | --- | --- |
| 상품이 | 상품 + 이 | 명사 + 조사 |
| 상품은 | 상품 + 은 | 명사 + 조사 |
| 배송이 | 배송 + 이 | 명사 + 조사 |
| 배송은 | 배송 + 은 | 명사 + 조사 |

이를 통해 조사 차이가 있어도 공통된 명사인 `상품`, `배송`을 확인할 수 있다. 학습자료에서는 한국어 형태소 분석기의 예로 Okt와 Mecab을 소개했다. 실제 결과는 사용하는 분석기에 따라 달라질 수 있다.

형태소 분석은 언어와 분석 목적에 맞게 선택한다. 한국어 리뷰의 조사 처리가 필요할 수 있지만, 앞서 수집한 영어 명언에는 영어에 적합한 토큰화와 전처리를 적용해야 한다.

### 명사만 추출하면 잃을 수 있는 정보

`상품은 좋지만 배송은 느려요`에서 명사만 추출하면 `상품`, `배송`이라는 대상을 파악하기 쉽다. 하지만 평가를 담은 표현이 사라져 어느 대상에 만족하고 불만족했는지 알기 어렵다.

| 목적 | 유지하거나 추출할 정보 |
| --- | --- |
| 주요 대상·키워드 파악 | 명사 등 필요한 형태소 |
| 긍정·부정 이유 분석 | 평가 표현, 부정 표현, 대상과의 관계 |
| 문맥을 활용한 분류·요약 | 의미와 관계가 유지된 문장 |

형태소 분석을 했다고 명사만 사용해야 하는 것은 아니다.

## 4. 분석 목적별 전처리와 표현 방법

### TF-IDF: 단어의 가중치

TF-IDF는 문서에서 단어가 얼마나 등장하는지와 다른 문서에서는 얼마나 드물게 등장하는지를 활용한다. 따라서 무엇을 하나의 단어로 볼지에 따라 단어 목록과 가중치가 달라진다.

예를 들어 `상품이`와 `상품은`을 그대로 사용하면 서로 다른 항목이 될 수 있다. 형태소 분석으로 `상품`을 추출하면 공통 단어로 집계할 수 있다.

이번 학습에서는 TF-IDF의 역할과 전처리의 연결을 이해했으며, 계산과 구현은 이후 학습 내용이다.

### 임베딩: 문서를 수치 벡터로 표현

텍스트 임베딩은 문서를 수치 벡터로 표현하여 의미 유사도 비교 등에 활용하는 방법이다. 단어가 달라도 의미가 비슷한 문서를 찾는 데 사용할 수 있으며, 입력은 모델에 적합하게 정리한다.

### LLM: 지시사항에 따른 분류·추출·요약

LLM 기반 분석에서는 텍스트와 분석 지시사항을 전달하여 필요한 결과를 얻는다. 문장의 평가와 관계가 중요하므로 불필요한 요소만 정리하고 맥락을 유지하는 방향을 고려한다.

사용자가 LLM 입력 전에 형태소 분석을 반드시 수행할 필요는 없다. 모델 내부의 토큰화와 사용자가 수행하는 한국어 형태소 분석은 같은 과정이 아니다.

### 입력과 출력 비교

| 방법 | 주요 입력 | 주요 출력 |
| --- | --- | --- |
| TF-IDF | 문서별 텍스트 또는 토큰 | 문서별 단어 가중치 |
| 텍스트 임베딩 | 문서별 텍스트 | 수치 벡터 |
| LLM API | 텍스트와 지시사항 | 분류·정보 추출·요약 결과 |

`배송은 빨랐지만 상품이 파손되어 왔어요`라는 문장을 기준으로 역할을 비교하면 다음과 같다. 아래는 설명용 예시이며 실제 모델 실행 결과가 아니다.

| 방법 | 결과의 형태 예시 |
| --- | --- |
| TF-IDF | 배송·상품·파손 등의 단어 가중치 |
| 임베딩 | 리뷰를 표현하는 수치 벡터 |
| LLM 분류 | 상품 상태 불만 |
| LLM 요약 | 배송은 빨랐으나 상품이 파손되어 도착함 |

## 5. 문서 단위와 결과 구조화

### 하나의 문서가 무엇인지 정하기

문서는 텍스트 분석에서 하나의 분석 대상으로 취급하는 단위다.

| 데이터 | 문서 단위 |
| --- | --- |
| 고객 리뷰 | 리뷰 하나 |
| 뉴스 | 기사 하나 |
| 명언 | 명언 하나 |

앞서 만든 `quotes_clean.csv`에서는 명언 하나가 한 행이며, 다음 구조를 사용한다.

| 컬럼 | 역할 |
| --- | --- |
| `text` | 실제 분석할 명언 본문 |
| `author` | 작성자별 결과 비교 |
| `tags` | 관련 주제 확인 |
| `source_url` | 원본 출처 추적 |

분석 대상 본문과 메타데이터를 구분해 두면 같은 데이터셋을 키워드 분석과 작성자별 비교 등 여러 목적으로 활용할 수 있다.

### 분석 결과도 원문과 연결하기

결과를 일정한 컬럼 구조로 정리하면 범주별 집계와 오류 검토가 쉬워진다.

| 리뷰 본문 | 분류 결과 예시 |
| --- | --- |
| 배송은 빨랐지만 상품이 파손되어 왔어요. | 상품 상태 불만 |
| 배송이 너무 늦게 도착했어요. | 배송 불만 |
| 가격이 저렴해서 만족해요. | 가격 만족 |

분류 기준과 필요한 결과 항목을 미리 정하고, 어떤 원문에서 나온 결과인지 연결해 관리해야 한다. 이후 LLM API 학습에서는 일관된 형태로 결과를 출력받는 방법을 다룬다.

## 오늘 배운 점

- 텍스트는 표현이 달라도 의미가 비슷할 수 있고, 한 문장에 여러 대상과 평가가 섞일 수 있다.
- 정제·토큰화·형태소 분석은 역할이 다르며, 모든 분석에 같은 방식으로 적용하는 필수 순서가 아니다.
- 한국어 키워드 분석에서는 조사 차이를 정리하는 것이 도움이 될 수 있지만, 명사만 남기면 감정과 평가 정보를 잃을 수 있다.
- TF-IDF, 임베딩, LLM은 입력과 결과 형태가 다르므로 목적에 맞게 선택해야 한다.
- 문서 단위를 먼저 정하고 본문·메타데이터·분석 결과를 연결해 관리해야 후속 집계와 검증이 가능하다.

> 오늘의 핵심: 전처리는 분석에 필요한 의미를 유지하는 과정이며, 분석 목적에 맞춰 텍스트의 단위와 표현 방법을 선택해야 한다.
