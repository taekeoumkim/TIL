## 1. TF-IDF와 텍스트 임베딩의 차이

다음 두 문의는 표현이 다르지만 모두 환불 금액을 받지 못한 상황을 설명한다.

- 환불 요청했는데 아직 돈이 들어오지 않았어요.
- 반품 처리는 끝났는데 결제 금액을 돌려받지 못했어요.

TF-IDF는 단어의 빈도와 문서 간 분포를 활용하므로 공통 단어가 적은 문장의 의미적 유사성을 충분히 반영하기 어렵다. 텍스트 임베딩은 모델이 학습한 의미적 특징을 수치 벡터로 표현하여 이러한 문서를 비교하는 데 활용할 수 있다.

| 구분 | TF-IDF | 텍스트 임베딩 |
| --- | --- | --- |
| 표현 기준 | 단어의 빈도와 희소성 | 학습된 의미적 특징 |
| 벡터 구성 | 단어별 가중치 | 모델이 생성한 수치 벡터 |
| 장점 | 단어별 중요도 해석이 쉬움 | 표현이 다른 문장의 의미적 유사성 반영 가능 |
| 활용 | 키워드 추출, 단어 기반 검색 | 의미 검색, 유사 문서 비교·그룹화 |

두 방법 모두 텍스트를 숫자로 표현한다. 중요한 단어를 설명하려면 TF-IDF, 표현이 달라도 관련된 문서를 찾으려면 임베딩을 고려할 수 있다. 선택 기준은 분석 목적이다.

### 임베딩 벡터란?

```text
"상품이 빠르게 도착했습니다."
→ 임베딩 모델
→ [0.21, -0.35, 0.78, ...]
```

위 숫자는 구조를 설명하기 위한 가상 예시다. 실제 차원과 값은 모델에 따라 다르며, 문장이 비슷한 의미를 가진다고 항상 높은 유사도가 보장되는 것은 아니다.

비교할 질문과 문서는 서로 호환되는 임베딩 모델과 표현 방식을 사용해야 한다. 이번 학습에서는 같은 모델로 벡터를 생성하는 흐름으로 이해했다.

## 2. 코사인 유사도의 원리

코사인 유사도는 두 벡터의 길이보다 **방향이 얼마나 비슷한지**를 비교한다.

```text
cosine(A, B) = (A · B) / (norm(A) × norm(B))

A · B: 대응하는 원소를 곱한 뒤 더한 내적
norm(A), norm(B): 각 벡터의 크기
```

0이 아닌 벡터의 코사인 유사도는 -1부터 1 사이의 값을 갖는다.

| 값 | 벡터의 관계 |
| --- | --- |
| 1 | 같은 방향 |
| 0 | 서로 직교 |
| -1 | 반대 방향 |

이는 벡터의 수학적 관계다. 임베딩 점수 0을 무조건 의미적 무관계, -1을 반대 의미로 해석해서는 안 된다. 모델의 벡터 공간과 데이터 특성을 함께 고려한다. 또한 영벡터는 분모가 0이므로 이 수식으로 유사도를 정의할 수 없다.

### 가상 벡터로 계산하기

질문 Q가 `[1, 0]`, 문서 A가 `[0.8, 0.6]`이라고 하자.

```text
내적 = 1×0.8 + 0×0.6 = 0.8
Q의 크기 = 1
A의 크기 = √(0.8² + 0.6²) = 1
코사인 유사도 = 0.8 / (1×1) = 0.8
```

문서 B가 `[0, 1]`이면 Q와의 내적은 0이고 유사도도 0이다. 이 예시에서는 A의 방향이 질문과 더 비슷하다. 코사인 유사도는 임베딩뿐 아니라 TF-IDF 벡터에도 적용할 수 있다.

## 3. Top-K 유사 문서 검색

Top-K 검색은 질문과 각 문서의 점수를 계산한 뒤 상위 K개를 선택하는 방법이다.

1. 저장된 문서를 임베딩으로 변환한다.
2. 질문도 호환되는 방식으로 벡터화한다.
3. 질문과 문서의 유사도를 계산한다.
4. 점수가 높은 순서로 정렬한다.
5. 상위 K개 문서를 선택하고 원문을 검토한다.

### NumPy로 계산 흐름 확인

다음 코드는 실제 임베딩 API를 호출하지 않는다. 학습자료처럼 미리 정한 2차원 가상 벡터로 계산과 순위 선택 원리를 보여 준다.

```python
import numpy as np

query = "환불금이 언제 들어오나요?"
documents = [
    "환불 금액은 언제 입금되나요?",
    "반품 절차를 알려주세요.",
    "상품 색상이 사진과 달라요.",
]

query_vector = np.array([1.0, 0.0])
document_vectors = np.array([
    [0.8, 0.6],
    [0.6, 0.8],
    [0.0, 1.0],
])

dot_products = document_vectors @ query_vector
query_norm = np.linalg.norm(query_vector)
document_norms = np.linalg.norm(document_vectors, axis=1)

if query_norm == 0 or np.any(document_norms == 0):
    raise ValueError("영벡터의 코사인 유사도는 계산할 수 없습니다.")

similarities = dot_products / (query_norm * document_norms)
top_k = 2
top_indices = np.argsort(similarities)[::-1][:top_k]

print("질문:", query)
for index in top_indices:
    print(f"{documents[index]} (유사도: {similarities[index]:.2f})")
```

| 기능 | 역할 |
| --- | --- |
| `@` | 문서 벡터와 질문 벡터의 내적 계산 |
| `np.linalg.norm()` | 벡터의 크기 계산 |
| `axis=1` | 각 문서 행의 크기 계산 |
| `np.argsort()` | 점수 정렬에 필요한 인덱스 반환 |
| `[::-1][:top_k]` | 내림차순으로 상위 K개 선택 |

가상 벡터에서 세 문서의 점수는 각각 0.80, 0.60, 0.00이므로 Top-2는 환불 입금 문의와 반품 절차 문의다. 이 점수는 실제 문장을 모델로 분석한 성능 결과가 아니다.

### 검색 결과의 해석

Top-K는 후보 중 상대적으로 높은 점수를 선택한다. 관련 문서가 부족해도 순위는 만들어지므로 선택된 모든 문서가 충분히 관련 있다는 보장은 없다.

또한 `환불을 받았습니다`와 `환불을 받지 못했습니다`는 주제가 비슷하지만 상태가 반대다. 점수가 높더라도 부정 표현, 조건, 실제 사실관계는 원문에서 확인해야 한다. 유사도 점수는 정답 확률로 해석하지 않는다.

## 4. 유사 문서 검색과 토픽 모델링

| 구분 | 유사 문서 검색 | 토픽 모델링 |
| --- | --- | --- |
| 목적 | 입력 질문과 관련된 문서 찾기 | 전체 문서의 주요 주제 발견 |
| 기준 | 질문과 각 문서의 유사도 | 문서들 사이의 유사성 |
| 결과 | 관련 문서 목록 | 문서 그룹과 대표 키워드 |
| 예시 | 환불 질문과 비슷한 문의 검색 | 리뷰의 배송·환불·품질 문제 탐색 |

검색은 질문이 기준이고, 토픽 모델링은 특정 질문 없이 전체 문서 집합을 탐색한다. 두 작업은 임베딩을 활용할 수 있지만 해결하려는 문제가 다르다.

## 5. BERTopic의 토픽 생성 원리

BERTopic은 임베딩과 군집화, 대표 키워드 추출을 결합하여 문서의 주제를 탐색하는 기법이다. 학습자료의 일반적인 흐름은 다음과 같다.

```text
문서 임베딩 → 차원 축소 → 군집화 → c-TF-IDF → 토픽 해석
```

| 단계 | 역할 |
| --- | --- |
| 문서 임베딩 | 문서를 의미적 특징을 반영한 벡터로 변환 |
| 차원 축소 | 군집화를 위한 중간 표현으로 차원 축소 |
| 군집화 | 유사한 문서들을 그룹으로 묶음 |
| 대표 키워드 추출 | 그룹별 특징적인 단어를 찾음 |
| 토픽 해석 | 키워드와 실제 문서를 함께 보고 주제 판단 |

### c-TF-IDF와 TF-IDF의 관점 차이

개별 문서의 TF-IDF는 문서별 특징적인 단어를 찾는다. c-TF-IDF(Class-based TF-IDF)는 같은 그룹의 문서를 모아 **그룹별로 특징적인 단어**를 찾는 데 활용한다. 두 방법의 계산 관점과 비교 단위를 구분한다.

### 정해진 업무 분류와 토픽 발견 구분

BERTopic은 처음부터 `배송 불만`, `환불 불만`이라는 정답 분류명을 예측하는 방식으로 이해하면 안 된다. 문서의 유사성을 바탕으로 그룹을 발견하고, 사람이 대표 키워드와 문서를 확인하여 해석한다.

| 가상 그룹 | 대표 키워드 예시 | 해석 예시 |
| --- | --- | --- |
| 토픽 0 | 배송, 지연, 도착 | 배송 관련 문제 |
| 토픽 1 | 환불, 반품, 금액 | 환불 관련 문제 |
| 토픽 2 | 파손, 불량, 상품 | 상품 품질 문제 |

위 표는 원리 설명용 가상 결과다. 소수의 리뷰만 입력하면 반드시 이 그룹이 생성되는 것은 아니다. 문서 수, 임베딩의 적합성, 군집화 결과에 따라 달라지고 일부 문서는 특정 그룹에 포함되지 않을 수 있다.

결과를 볼 때는 다음을 확인한다.

- 같은 그룹의 문서들이 실제로 비슷한 내용을 다루는가?
- 대표 키워드가 그룹을 잘 설명하는가?
- 업무에서 필요한 구분과 발견된 토픽이 맞는가?
- 환불 요청·완료·지연처럼 다른 상태가 한 토픽에 섞이지 않았는가?

## 6. 임베딩 검색과 RAG의 연결

RAG(Retrieval-Augmented Generation)는 외부 문서의 검색 결과를 LLM 입력에 포함하여 답변을 생성하는 방식이다.

```text
사용자 질문 → 관련 문서 검색 → 검색 결과를 LLM에 전달 → 답변 생성
```

| 기술 | 역할 |
| --- | --- |
| 텍스트 임베딩 | 질문과 문서를 벡터로 표현 |
| 코사인 유사도 | 질문과 문서 벡터의 유사도 비교 |
| 유사 문서 검색 | 답변에 참고할 관련 문서 선택 |
| LLM | 검색 문서를 참고하여 답변 생성 |

BERTopic은 전체 문서의 주요 주제를 발견하는 데, RAG는 질문에 관련된 문서를 답변 생성에 활용하는 데 목적이 있다. 이번에는 연결 원리를 배웠으며 실제 임베딩 생성, BERTopic 실행, RAG 구현은 수행하지 않았다.

앞서 만든 `quotes_clean.csv`도 `text`를 벡터화하면 의미가 비슷한 명언을 검색하는 자료로 활용할 수 있다. 이때 검색 결과와 원문·작성자·출처를 연결하여 확인하는 것이 중요하다.

## 오늘 배운 점

- TF-IDF는 단어의 중요도를 설명하는 데, 임베딩은 표현이 다른 문서의 의미적 유사성을 비교하는 데 활용할 수 있다.
- 코사인 유사도는 벡터의 방향을 비교하며, 수학적 점수와 의미의 동일성은 구분해야 한다.
- Top-K 검색은 관련 후보를 고르는 과정으로, 선택된 문서의 적합성은 추가 검토해야 한다.
- BERTopic은 문서를 군집화한 뒤 그룹별 키워드로 주제를 해석하는 과정이다.
- 검색, 토픽 모델링, RAG는 임베딩을 활용할 수 있지만 목적과 결과가 다르다.

> 오늘의 핵심: 임베딩으로 관련 문서를 찾고 묶을 수 있지만, 유사한 주제와 동일한 사실은 다르므로 결과를 원문과 분석 목적에 맞춰 해석해야 한다.
