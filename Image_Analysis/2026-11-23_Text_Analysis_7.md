# TIL | 2026-11-23 — 이미지 분석 모델의 오류 분석과 성능 개선

제조 이미지의 결함 분석을 사례로 오분류, 미검출, 위치 오류, Mask 오류를 조사하고 원인에 맞는 개선 방법을 선택하는 과정을 배웠다.

## 1. 태스크별 오류 확인

| 태스크 | 주요 오류 | 확인 방법 |
| --- | --- | --- |
| 이미지 분류 | 정상→불량, 불량→정상 오분류 | Confusion Matrix와 원본 이미지 확인 |
| 객체 탐지 | 미검출, 잘못된 검출, 클래스·위치 오류, 중복 검출 | 정답 클래스·Box와 예측 비교 |
| 세그멘테이션 | 영역 누락·과다 예측, 경계·객체 구분 오류 | 정답과 예측 Mask를 이미지에 겹쳐 확인 |

정상 제품을 불량으로 판단하면 재검사나 폐기가 늘 수 있고, 불량을 정상으로 판단하면 결함 제품이 통과할 수 있다. 전체 Accuracy와 함께 오류의 방향과 영향을 살펴야 한다.

탐지 Recall이 낮으면 미검출 사례를, Precision이 낮으면 오검출과 중복을, IoU가 낮으면 Box의 위치와 범위를 조사한다. 지표는 조사할 지점을 알려 주며 실제 원인은 이미지와 라벨에서 확인한다. Instance Segmentation은 Mask 형태 외에도 객체 자체의 누락과 중복을 살핀다.

## 2. 원인 가설과 개선 방법

| 관찰한 문제 | 조사할 부분 | 개선 후보 |
| --- | --- | --- |
| 작은 균열 미검출 | 축소 후 크기, 작은 결함 사례 수, 위치 라벨 | 입력 크기 조정, 사례 보완 |
| 어두운 이미지 오분류 | 조명별 분포, 흐림, 라벨 품질 | 실제 어두운 이미지 추가, 밝기·대비 증강 |
| 특정 클래스 성능 저하 | 클래스별 수량과 라벨 일관성 | 데이터 보완과 라벨 수정 |
| 부정확한 Mask | 정답 경계와 세부 정보 보존 | Mask 수정과 전처리 조정 |
| 높은 Train 성능과 낮은 Validation 성능 | 과적합 가능성 | 증강·학습 범위·설정 조정 |
| 새로운 촬영 환경의 성능 저하 | 학습·운영 데이터의 차이 | 신규 데이터 보완, Fine-tuning |

같은 미검출이라도 해상도, 사례 부족, 라벨 오류 등 원인이 다를 수 있다. 오류 이미지를 모아 가설을 세우고 관련 변경을 검증한다. 유형별 건수와 함께 전체 이미지·객체 수와 오류 비율을 확인한다.

## 3. 전처리와 증강의 정답 보존

원본에서 8픽셀 너비인 균열은 이미지를 절반으로 축소하면 약 4픽셀이 된다. 입력 크기를 늘리면 세부 정보를 유지할 수 있지만 메모리와 연산 부담도 증가한다.

이미지를 자르면서 결함이 사라졌는데 불량 라벨을 유지하면 잘못된 학습 사례가 생길 수 있다.

```python
import numpy as np

mask = np.zeros((8, 8), dtype=np.uint8)
mask[5:7, 5:7] = 1
cropped_mask = mask[:4, :4]

print(mask.sum())          # 결함 픽셀 4개
print(cropped_mask.sum())  # 결함 픽셀 0개
```

회전·반전·자르기를 객체 탐지와 세그멘테이션에 적용할 때는 Box와 Mask도 동일한 공간 변환을 반영한다. 변환 후 정답이 유지되고 실제 촬영 환경에서 가능한 변화인지 확인한다.

Feature Extraction은 분류기만 학습하고, Partial Fine-tuning은 일부 특징 레이어까지, Full Fine-tuning은 전체 가중치를 조정한다. 학습 범위별 Validation 성능과 과적합, 비용을 비교한다.

## 4. Baseline과 동일 조건에서 비교

```text
Baseline 평가 → 오류 사례 수집 → 원인 가설
→ 개선 적용·재학습 → 동일 Validation 평가 → 오류 사례 재확인
```

평가 원본 데이터, 지표 계산 방식, IoU·Confidence 기준을 맞춘다. 입력 해상도를 개선 항목으로 변경했다면 같은 원본 이미지를 사용하고 변경한 전처리 조건을 기록한다.

학습자료의 가상 비교는 다음과 같다.

| 항목 | 개선 전 | 개선 후 | 변화 |
| --- | ---: | ---: | ---: |
| Precision | 0.85 | 0.78 | -7%p |
| Recall | 0.60 | 0.78 | +18%p |
| mAP@0.5 | 0.68 | 0.74 | +6%p |
| 이미지당 추론 시간 | 45ms | 70ms | +25ms |

변화량은 두 비율의 차이다. Recall 0.60→0.78은 18%p 상승이다. 결함 누락은 줄었지만 오검출 비율과 처리 시간이 늘어난 영향을 함께 판단한다.

전체 지표와 함께 목표 오류가 줄었는지, 이전에 맞히던 사례에서 새 오류가 생겼는지, 특정 크기나 조명 조건에 문제가 남았는지 확인한다.

## 5. 검증과 기록

Train은 가중치 학습에, Validation은 개선 방법 비교와 모델 선택에 사용한다. 최종 선택한 모델은 독립적인 Test에서 평가한다. 운영 환경이 달라질 수 있다면 새로운 촬영 조건과 시간대의 데이터도 살핀다.

프로젝트 기록에는 발견한 문제, 원인 가설, 변경 내용, 평가 조건, 개선 전후 수치, 남은 오류를 남긴다. 어떤 변경이 효과가 있었는지 추적하고 결과를 재현하는 근거가 된다.

## 배운 점

작은 결함을 더 많이 찾는 개선이 오검출이나 추론 시간을 늘릴 수 있다는 점을 배웠다. 오류 유형과 실제 이미지를 근거로 변경을 선택하고, 목표 오류의 감소와 다른 오류의 증가를 함께 비교해야 운영 목적에 맞는 모델을 고를 수 있다.
