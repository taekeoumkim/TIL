## AI 기본 개념 이해

### AI, 머신러닝, 딥러닝, 생성형 AI, LLM

AI를 공부하면서 가장 먼저 헷갈렸던 부분은 **AI, 머신러닝(ML), 딥러닝(DL), 생성형 AI, LLM의 관계**였다.

이 개념들은 서로 완전히 다른 기술이라기보다 포함 관계를 가지고 있다.

```text
인공지능(AI)
└── 머신러닝(ML)
    └── 딥러닝(DL)

생성형 AI
└── LLM
```

다만 생성형 AI는 AI의 특정 계층을 단순히 의미하는 개념이라기보다는 **새로운 콘텐츠를 생성하는 AI 기술의 범주**로 이해하는 것이 좋다.

학습 자료에서는 다음과 같이 정리할 수 있었다.

| 개념 | 의미 | 예시 |
| --- | --- | --- |
| AI | 사람의 지능적인 작업을 수행하도록 만드는 기술 | 자율주행, 추천 시스템, 음성 비서 |
| ML | 데이터를 학습하여 패턴을 찾고 예측하는 기술 | 스팸 분류, 상품 추천 |
| DL | 인공신경망을 이용해 복잡한 데이터를 학습하는 ML의 한 분야 | 얼굴 인식, 음성 인식 |
| 생성형 AI | 학습한 패턴을 바탕으로 새로운 콘텐츠를 생성하는 AI | 텍스트, 이미지, 음성 생성 |
| LLM | 대규모 텍스트 데이터를 학습하고 자연어를 처리·생성하는 모델 | ChatGPT, Claude, Gemini |

AI가 가장 넓은 개념이고 머신러닝은 AI의 한 분야, 딥러닝은 머신러닝의 한 분야라는 관계를 이해하는 것이 핵심이다. fileciteturn11file0L45-L69

### 전통적인 프로그래밍과 머신러닝의 차이

전통적인 프로그래밍에서는 개발자가 **규칙을 직접 작성**한다.

```text
입력 데이터 + 사람이 만든 규칙
            ↓
          결과
```

예를 들어,

```text
if 스팸 단어가 포함되어 있으면
    → 스팸 메일
else
    → 정상 메일
```

처럼 사람이 판단 기준을 직접 정한다.

반면 머신러닝에서는 데이터와 정답 또는 패턴을 이용해 모델이 규칙을 학습한다.

```text
데이터 + 정답
    ↓
머신러닝 모델 학습
    ↓
학습된 패턴
    ↓
새로운 데이터 예측
```

즉, 사람이 모든 규칙을 직접 작성하는 대신 **데이터에서 패턴을 찾아 새로운 데이터에 적용한다**는 차이가 있다. fileciteturn11file0L90-L99

이 차이를 이해하면 머신러닝이 복잡하고 다양한 상황에 유연하게 대응할 수 있는 이유를 이해할 수 있다.

## 생성형 AI 시대의 시작

### 생성형 AI가 발전할 수 있었던 이유

생성형 AI와 LLM이 빠르게 발전한 데에는 여러 기술적 배경이 있다.

- 인터넷과 디지털 서비스 확산
- 학습 데이터의 급격한 증가
- GPU를 통한 컴퓨팅 성능 향상
- 딥러닝 기술 발전
- Transformer 구조의 발전

특히 Transformer는 **Self-Attention**을 활용하여 문장 전체의 관계를 효과적으로 고려하고 병렬 연산을 가능하게 했다.

이를 통해 대규모 언어 모델을 학습할 수 있는 기반이 마련되었다. fileciteturn11file0L102-L120

### Foundation Model

Foundation Model은 대규모 데이터를 이용해 사전학습한 **범용 모델**이다.

하나의 특정 작업만 수행하는 것이 아니라 이후 프롬프트, 추가 학습, 외부 도구 등을 활용하여 다양한 작업에 적용할 수 있다.

예를 들어 하나의 기반 모델을 이용해 다음과 같은 작업을 수행할 수 있다.

- 번역
- 요약
- 질의응답
- 코드 생성
- 문서 작성

즉, 생성형 AI의 발전은 단순히 모델의 크기가 커진 것뿐만 아니라 **하나의 모델을 다양한 업무에 활용할 수 있게 된 것**과도 관련이 있다. fileciteturn11file0L113-L120

## LLM은 어떻게 답변을 만드는가?

### LLM은 정답을 검색해서 보여주는 것이 아니다

LLM을 처음 접했을 때는 질문을 입력하면 모델이 어딘가에 저장된 정답을 찾아서 보여준다고 생각하기 쉽다.

하지만 LLM은 기본적으로 **입력된 문맥을 바탕으로 다음에 올 가능성이 높은 Token을 예측하는 방식**으로 답변을 생성한다.

전체적인 흐름은 다음과 같다.

```text
사용자 입력
    ↓
Tokenization
    ↓
Embedding
    ↓
문맥 계산
    ↓
다음 Token 확률 계산
    ↓
Token 선택
    ↓
다시 예측
    ↓
문장 완성
```

이 과정을 반복하면서 답변이 만들어진다. fileciteturn11file1L165-L181

### Token

Token은 LLM이 텍스트를 처리하기 위해 사용하는 단위이다.

중요한 점은 **단어 하나가 반드시 Token 하나가 되는 것은 아니라는 것**이다.

Tokenizer에 따라 하나의 단어가 여러 Token으로 나뉠 수도 있고, 여러 단어가 하나의 Token으로 처리될 수도 있다.

특히 한국어는 조사나 어미 등이 결합하는 특성 때문에 하나의 단어가 여러 Token으로 분리되는 경우가 많다. fileciteturn11file1L217-L238

또한 대부분의 LLM 서비스에서는 입력과 출력에 사용되는 Token 수가 비용과 관련되기 때문에, 불필요하게 긴 프롬프트와 출력을 줄이는 것도 중요하다.

### Embedding

Token은 컴퓨터가 직접 의미를 이해할 수 있는 형태가 아니므로 **숫자로 이루어진 벡터로 변환**한다.

이 과정을 Embedding이라고 한다.

```text
Token
 ↓
Embedding
 ↓
Vector
```

Embedding Space에서는 의미나 사용 맥락이 비슷한 Token이 유사한 벡터를 가지는 경향이 있다.

따라서 LLM은 이러한 벡터 표현을 활용하여 입력 문맥을 계산하고 다음 Token을 예측한다. fileciteturn11file1L239-L250

## Next-Token Prediction

### 답변 생성 과정

LLM이 사용자의 입력을 받아 답변을 생성하는 과정을 **Inference(추론)**라고 한다.

답변을 생성하는 과정은 크게 다음과 같이 이해할 수 있다.

### 1. 입력 변환

사용자가 입력한 텍스트를 Tokenizer가 Token으로 나눈다.

```text
"나는 AI를 공부한다."
        ↓
Token  Token  Token ...
```

### 2. Embedding

각 Token을 숫자 벡터로 변환한다.

### 3. 문맥 계산

현재 입력된 Token과 앞에서 생성된 내용을 함께 고려한다.

### 4. 다음 Token 확률 계산

다음에 올 수 있는 Token마다 확률을 계산한다.

### 5. Token 선택

Temperature 등의 설정을 반영하여 하나의 Token을 선택한다.

### 6. 반복

새롭게 생성된 Token을 포함한 문맥을 다시 사용하여 다음 Token을 예측한다.

이 과정을 반복하면서 하나의 답변이 완성된다. fileciteturn11file1L261-L284

즉,

> **LLM은 한 번에 완성된 문장을 만드는 것이 아니라 Token을 하나씩 예측하면서 답변을 만들어 간다.**

## Hallucination

### 환각 현상이 발생하는 이유

LLM은 데이터베이스에서 정답을 검색하는 방식이 아니라 **확률적으로 가장 적절한 다음 Token을 예측하는 방식**으로 답변한다.

따라서 문법적으로 자연스럽고 그럴듯한 문장이 실제 사실과 다를 수 있다.

이처럼 LLM이 **사실이 아니거나 존재하지 않는 정보를 사실처럼 생성하는 현상**을 Hallucination이라고 한다. fileciteturn11file1L288-L297

예를 들어 존재하지 않는 논문이나 인물을 물어봤을 때 실제로 존재하는 것처럼 설명하거나, 잘못된 숫자를 자연스럽게 설명하는 경우가 이에 해당한다.

따라서 AI의 답변을 사용할 때는 다음과 같은 검증 과정이 필요하다.

```text
AI 답변
  ↓
사실 확인
  ↓
출처 확인
  ↓
다른 자료와 교차 검증
  ↓
사용
```

특히 중요한 의사결정이나 외부에 공개할 자료라면 AI의 답변을 그대로 복사해서 사용해서는 안 된다.

## Context Window

### Context Window란?

Context Window는 LLM이 **한 번의 추론 과정에서 동시에 처리할 수 있는 최대 Token 수**를 의미한다.

Context에는 단순히 현재 질문만 들어가는 것이 아니다.

- 현재 사용자 입력
- 이전 대화
- System Prompt
- 참고 문서
- RAG 검색 결과
- 추가 지시사항

등 다양한 정보가 포함될 수 있다. fileciteturn11file1L301-L317

### Context Window가 중요한 이유

LLM이 처리할 수 있는 Context의 양에는 한계가 있다.

만약 전달되는 정보가 Context Window를 초과하면 모든 정보를 한 번에 활용할 수 없다.

그 결과,

- 이전 대화 내용을 충분히 반영하지 못하거나
- 중요한 지시사항을 놓치거나
- 긴 문서의 일부 내용을 제대로 활용하지 못하는

상황이 발생할 수 있다.

따라서 긴 문서나 복잡한 업무를 AI에게 맡길 때는 **어떤 정보를 Context에 넣을 것인지 설계하는 것**이 중요하다.

## Context Engineering

### Prompt Engineering에서 Context Engineering으로

단순한 프롬프트는 질문만 입력하는 방식이다.

```text
우리 회사 신제품 마케팅 아이디어 3개만 짜줘.
```

이렇게 요청하면 AI는 회사가 어떤 회사인지, 제품이 무엇인지, 고객이 누구인지 알 수 없기 때문에 일반적인 답변을 생성할 가능성이 높다.

반면 Context Engineering을 활용하면 AI가 답변을 생성하는 데 필요한 맥락을 함께 제공한다.

```text
역할
→ 10년 차 IT 기기 마케터

배경
→ 20대 대학생을 대상으로 가성비 이어폰 출시

목표
→ 신제품 초기 인지도 확보

제약 조건
→ 대학생이 부담 없이 실행할 수 있는 마케팅

출력 형식
→ 마케팅 아이디어 3개 + 기대 효과 + 실행 방법
```

이처럼 **역할, 배경 정보, 제약 조건, 출력 형식 등을 구조적으로 제공하는 것**이 Context Engineering의 핵심이다. fileciteturn11file1L321-L330 fileciteturn11file1L337-L349

### 좋은 Context의 구성

AI에게 복잡한 작업을 요청할 때는 다음과 같은 요소를 생각해 볼 수 있다.

```text
Role
  ↓
Background
  ↓
Goal
  ↓
Reference
  ↓
Constraints
  ↓
Output Format
```

예를 들어 코드 리뷰를 요청한다면,

```text
역할: 10년 차 백엔드 개발자

배경:
Spring Boot로 REST API를 개발하고 있음

목표:
코드의 유지보수성과 예외 처리 개선

참고:
현재 프로젝트의 코드

제약:
기존 API의 동작은 변경하지 않기

출력 형식:
문제점 → 개선 이유 → 수정 코드
```

처럼 맥락을 구체적으로 제공하면 AI가 보다 목적에 맞는 답변을 생성하도록 유도할 수 있다.

## AI를 사용할 때 주의할 점

### 1. AI의 답변을 무조건 신뢰하지 않기

LLM의 답변은 확률적으로 생성된 결과이므로 **정답을 보장하지 않는다.**

따라서 중요한 정보는 반드시 검증해야 한다.

### 2. 개인정보와 민감한 정보 보호

AI 서비스를 사용할 때 개인정보나 기업의 영업 비밀과 같은 민감한 정보를 무분별하게 입력해서는 안 된다.

업무 데이터를 AI에 넣기 전에 다음을 확인해야 한다.

- 개인정보가 포함되어 있는가?
- 회사의 기밀 정보가 포함되어 있는가?
- 외부 서비스에 입력해도 되는 데이터인가?
- 데이터의 비식별화가 필요한가?

학습 자료에서도 AI의 기술적 한계를 이해하고 **안전한 활용 범위를 판단하는 능력**이 중요하다고 강조한다. fileciteturn11file0L124-L138

### 3. AI를 도구로 활용하기

AI가 발전했다고 해서 사람이 할 일이 없어지는 것은 아니다.

오히려 사람에게 필요한 역할이 다음과 같이 변화한다고 생각했다.

```text
과거
정보 탐색 → 자료 정리 → 초안 작성 → 결과물 완성

AI 활용 시대
문제 정의 → AI 활용 → 결과 검증 → 수정 → 최종 판단
```

AI가 초안을 빠르게 만들어 줄 수 있기 때문에 사람은 **문제를 정확하게 정의하고, 결과를 검증하고, 최종적으로 판단하는 역할**에 더 집중할 수 있다. fileciteturn11file0L22-L32

## 오늘 배운 내용 정리

이번 학습에서는 AI의 기본적인 개념부터 LLM의 동작 원리, 그리고 AI를 효과적으로 활용하기 위한 Context Engineering까지 학습했다.

특히 기억할 내용은 다음과 같다.

- AI는 가장 넓은 개념이고, 머신러닝은 AI의 한 분야이며, 딥러닝은 머신러닝의 한 분야이다.
- 생성형 AI는 텍스트, 이미지, 음성, 영상 등의 새로운 콘텐츠를 생성하는 기술이다.
- LLM은 대규모 텍스트 데이터를 학습하고 자연어를 처리·생성하는 모델이다.
- 머신러닝은 사람이 모든 규칙을 직접 작성하는 대신 데이터에서 패턴을 학습한다.
- Transformer와 GPU, 대규모 데이터 등의 발전이 생성형 AI와 LLM의 발전을 가능하게 했다.
- LLM은 정답을 검색하는 것이 아니라 입력된 문맥을 바탕으로 다음 Token을 확률적으로 예측한다.
- Token은 LLM이 텍스트를 처리하는 단위이고, Embedding은 Token을 숫자 벡터로 표현하는 과정이다.
- LLM은 확률 기반으로 답변을 생성하기 때문에 Hallucination이 발생할 수 있다.
- Context Window에는 현재 질문뿐 아니라 이전 대화, System Prompt, 참고 문서 등의 정보가 포함될 수 있다.
- Context Engineering은 AI가 필요한 정보를 잘 활용할 수 있도록 역할, 배경, 제약 조건, 참고 자료, 출력 형식 등을 구조적으로 구성하는 방법이다.
- AI를 잘 활용하는 것뿐만 아니라 **AI의 결과를 검증하고 개인정보와 기밀 정보를 보호하는 것**도 중요하다.

### 한 줄 회고

> **AI를 잘 사용하는 사람은 AI에게 답을 맡기는 사람이 아니라, 좋은 맥락을 제공하고 결과를 검증하여 최종 판단을 내리는 사람이다.**
